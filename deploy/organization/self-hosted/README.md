# Advanced self-hosted organization candidate

This is the **advanced operator path**, not a beginner prerequisite. It runs the same C# organization server, PostgreSQL and existing P17 evidence storage. No public deployment or production release is created here. Complete P26 recovery/security and live-operator acceptance before important research.

A technical operator needs a supported Docker/Compose host, Python/OpenSSL, a public domain pointing at that host, ports 80/443, storage monitoring and a plan for database **and protected certificate/password** recovery. The private subnet `172.29.251.0/24` must not conflict with another network; changing it requires changing both proxy address and app trusted-proxy configuration. PostgreSQL and the organization app publish **no** public port. Caddy is the only public endpoint and obtains public HTTPS for the operator's domain.

From this directory, `python3 prepare.py --hostname research.your-domain.example` creates **unique**, private `protected/` configuration. It refuses to overwrite an existing configuration and prints no credentials. Choose a real hostname; the example is not a usable domain. Keep `protected/` out of version control/backups available to untrusted people. `database-ca.key`, credentials and initialization SQL are private; server certificates alone are public. The app's identity PFX is generated on the separate named configuration volume. PostgreSQL uses a verified private CA/server certificate and a nonsuperuser application role. The retained bootstrap-owner database role is an operator credential, not an application credential.

Build from a **clean, accepted source revision** using the root Dockerfile recipe, or later select an officially accepted immutable registry digest. Set `AEROSCIENCE_ORGANIZATION_IMAGE` to that verified image, then `docker compose up -d --wait`. This is an operator instruction, not a public Deploy button. There are **no usable sample passwords**. The root initialization helper only sets permissions on the configuration volume, has no network and does not handle research data. The app runs non-root, read-only except its private configuration volume, with dropped capabilities and no new privileges. Init scripts and database secrets are privately copied with PostgreSQL ownership rather than made world-readable.

The owner reads their private `Organization__BootstrapSecret` from `protected/application.env` and pastes it into the portal's **Setup code** input. That code expires after 30 minutes from first managed initialization and is consumed once. A deliberate owner rotation of this value followed by app replacement can renew an unused expired setup; never replace the persistent data-protection password/certificate during routine setup. There is no open default administrator or anonymous ownership flow.

The maintained local acceptance probe uses a reserved local HTTPS fixture and the same topology. It is reproducible with `scripts/deployment/verify_organization_container.py` after building the real test host. It proves startup, TLS, ownership, scoped evidence receipt and persistence through restart/replacement, **not** production backup restore or a managed-provider deployment. The fixture replaces Caddy's public-ACME certificate with an explicitly trusted test certificate; it never disables TLS verification.

Durable volumes: PostgreSQL records/received evidence, protected app certificate, Caddy identity/configuration. **Do not run `docker compose down --volumes` on a real organization.** A missing protected certificate with an existing database is refused. No remote scene files or personal flight archives belong on these volumes. Database backups, certificate expiry/rotation, independent off-server restoration, retention, upgrades and MFA recovery remain P26 release gates. The generated database certificate is valid for 90 days; accepting/operating renewal is mandatory before long-term use. Snapshots or container restart do not establish backup acceptance.

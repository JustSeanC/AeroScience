# Build the private 0.7.0 Beta 1 installer

This packages the existing isolated v0.7.0 validation companion for private testers.
It does not finalize a production release, mark scientific or installed acceptance
passed, publish assets, merge main, install anything or launch the app.

The installer has its own Windows identity, application directory, Start menu
shortcut and uninstaller. It retains the compiled validation profile, port, cookie,
source-bound CommBus and shared single-companion mutex. Its in-app and MSFS toolbar
labels remain **AeroScience 0.7.0 Validation**. Existing v0.7.0 validation data is
retained/reused; stable and older validation data are not selected. Beta uninstall
retains all data and the shared validation toolbar.

## Build on the SDK-equipped Windows PC

Use PowerShell 7 x64 inside the Visual Studio x64 developer environment. Close
MSFS and other AeroScience copies. Use the clean committed `develop/v0.7.0` source
SHA from the build handoff. Inno Setup 6.3 or newer must be installed; the existing
discovery helper supports its standard, custom and per-user installation paths.
The app and toolbar still require the genuine SDK and the existing hash-bound
runtime attestation; there is no substitute structural/CI package.

```powershell
Set-Location -LiteralPath 'C:\Dev\AeroScience-release'
$betaOutput = Join-Path 'C:\AeroScience-Builds' ('Beta070-1-' + (Get-Date -Format 'yyyyMMdd-HHmmss'))
pwsh -NoProfile -File .\scripts\release\Build-BetaInstaller.ps1 `
    -SdkRoot 'C:\MSFS 2024 SDK' `
    -RuntimeApprovalRecord 'C:\AeroScience-Release-Records\runtime-approval.json' `
    -RuntimeRedistributionConfirmed `
    -OutputDirectory $betaOutput
```

This calls the maintained private-validator builder, checks its exact-source
receipt, compiled SDK package, generated ES2017 bytes, real Windows runtime
loading/exports, permission attestation, self-contained GUI payload, assets and
licences, then compiles with Inno and a signature-verified Microsoft VC x64 runtime.
The installer copies runtime files byte-for-byte into `payload/application`.
Only the root `AeroScience.Engine.exe` launcher and optional `createdump.exe` are
omitted when present, matching the production publisher's cleanup. Each omission
and original hash is recorded in `BETA-BUILD.json`. The original validation receipt
is preserved unchanged as `SOURCE-VALIDATION-RECEIPT.json` beside the application;
every installed file must match its original inventory. Beta metadata and the
tester guide are outside the application directory. Existing validator folders,
ZIPs and original receipts are never modified or re-stamped.

Optional private chart runtimes are excluded from this tester distribution. No
scientific reference data, personal settings, credentials, databases, logs, original
authorization correspondence or developer tools may enter the payload. Runtime
path/private fields are omitted from distributed evidence.

## Reuse a verified build without rebuilding the app or SDK package

If a matching validator already exists, pass its actual application folder, the
original adjacent `runtime-check.json`, and its exact payload SHA:

```powershell
pwsh -NoProfile -File .\scripts\release\Build-BetaInstaller.ps1 `
    -ValidationFolder 'C:\AeroScience-Builds\YOUR-EXISTING-BUILD\AeroScience-0.7.0-Validation' `
    -RuntimeReport 'C:\AeroScience-Builds\YOUR-EXISTING-BUILD\runtime-check.json' `
    -ExpectedSourceCommit 'EXACT-40-CHARACTER-PAYLOAD-SHA' `
    -OutputDirectory $betaOutput
```

Replace the explicit example paths/SHA; the command refuses an incorrect source,
changed bytes, absent genuine SDK proof, metadata-only runtime report or missing
permission. This route needs Windows/Inno but does not require SDK recompilation.
The payload's source and original receipts remain unchanged; the installer receipt
also binds the exact beta recipe hash. Do not infer installed acceptance from it.

## Outputs and tester handoff

After successful compilation, `$betaOutput\beta-installer` contains:

- `AeroScience-Setup-v0.7.0-beta.1.exe`
- `AeroScience-Setup-v0.7.0-beta.1.exe.sha256`

The primary download for testers is the EXE; include its checksum and receipt.
The compiler log and prerequisite evidence remain under `installer-prerequisites`.
Installer code signing is not configured; verification of the Microsoft prerequisite
does not sign the AeroScience installer. No public release or tag is created.

Validate the actual installer on Windows before sharing it: check the setup label,
shortcut, default folder, runtime prerequisite, first run, matching MSFS toolbar,
stable/validation data preservation, reinstallation and uninstall retention. The
silent-install path performs the same folder checks before copying any app files.
User data directories and unrelated applications must remain unchanged. Provide
testers the included [guide](v0.7.0-beta1-testers.md).

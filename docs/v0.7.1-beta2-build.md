# Build AeroScience 0.7.1-beta.2 privately

Use packaging branch `build/v0.7.1-beta2`. Its base is v0.7.1 engineering source
`331dbf20d9c443f088eb0f97de1363c4d7af26b7`, whose [Full CI passed](https://github.com/JustSeanC/AeroScience/actions/runs/42973752197).
The packaging source has its own exact SHA and Full CI result in the
[packaging acceptance report](roadmap/v0.7.1-beta2-packaging.md).

This is **0.7.1-beta.2**, not an approved production release. Beta 2 does not imply
that a v0.7.1 Beta 1 was built or accepted. The public scientific acceptance verifier
and public candidate builder remain unchanged. The private policy requires genuine
SDK/runtime/redistribution checks but permits explicitly pending scientific and
installed-device acceptance. Every private receipt retains those pending statuses.

## Windows prerequisites

Use Windows x64, PowerShell 7 in the Visual Studio x64 Native Tools environment,
the official installed MSFS 2024 SDK, the .NET SDK pinned by `global.json`, Node/npm,
Python and Inno Setup 6.3+. Reuse the existing permission attestation bound to the
actual official `SimConnect.dll` SHA-256. Original authorization correspondence stays
private. The builder validates the runtime's actual loading/exports and authorization;
neither a copied metadata report nor CI structural output replaces those checks.

The Microsoft Visual C++ v14 x64 prerequisite must pass Authenticode, Microsoft
publisher, architecture and product-version checks. The builder can download it
from Microsoft's established URL, or use an existing verified `-VcRuntimePath`.
An optional `-InnoCompiler` selects the actual ISCC executable through the existing
version/discovery checks. These checks do not sign the AeroScience setup EXE.
Inno PE string resources can include trailing padding: verification removes only
trailing SPACE/NUL, keeps the raw values in build evidence, and compares the complete
semantic name/version and numeric version exactly.

## Exact clean build

Close MSFS, all AeroScience companions and any SDK package build. Use a fresh clone
or worktree and a new output directory under `C:\AeroScience-Builds`. The command
pins the exact **packaging** source checked by the Full run in the acceptance report;
do not use the older engineering SHA to compile this beta.

```powershell
git clone --branch build/v0.7.1-beta2 --single-branch https://github.com/JustSeanC/AeroScience.git C:\Dev\AeroScience-071-Beta2
Set-Location -LiteralPath 'C:\Dev\AeroScience-071-Beta2'
$betaSource = '69b99e31edc8ef31018329b0d422c3d5237b4676'
git branch -m build/v0.7.1-beta2 build/v0.7.1-beta2-saved-docs
git switch -c build/v0.7.1-beta2 $betaSource
git status --porcelain
$betaOutput = Join-Path 'C:\AeroScience-Builds' ('0.7.1-beta.2-' + (Get-Date -Format 'yyyyMMdd-HHmmss'))
pwsh -NoProfile -File .\scripts\release\Build-071PrivateBeta.ps1 `
  -ExpectedSourceCommit $betaSource `
  -SdkRoot 'C:\MSFS 2024 SDK' `
  -RuntimeApprovalRecord 'C:\AeroScience-Release-Records\runtime-approval.json' `
  -RuntimeRedistributionConfirmed `
  -OutputDirectory $betaOutput
```

Status must be empty. The two branch commands preserve the clone's documentation tip
and attach the exact accepted source to the required packaging branch. Run them once;
if that backup branch name exists, preserve it and choose another unused name.
This avoids the original source's detached-checkout preflight bug described below.
The corrected scripts support a detached checkout only with an explicitly matching
`-ExpectedSourceCommit`. Their follow-up Full result must pass before changing this
guide's accepted source pin. The builder requires
the accepted maintenance commit as an ancestor. It refuses output overlapping stable,
v0.7.0 Beta 1, validation or Beta 2 application/data roots and configured archive paths.
It never installs, publishes, modifies an existing candidate, or switches Community packages.

The entry point invokes the maintained beta installer and private-validation pipeline:

1. Locked restore, affected/public regressions and ordinary web/native checks.
2. Separately compiled Beta 2 profile, compiled isolation probe and Windows GUI publish.
   Actual published companion/engine product versions, file versions and hashes must agree.
3. Namespace/version staging **before** the genuine SDK package compilation, official
   header/ABI checks and ES2017 asset proof. The base toolbar templates are not rewritten.
4. Real SimConnect runtime load/export and hash-bound redistribution checks; sanitized
   authorization only in the payload. Original SDK files/authorization are not distributed.
5. Exact-source private receipt, immutable file projection, credential/data/developer-tool
   rejection, verified VC prerequisite, shared Inno recipe, EXE version checks and checksum.

The public scientific verifier runs and its real outcome is retained in
`validation\public-scientific-gate.txt`. A refusal does not become a pass. The isolated
private policy always sets `public_release_approved=false`,
`scientific_release_approved=false` and installed acceptance unverified.

- `payload\application\PRIVATE-PROFILE.json` and `build-info.json`, binding actual
  compiled versions, DLL hashes and source identity
- `payload\START-HERE.md`, the private tester instructions

Only the two declared redundant root build executables may be omitted from the installer
projection; their original hashes are recorded. Genuine runtime and all required DLLs remain.
SDK/JS proof, sanitized authorization and original source receipt must match exact bytes.
No optional chart runtime, credentials, personal data, source datasets or developer tools ship.

```powershell
$setup = Join-Path $betaOutput 'beta-installer\AeroScience-Setup-v0.7.1-beta.2.exe'
Get-FileHash -LiteralPath $setup -Algorithm SHA256
Get-Content -LiteralPath "$setup.sha256"
python scripts/release/beta_installer.py verify `
  --beta-version 0.7.1-beta.2 `
  --folder (Join-Path $betaOutput 'beta-installer') `
  --source $betaSource
```

The EXE/checksum do not exist until that Windows build succeeds. No checksum is invented
in this handoff. Keep the exact EXE and receipts for installed testing; do not rebuild
between testing and any later distribution decision. Do not upload this beta to Releases.

## Original source: detached-checkout preflight error

The original Full-tested source `69b99e31edc8ef31018329b0d422c3d5237b4676`
calls `.Trim()` on the empty output of `git branch --show-current`. In PowerShell,
a detached checkout returns no object, producing "You cannot call a method on a
null-valued expression" before creating build output. Both private builders are affected.

To build that exact original source without editing files, preserve the cloned branch
under a new name and attach the expected local packaging branch to the pinned source:

```powershell
git branch -m build/v0.7.1-beta2 build/v0.7.1-beta2-saved-docs
git switch -c build/v0.7.1-beta2 $betaSource
git status --porcelain
```

Use these commands once, from the clean detached checkout with `$betaSource` still
set to the exact original SHA. If the backup branch name already exists, preserve it
and choose another unused name. Status must be empty; rerun the same build command.
The original source/receipts remain unchanged and no release or SDK/runtime gate is bypassed.
The follow-up correction normalizes empty branch output to a string in both builders;
missing/wrong source pins, dirty checkouts and unrelated branches remain refused.

# AeroScience 0.6.0 private validation — not a public installer

Build only from a clean committed `develop/v0.6.0` checkout using the existing
`scripts/release/Build-PrivateValidation.ps1`, official MSFS 2024 SDK, x64 Visual C++ tools,
pinned .NET SDK and hash-matched runtime authorization. Use a new output directory. This
integration does not build, install or publish a private or public candidate.

The compiled profile is **AeroScience 0.6.0 Validation**, port **5086**, with configuration/data
under `%LOCALAPPDATA%\AeroScience-Validation-v0.6.0` and registry identity
`Software\AeroScience\Validation\v0.6.0`. Its Community package is
`aeroscience-validation-v0-6-0-toolbar`, panel folder `AeroScienceValidationV060`, and native
channels/cookie use `AeroScience.Validation.0_6_0`. The exact-source toolbar guard remains enforced.
It does not reuse the 0.5.0 Validation root, port, package, panel identifiers or channels.

Production remains AeroScience / port 5080 / `aeroscience-toolbar`; the shared desktop exclusion
mutex still permits only one desktop companion at a time. Keep the existing 0.5.0 installer,
SDK-built candidate, runtime approval and production/validation stores intact. The private builder
protects both validation roots and production paths and never installs or registers its output.

Use Settings' existing verified disposable archive-copy workflow to test copied legacy missions;
never point validation at production storage. Existing public/private source and installer release
gates remain enforced. Automated publishing/isolation tests do not pass installed Windows/MSFS,
physical iPad/Quest, authorized NASA/EMIT originals or final release acceptance. Follow the
[0.6.0 workbook](v0.6.0-acceptance-workbook.md) and [readiness report](v0.6.0-readiness.md).

## Incremental P01/P02 Windows check

After the exact development source passes full technical validation, use a new output directory on
the SDK-equipped gaming PC (the existing runtime authorization record must match the actual DLL):

```powershell
git fetch origin
git switch develop/v0.6.0
git pull --ff-only origin develop/v0.6.0
git status --short
pwsh -NoProfile -File .\scripts\release\Build-PrivateValidation.ps1 -SdkRoot 'C:\MSFS 2024 SDK' -RuntimeApprovalRecord 'C:\AeroScience-Release-Records\runtime-approval.json' -RuntimeRedistributionConfirmed -OutputDirectory 'C:\AeroScience-Builds\Validation060-P01P02-1'
```

Keep the source clean and preserve prior candidates. This is isolated private validation, not an
official public installer or a claim that all 0.6.0 features are implemented.

1. Confirm the 0.6.0 title, port 5086, separate stores/Community package and intact production 5080 installation.
2. Allow FAA access deliberately. Select one small exact chart edition, review whole-ZIP allowances and approve. Close/reopen the dialog; inspect real job state, bytes and separately labeled physical capacity.
3. Pause/retry/cancel, restart the companion mid-transfer, reconnect a disposable external aviation drive and verify retained hashes/offline reopening. Never test destructive failures against production originals.
4. Record a simulator flight during an approved background FAA transfer. It should wait for flight priority; recording/science/session controls and telemetry must continue. Explicitly paused FAA work must remain paused after flight end.
5. In Planner, Library, Science Map, analysis and comparison, toggle layers and basemaps without losing the selected areas, quantities, flight/session state or map view. Check X/Escape, focus, high zoom and physical iPad touch. Check Quest responsiveness separately.
6. FAA controlled/SUA polygons, chart rendering/TFR geographic screening and native EMIT are still implementation pending. A retained ZIP or prototype ledger does not pass those scenarios; do not claim a complete 0.6.0 owner acceptance.

## Incremental NASR point/runway check (partial P03)

Use a new private output, for example `C:\AeroScience-Builds\Validation060-NASR-1`, with the official
SDK/runtime approvals above. On **5086**, open Maps & Basemaps → FAA Catalog & Notices → NASR.
Enable access, refresh, choose an exact APT/NAV/FIX edition, review whole-original allowances and
approve. After Completed, choose Import FAA Reference Features. Indexing may yield to recording or
low space; originals remain retained. No additional download or observation is created by import.

In Overlays & Legend, choose each FAA category/edition, zoom 7 or closer, inspect opacity, actual
features, View references, paged keyboard lists, source details/X/Escape/focus and narrow touch layout.
Reopen offline and reconnect a disposable missing aviation drive. Mission/science values and layers
must remain unchanged. These are NAD83 coordinates with approximate basemap display, not certified
navigation. Controlled/SUA boundaries, accurate chart tiles/neatlines, TFR screening and native EMIT
remain unsupported. Actual SDK/MSFS, physical iPad/Quest and authorized NASA originals remain owner
acceptance categories; none is established by these automated checks.

# v0.4.1 interaction design and QA

## Baseline and consolidation

The v0.4.0 sidebar has two Help links: Settings Support and raw Markdown.
Archive detail contains six nested science tabs. Science lists datasets across
missions. Planner starts recording from an ambiguously named action. Standby
Control cannot select the saved route. Preparation repeats regional jobs and
scope is unclear. These are workflow problems, not missing scientific sources.

## Page layouts (design before implementation)

| Page | Stable header | Main content | Secondary content |
|---|---|---|---|
| Control | Choose Mission / explicit Start Mission | Planned route, actual track, telemetry | Instrument preparation, collection controls |
| Planner | Saved plans / create or edit | Route and survey map with editor | Prepare, save, Select for Flight |
| Preparation | Data Preparation — mission name | One summary per instrument | Advanced regions, provenance and transfer diagnostics |
| Science Map | Mission / sensor / dates | Large geographic numeric raster map | Legend, sampled versus retained distinction, inspection |
| Compare | Mission choices / measurement | Synchronized views and compatible statistics | Source dates, QA and refusal reasons |
| Analysis | Selected mission and review status | Instrument cards, ranges and charts | Quality gaps and advanced evidence |
| Results | Mission and science status | Instruments and exports | Original metadata and provisional-output warning |
| Library | Provider / collection filters | Collection summaries and coverage | Paginated regions and original provenance |
| Help | One Help & Support destination | Rendered offline guide with TOC | Community, issue reporting and feedback |
| Settings | Existing category navigation | Preferences and consent | Context links to Help and Library |

Each Science page is a real hash route with mission context retained in the URL.
Browser back/forward changes pages without starting mutations. Selection and
readiness are server-owned. Selecting a plan does not record or download.

## Reused visual language

Use existing panels, primary/secondary/danger actions, typography and map wrapper.
Primary action appears once per scope. State labels use words, not color alone.
Technical records appear in deliberately labeled Advanced details. Controls wrap
at narrow widths; maps retain useful height. Keyboard focus remains visible.
Date labels use local display time with exact original UTC in details/exports.

## Evidence policy

Browser captures and viewport emulation demonstrate browser layout only. Physical
iPad, installed Windows, native toolbar and Quest 3 acceptance require actual
hardware testing and must remain separate from automated results.

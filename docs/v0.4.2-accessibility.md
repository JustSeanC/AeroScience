# v0.4.2 accessibility findings

WCAG 2.2 AA is the target. This report is developer evidence, **not a conformance
statement** or an independent accessibility audit.

## Implemented and checked

- Named page headings and landmarks, skip navigation and visible focus. The labeled
  tablet Menu opens a focus-contained drawer; Escape restores the launch button.
  Inert content prevents focus moving into closed navigation or behind the drawer.
- Native labeled inputs, readable 16px ordinary / 14px supporting text, 44px primary
  controls, explicit units and text alongside status colors. Motion is reduced when
  the operating-system preference requests it.
- Science Map has an accessible archive browser and paged values table with the same
  stored numbers, units, quality and source/flight times. Dense location overviews
  are labeled as aggregation. No map click is required to inspect original values.
- Compare has values tables, explicit shared/independent scales and common-cell
  differences. Analysis/profile charts have labels and tabular alternatives; gaps
  remain gaps. Route waypoints have a non-overlapping table/selection alternative,
  rather than thousands of overlapping marker tab stops.
- Status regions are polite and selective. Repeated scientific-review announcements
  are visually hidden; polling keeps expanded download rows and stable controls.
- Axe-core checks use WCAG 2 A/AA, 2.1 AA and 2.2 AA tags with **no excluded rules**.
  Browser tests exercise the new pages and tablet navigation; inspect the completion
  report for the final run count. Automated findings exposed and led to fixes for
  footer contrast and misleading/overlapping map-marker interaction targets.

## Remaining manual verification

Windows Narrator/NVDA reading order, useful chart descriptions, keyboard-only long
workflows, native dialogs, forced colors/high contrast, OS browser zoom, physical iPad
Safari/VoiceOver, MSFS native panel and Quest 3 remain untested here. CSS zoom and
Chromium viewport emulation do not establish device or assistive-technology acceptance.

Use [Windows/device checklist](v0.4.2-windows-testing.md) and the representative-user
[usability protocol](v0.4.2-usability-testing.md). Track defects separately from the
weighted UX score: a high average cannot cancel scientific or accessibility failures.

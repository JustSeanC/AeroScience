## Provider decision and verified public information

**Esri ArcGIS Location Platform** is selected for optional imagery. Official pricing retrieved on 2026-10-17 advertises **2 million basemap tiles free monthly, then $0.15 per 1,000** under tile-based billing. Sessions have different pricing; labels add requests. This is published pricing, not a guarantee of perpetual free usage or entitlement for a particular account.

The documented authenticated Imagery style discovers its authorized raster tile source. The map requires source attribution or source metadata `copyrightText`, displays Powered by Esri/the official logo, and obtains reference-layer credits from its metadata. API key scopes, origin restrictions, account quotas/alerts, client-token visibility and applicable account terms remain the account holder's responsibility. No paid imagery or Esri SDK is redistributed.

Mapbox is viable but not needed for this implementation: the retrieved raster pricing advertises 750,000 free monthly requests and $0.25/1,000 in the first paid band. MapTiler's retrieved Free description limits suitability to testing/PoC/personal/non-commercial use, making it less suitable as this public application's default optional provider. Complete sources, licensing/attribution details, privacy, caching and configuration are in [the provider research](map-providers-v0.2.2.md).

No real provider key was supplied in the cloud. Authorized images, live data credits, origin restrictions, account quota behavior and DPAPI execution require the Windows/account test. Mocked provider responses demonstrate code handling, not real service acceptance.

## Route compatibility and limitations

The official EFB documentation explicitly permits omitted DepartureID/DestinationID, using the first/last en-route fix. Export therefore supports local/closed/helicopter routes without invented airports, while requiring an explicit cruising altitude. Descriptive airport names are rejected for PLN until replaced by an identifier or omitted. All patterns export their existing ordered vertices. The original scientific configuration, objectives, intervals, datasets and notes remain in AeroScience and are not claimed to transfer into the EFB.

XML structure, coordinates, identifiers, optional fields, large routes and escaping are tested. **Real MSFS 2024 EFB import has not been run.** Practical EFB/aircraft-FMS limits are unknown; 100 points is an acknowledgement threshold, not a claimed simulator maximum. There is no automatic simplification/densification.

SimBrief's official guide documents `591730N1403212W` custom fixes and DCT routing. The implemented whole-second option follows that notation, warns about rounding, and has not been tested through an authenticated SimBrief generation workflow. ICAO minute notation is separately labeled and warns about survey precision loss. The VATSIM documentation endpoints returned HTTP 403 to the cloud; current regional/VATSIM filing and ATC acceptance remain unverified. Human-readable science names are never assumed to be published fixes, and no external plan is filed automatically.

The native offline geography is intentionally coarse and its airport gazetteer is not exhaustive. Mercator display clips at ±85.0511°, while canonical coordinates/exports retain polar positions. Track display is bounded and incomplete by design; the complete archive remains accessible independently. Live next-target hints use observed positions in order within 1,000 m while the map is open and can miss crossings; they are not completion guarantees, certified navigation, pilot scores or aircraft-control commands.

## Data preservation and deletion behavior

Mission schema remains **5**. New geographic fields are optional JSON fields; v0.2.0/v0.2.1 missing fields read safely, recorded snapshots/telemetry are not rewritten, and there is no new SQLite migration. Existing schema-upgrade verified backup/rollback mechanisms remain intact. Universal/Realistic, plans, presets, two independent data locations, library identity/references and display settings are preserved.

Map preferences/key are separate stable configuration, not inside either movable store or the application installation. Uninstall preserves user configuration/data by default. DPAPI is tied to the Windows profile; copying profiles/machines can require re-entering a public key. Release inputs reject map configuration, and feedback collection does not copy it.

The deletion default is recreated when the existing native form opens, so it applies after restart and upgrade without changing user database/configuration. It does not mean deleting existing backups. Clear operations retain their independent database transactions and safeguards. Exact Windows picker/confirmation/cancellation behavior still needs the disposable-data procedure in [Windows acceptance](v0.2.2-windows-testing.md).

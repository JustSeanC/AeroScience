# v0.2.0 Windows / MSFS acceptance

Run the new SDK-built installer candidate from the [Windows build guide](public-release-windows.md). These are tests to perform, not completed results. Use disposable stores for deletion/failure tests and stopped copies of your v0.1.1 archives for upgrade preservation. Keep the previous installer and original data. Do not count older T-38/live-recording results as new atmospheric/guidance acceptance.

## Installed startup and upgrade

1. Record the exact installer/source/hash. Install in a clean Windows account/environment without developer tools. Check version/branding/progress, path, Start/optional desktop shortcuts, dependency setup, Installed Apps/uninstaller and launch-at-finish.
2. With MSFS closed and internet disconnected, launch from Start. The dashboard should open automatically with live telemetry unavailable; old simulated/live missions, modes, Mach-null records, history/details and full exports should still work.
3. Install over a backed-up v0.1.1 profile. Compare mission IDs/counts/telemetry, both storage paths/settings, library IDs/files and notes. Confirm verified `Backups` before schema 4 migration. Cancel setup/storage changes and confirm no silent move/replacement. Test upgrade while respecting the app-close prompt.
4. Confirm Community detection for the actual Steam/Store install, custom path/browse, Skip for Now and later Settings installation. Close MSFS before toolbar updates. Check no duplicate AeroScience copies or unrelated add-on changes.

## Spontaneous and planned live research

5. Start MSFS 2024, load a flight and launch AeroScience. Verify actual aircraft identity, timestamps, altitude/IAS/position/Mach. Match values/units against the simulator; record aircraft and conditions. No synthetic fallback is allowed.
6. Record an immediate Universal mission. Open/close dashboard and toolbar while it records. Compare counts/cadence/missing intervals across displays; investigate configured 1 Hz versus received cadence rather than assuming exact 1 Hz. End and reopen history.
7. Create/save an Atmospheric Profile plan. Edit objective, aircraft description, airports, ordered waypoints, altitude range/duration, polygon and notes. Save/reload it. Change its instruments/intervals. Review its science-only storage estimate/free capacity.
8. Start that plan. Confirm selected mode/template/instruments/objective and immutable recording snapshot. Edit the saved plan while recording and ensure the recording snapshot stays unchanged.
9. Compare actual ambient temperature/pressure/wind/density with official supported simulator readings. Validate Celsius, inHg, knots, true-reference wind degrees and slug/ft3. Missing readings should show unavailable, with other supported channels/flight recording retained. Record actual supported/unsupported fields; do not infer a measured pass from an enabled switch.
10. Enable/disable channels and change intervals. Verify actual success timestamps/counts/rejections/gaps, independent flight recording and no invented samples during pause, loading, source disconnect or storage failure. Test disconnect/reconnect and abrupt process recovery on disposable data.
11. Observe the offline grid, current heading, actual route, planned overlay, sample positions and markers. Add categorized markers/in-flight notes; verify stored UTC/position/context and coordinate ordering. Pan/zoom and inspect historical routes. This map intentionally has no online basemap.
12. With supported avionics, compare AP engagement, lateral/vertical/speed flags and actual selected targets. Check HDG/NAV/LOC/ALT/VS/FLC/GS/IAS/Mach only where reported; armed indications stay separate. Change targets without spamming mode events. Test AP off, unavailable/custom/conflicting indicators, pause/loading and stale/disconnected displays. The app must never control the aircraft/AP/flight plan.
13. Compare **Mach** in the desktop, toolbar and paired iPad. Include subsonic and supersonic operation where the aircraft supports it. Confirm historical/exported Mach matches actual samples and absent legacy values remain null.
14. Test full toolbar header drag, all edges/corners resize, minimize/close/pop-out, scrolling, keyboard focus and narrow layouts. The content container should not have the turquoise outline; individual interactive controls must retain focus styling. Browser mocks cannot establish native interactions.

## Offline review, storage and destructive operations

15. End/restart with MSFS and internet closed. Review flight/science statistics, plan snapshot, instrument diagnostics, markers, pre-/in-/postflight notes and graphs. Download complete JSON, flight/science/events CSV, GPX/KML and text summary. Check row counts, provenance, UTC, Mach, full coordinates and feet-to-metre conversion in a separate viewer. Long exports must exceed preview limits without truncation.
16. Using disposable copies, migrate the populated Science Library independently to another drive, then mission storage. Compare IDs, data/references and original retained copies. Disconnect/reconnect external storage; existing archives must not appear replaced with fresh empty ones. Exercise permission/capacity/conflict/recovery errors safely.
17. In native Settings → Storage → Data Management, inspect selected paths/scope/counts and backup offer. Cancel each confirmation and verify no changes. Wrong phrases and active recording must block clearing. Clear science only and verify flight history remains, links show unavailable and unrelated files/library identity stay. Restore test data; clear flight only and verify scientific datasets remain independently browsable. Verify optional saved-plan checkbox and settings retention. Check backup integrity before relying on it.
18. Uninstall/reinstall. Verify retained mission/science data and configuration; independently test toolbar Keep and explicit Remove choices while preserving unrelated Community add-ons. No uninstaller should erase these archives automatically.

## Device, aircraft and performance coverage

Repeat representative workflows with a default fixed wing, third-party fixed wing, helicopter and custom avionics aircraft. Record unsupported standard variables honestly; one aircraft is not proof for every aircraft.

Quest 3 testing should compare frame time/FPS and CPU/memory with/without the recording/toolbar, at narrow and normal sizes, over a sustained mission. Do not invent a VR-specific acceptance UI or claim desktop drag tests establish headset behavior. Pair a physical iPad through optional private-LAN settings and Safari, verify responsive controls/map/graphs, shared state and reconnect. LAN is optional and should use the Windows Private network profile only.

## Feedback

Use AeroScience **Collect Feedback** to save the local report/log ZIP; review it before sharing. Include installer/source/hash, Windows/MSFS/SDK versions, aircraft, source/quality/cadence, steps, expected/actual results, relevant timestamps and screenshots/video. Include console errors only from the relevant Coherent AeroScience target. Source-map `.map` 404s alone do not establish a runtime failure. Never include private correspondence, pairing secrets or an entire personal archive without intending to share it.

Record actual results against the exact candidate's generated acceptance groups. Any missing required result remains pending. See [completion status](v0.2.0-completion.md) for cloud evidence and its limits.

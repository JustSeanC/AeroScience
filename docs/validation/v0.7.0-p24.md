## Strict numeric-token correction and superseded acceptance

A final schema audit added a test for quoted numeric version/criterion tokens under
an otherwise matching canonical digest. It **failed as expected** on the first
candidate: the web JSON defaults coerced strings to numbers. Portable deserialization
now explicitly uses `JsonNumberHandling.Strict`. The unchanged digest cannot make a
wrong JSON token type valid. The correction does not change the ordinary API binder,
scientific calculations, numeric bounds, credentials, database schema or deadlines.

Corrected focused evidence: **28 .NET passed / 0 failed / 0 skipped**, including all
24 portable cases and real PostgreSQL proposal/publication/execution paths; **5 real
browser workflows passed / 0 failed / 0 skipped**, including numeric-type rejection,
valid import/export/editing/restart and editing all eight organizational definitions.

The first Full run, [40807063432](https://github.com/JustSeanC/AeroScience/actions/runs/40807063432),
on `890a36fb1ae9dce3b7cb3743d1859ee784aae721` was deliberately cancelled as superseded.

browser/Windows gates were not completed and it is **not** accepted Full evidence.

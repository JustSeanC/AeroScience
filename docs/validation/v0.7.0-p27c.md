## Implemented product

Organization Settings → Notifications, OFF by default, one masked/encrypted incoming-webhook destination per organization. Active administrators with recent MFA can configure/rotate/delete, preview/test, choose categories, explicitly disclose current approved research/accepted exceptions and inspect paged delivery history. Pilots separately authorize/revoke an exact flight/destination revision in the organization browser, linked from AeroScience. Existing desktop permissions gain no Discord authority.

The authoritative P27 event stream feeds a durable PostgreSQL outbox. Flight announcements require independent consent; approved research summaries and exceptions require explicit exact-message disclosure approval. Unsupported client completion, recorded attempts, private findings, receipts and unapproved science cannot be promoted into public success. Posts contain no coordinates, tracks, samples, notes, private mission names or reviewer comments.

Production HTTPS uses strict Discord endpoints, all-answer DNS validation, pinned checked socket peers, normal hostname/chain validation, no proxy/redirect, bounded sanitized messages, empty allowed_mentions and bounded acknowledgment reads. Credentials use existing protected key infrastructure and never enter response/revision/audit payloads. Unique event/destination revisions, source/consent rechecks, bounded scheduling/retries, destination-wide rate-limit delay, cancellation and restart recovery preserve privacy. A valid Discord message identity is required for Delivered. Lost/uncertain acknowledgment becomes Ambiguous and is never automatically retried.

See [architecture and limits](../architecture/organization-discord-notifications.md) and [nontechnical user guidance](../v0.7.0-organization-notifications.md).

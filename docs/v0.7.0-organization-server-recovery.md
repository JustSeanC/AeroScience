# Recover your organization

Use this after a tested recovery server is ready. You need the private recovery file saved outside the lost hosting account, plus your original administrator sign-in and authenticator or unused recovery code. Do not share that file in chat. No owner action is requested during repository development.

1. Sign in to the secured recovery server. Open **Server Protection**.
2. Open **Restore From Private Recovery File** and choose your saved file. Check the organization and old address.
3. Read the choices, tick the confirmations, enter your current password and choose **Prepare Independent Restore**.
4. Choose **Refresh Protection Status**. When **Restore Organization** shows a verified name and checkpoint, choose **Activate Restored Copy** only if they are right.
5. After restart, sign in with the **original** administrator account. Open **Members** to review held memberships and **Create Invitation Link** for new invitations. Reconnect desktop accounts and configure a new Discord webhook if needed.

You should see the original received research and history. Sharing and notifications stay off. Returning to a checkpoint does not merge later changes from the old database. The old database is retained rather than silently deleted.

Mark **Pass** or **Problem**. If something looks wrong, stop and save one screenshot or a short explanation; no commands or database work are required from you.

Current limits: guided import supports an existing independently controlled standard AWS S3 repository. Account creation, billing, first-time independent-storage setup and real account-loss recovery have not been accepted. A key alone is not a backup, and a Bucket in the lost hosting account is not independent protection. These are release gates, not instructions to create or pay for accounts now.

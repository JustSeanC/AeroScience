# EMIT 1B — scientific product contract and original verification

This is a backend decoder milestone, **not user-facing EMIT import**. Library/download/map/analysis
integration is 1C; genuine authorized-original numerical acceptance remains pending. No mission,
Scientific Library database, provider connection or source is created by the decoder/probe.
The [definition ledger](v0.6.0-emit-product-definitions.json) pins the official NASA reference and
SDS writer commits, document hashes, actual CMR collections and matching public granules.

## Supported definition

`EmitProductDecoder.OpenAsync` validates three explicitly selected originals. `ResolveOriginals`
orders an exact unordered triple; missing/duplicate roles, different acquisitions or ambiguous
selection fail rather than choosing a substitute. Only these product definitions are supported:

| Original | Collection / version | Numeric variables |
|---|---|---|
| `EMIT_L2A_RFL_002_<time>[optional orbit/scene].nc` | EMITL2ARFL / 002 | `reflectance`: float32, native downtrack × crosstrack × 285; fraction/`unitless` |
| `EMIT_L2A_RFLUNCERT_002_<same time>[same suffix].nc` | Same RFL collection / 002 | `reflectance_uncertainty`: float32, same dimensions and spectral channels |
| `EMIT_L2A_MASK_003_<same time>[same suffix].nc` | EMITL2AMASK / 003 | `mask`: float32 × 7; `band_mask`: uint8 × 36 packed bytes |

The current mask producer defines, in order: Cloud Flag, Cirrus Flag, Water Flag, Dilated Cloud Flag,
SpecTf-Cloud Probability, SpecTf-Cloud Flag, SpecTf-Buffer Distance. The older guide describes eleven
bands; it is not silently applied to a seven-band V003 file. An unverified layout is rejected.
The September 2026 NASA release explicitly pairs V002 reflectance/uncertainty with V003 masks;
equal version digits are neither required nor sufficient for compatibility.

Required original metadata includes EMIT instrument, product-specific title, `flight_line`, product
version, CF conventions and matching UTC acquisition start/end. Reflectance and uncertainty must
also share original software build/delivery revisions; mask processing revisions remain independent. The SDS writes `+0000`; `Z` and
`+00:00` are also supported. Missing timezones are not guessed. Original metadata and hashes remain
in source evidence. A compatible header alone does not prove NASA authenticity or numerical accuracy.

`sensor_band_parameters/wavelengths` and `fwhm` are original float32 nanometres;
`good_wavelengths` is **uint8**, not the old research fixture's int32. Reflectance/uncertainty
vectors and good-band definitions must match exactly. Missing wavelengths are never generated.
The returned definition retains original units, fill, CF scale/offset and their origin. Absent
scale/offset use documented CF identity defaults, not invented calibration. Raw little-endian numeric
bits remain available alongside physical values and separately QA-filtered usable values.
Finite negative or >1 estimated reflectance is not clipped. Fill/nonfinite values, excluded bands,
negative/missing uncertainty, interpolation and unknown/excluded QA have distinct states.

## Spatial and quality interpretation

Native `location/lat`/`lon` float64 arrays remain a swath, **not an affine original raster**.
`location/glt_x`/`glt_y` int32 map a derived geographic grid to one-based source column/row.
Zero, negative and out-of-range references yield explicit unavailable cells, never wrapped indices.
Only documented north-up WGS84 geographic GLT transforms/WKT forms are accepted; other projections,
rotations or dateline/polar extents are unsupported. `DerivedGltDomain` is grid extent, not verified
scientific coverage. Grid pixel centres and original native coordinates are returned separately.

Metadata checks establish scene, shape, spectral and grid compatibility. Every returned native
window also compares companion coordinates exactly; every geographic window compares companion GLT
entries before sampling. This does not claim the unvisited whole scene was scanned. Source hashes
are verified by the 1A worker before/after each request. No originals are rewritten or reconstructed.

The versioned AeroScience QA policy checks Cloud/Cirrus/Dilated/SpecTf **binary flags**; water exclusion
is optional. Probability and buffer-distance values remain quantitative data, not boolean errors.
Packed interpolation flags use big-bit order and original absolute spectral indexes. A single packed
byte may equal its encoded fill value; a whole fill vector is indeterminate when band QA is requested.
Unknown/nonbinary required flags never become passes. Quality-filtered support is limited to the
requested cells/bands and policy, not a whole-scene coverage percentage or measurement certification.

1A isolation, 128 MiB heap/256 MiB process controls, pre-resolution external/symbolic/raw/virtual
rejection, 4 MiB chunks/output, read budgets and cancellation remain enforced. 1B further bounds
native requests to 4,096 pixels / 32,768 spectral values and geographic requests to 64 cells whose
native bounding window fits those limits. These are request limits, never total Library capacity.
Only bounded string-label vectors/attributes were added to the same isolated reader; unsupported
types stay unsupported. No chart-native build/runtime or competing decoder process was introduced.
Full-file streaming integrity hashes can make large-original probes I/O intensive. Keep the validated
product handle for repeated windows; 1C must schedule/cache work safely without dropping integrity checks.

## Owner-authorized genuine-original procedure

No Earthdata credentials were available in this cloud session. One 1-KiB Range probe returned **302
to urs.earthdata.nasa.gov**, without following login or reading protected pixels. Public CMR confirms
the matching `20220810T034103` V002 RFL/RFLUNCERT and V003 mask; catalog records are not numeric acceptance.

1. In official Earthdata Search, select matching **EMITL2ARFL.002** and **EMITL2AMASK.003** granules.
   Download the original RFL, RFLUNCERT and MASK NetCDF files through your own authorized NASA session.
   Do not use PNGs, resized/subset files with altered identities, passwords in chat or copied cookies.
2. Keep the files under an approved **0.6.0 validation Library** `Sources/` or `Downloads/` directory,
   retaining original filenames. Do not alter the production v0.5.0 Library. If a separate staging
   Library is needed, create a new validation directory/`library.json` identity and explicitly copy
   only these three authorized files after checking available space. No application import is implied.
3. In a clean 0.6.0 development checkout, use the pinned .NET SDK and build the existing test host:

```powershell
dotnet restore AeroScience.sln --locked-mode
dotnet build tests/AeroScience.TestHost -c Release --no-restore --output C:\AeroScience-Validation\EMIT-1B-host
```

Create a local `emit-request.json` (keep local paths private), adjusting actual paths/scene and the
selected in-bounds sample. Example structure; coordinates here are **array indexes**, not lat/lon:

```json
{
  "libraryDirectory": "C:\\AeroScience-Validation\\EMIT-Library",
  "relativeOriginals": [
    "Sources/authorized/EMIT_L2A_RFL_002_20220810T034103.nc",
    "Sources/authorized/EMIT_L2A_RFLUNCERT_002_20220810T034103.nc",
    "Sources/authorized/EMIT_L2A_MASK_003_20220810T034103.nc"
  ],
  "nativeWindow": {"row": 0, "column": 0, "rows": 1, "columns": 1, "firstBand": 0, "bandCount": 285},
  "geographicWindow": {"row": 0, "column": 0, "rows": 1, "columns": 1, "firstBand": 0, "bandCount": 285}
}
```

The validation Library marker is `{"formatVersion":1,"libraryId":"<new UUID>"}`. Existing configured
0.6.0 Library identity must be preserved. Run against a **new output directory** outside the Library:

```powershell
dotnet C:\AeroScience-Validation\EMIT-1B-host\AeroScience.TestHost.dll --emit-product-probe .\emit-request.json C:\AeroScience-Validation\EMIT-1B-report-01
```

4. Use a separate scientific validation environment with **NumPy + trusted NetCDF-C** (e.g. a local
   conda environment providing `numpy` and `libnetcdf`; not an application runtime dependency):

```powershell
python scripts/research/verify_emit_originals.py --library C:\AeroScience-Validation\EMIT-Library --report C:\AeroScience-Validation\EMIT-1B-report-01 --netcdf-library C:\path\to\trusted-environment\Library\bin\netcdf.dll
```

On Linux the independent tool discovers `libnetcdf` automatically; omit `--netcdf-library`.
It checks original hashes, native values/scaling, wavelengths/FWHM, uncertainty, raw/selected QA,
packed bits, native coordinates and GLT centres/mapping without using PureHDF as its own reference.
Choose additional clearly located, excluded/cloudy/fill and bad-GLT windows using official scientific
tools; a zero GLT at the first corner alone cannot establish valid-pixel acceptance. Reopen offline
and compare the same retained originals again, using new report directories.

5. Retain exact source/build revision, approved acquisition method and CMR metadata, original hashes,
   product-definition/native/geographic reports, independent comparison and any unsupported errors.
   Reports may contain protected scientific samples: keep local unless sharing is explicitly permitted.
   The script verifies a comparison; it does **not** promote NASA acceptance records automatically.
   Record genuine numerical/format acceptance only after those actual originals pass. Installed
   Windows/MSFS, physical iPad/Quest and 1C user workflow acceptance remain separate.

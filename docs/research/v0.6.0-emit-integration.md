# EMIT 1C application integration — development validation

This unpublished 0.6.0 capability uses the 1A isolated reader and unchanged 1B decoder.
Application integration and synthetic process tests do **not** establish NASA original numerical
acceptance. Only RFL002, associated RFLUNCERT002 and the supported seven-layer MASK003 definition
are accepted. Older eleven-layer masks, radiance, different versions and incompatible companions
fail closed. See [product contracts and the authorized-original procedure](v0.6.0-emit-products.md).

## Pilot workflow

In **External Data Manager → Find & Download Data**, choose **EMIT · development validation**.
Use the existing geographic map/coordinate selection, dates and CMR discovery. Catalog outlines
are source metadata, not valid-pixel coverage. Select the exact scene and **Preview NASA Download
& Import**; acknowledge pending genuine acceptance, review the three exact original names, known
HEAD lengths, full-scene transfer/reservation allowance and source versions, then explicitly approve.
The existing Earthdata connection, durable Library job, budgets, verified staging, safe range
checkpoints, pause/cancel/retry/recovery and flight-priority scheduler control the transfer.
No new account, database, downloader or runtime dependency was added.

CMR must identify one exact MASK003 scene with matching acquisition start/end; RFL and uncertainty
are assets of the RFL granule. Missing/ambiguous companions never produce guessed download URLs.
Only exact unsigned official LP DAAC original paths are eligible for bearer requests. Login or
unverified redirects stop acquisition without forwarding credentials. **Authorized direct transfer
has synthetic HTTP integration evidence only; genuine LP DAAC token/redirect compatibility is
pending owner testing.** Use official Earthdata browser acquisition and the local workflow if blocked.
Browser download bytes/progress are not controlled or reported as AeroScience job progress.

For files already legitimately acquired, use **Import NASA EMIT Originals** on the companion PC.
The native Windows picker accepts the exact three `.nc` originals. No browser API accepts arbitrary
local paths. Originals are staged with bounded copies, pre/post hashes and storage checks; the
isolated decoder validates metadata and bounded native/GLT samples before approval/publication.
Review the exact identity, original bytes and pending-acceptance warning, then acknowledge and
choose **Import Verified EMIT Source**. Closing the dialog does not cancel an import. Cancel Import
is a separate action; incomplete staging is never advertised as a usable source.

In **Manage Downloaded Data**, expand the collection's **Individual Regions & Provenance**, then
choose **Explore Spectrum / Map / Export**. Paired browsers can explore retained sources; native
file selection and local-source mutation remain restricted to the companion PC.

- **Explore Spectrum:** zero-based native row/column, all 285 original channels, numeric wavelength
  and FWHM, decoded reflectance, uncertainty and QA-usable values. The chart uses an actual numeric
  wavelength axis, with uncertainty bounds and optional explicitly unfiltered original values.
  Negative/>1 estimates are retained. Missing/excluded/unknown values are not plotted as usable.
- **View on Map:** select a channel and a bounded GLT window (up to 64 cells, subject to 1B native
  span/value limits). Only decoded requested cells are drawn, with unitful legends, native links and
  accessible tabular inspection. Invalid GLT cells, missing and QA-excluded values remain distinct.
  The broader GLT domain is a candidate envelope, not a complete-scene QA map or original affine raster.
- **Compare / Analyze:** first-minus-second QA-usable reflectance for two samples in the same scene,
  channels and quality policy. Missing values stay missing; no unsupported cross-sensor equivalence.
- **Export Data & Provenance:** bounded self-contained JSON with wavelengths, units, uncertainty,
  raw numeric bytes, native/geographic sample identity, masks, original attributes/hashes and policy.
  It is decoded historical evidence, not a NASA original or aircraft observation. Reopen the JSON
  offline; original protected cubes/credentials are not embedded. Review sample-location privacy
  before sharing. The authenticated export API provides the same versioned scientific content.

## Storage, reuse and compatibility

An optional versioned `ScientificSwathSource` extends existing immutable source JSON; it is omitted
for legacy sources, preserving their serialized hash input. Library schema remains **4**, MissionStore
**8**. Existing indexed/keyset inventory includes swath domain candidates without creating a fake
`RasterGrid`. All three original files and source provenance are retained atomically through the
existing importer. New decoder verification is mandatory for a swath manifest; the affine importer
cannot bypass it. Existing ENVI and GeoTIFF behavior remains.

Exact original hashes/names/policy reuse one retained source. Public CMR UMM original SHA-512
checksums, when supplied, are matched against retained bytes before any protected dataset transfer;
filenames/geographic overlap alone cannot establish exact reuse. Advertised original checksums are
also checked before downloaded-source publication. Missing checksum metadata is Unknown and cannot
justify cross-workflow content reuse. A completed approved NASA job also
retains the exact catalog-to-source association when its source was previously imported locally;
offline previews use that existing job record without rewriting source provenance or another transfer.
Deleted/corrupt sources cannot satisfy this reuse. No total Library source-count cap was added.

No persistent derived EMIT cache is created. The existing permanent-deletion preview/hash/ownership
and transaction safeguards remove selected managed originals and duplicates. No hidden restoration
archive is made. User-owned input files and exported JSON outside managed scope are not silently
removed. Independently saved mission science and unrelated data retain the existing safeguards.

**Automatic aircraft EMIT sampling / affine composites are not implemented by this source adapter.**
The source is usable for historical scientific exploration, comparison and export. It is explicitly
excluded from the legacy affine flight sampler; import never creates mission observations, acquisition
credit, recovered historical flight evidence or changes to frozen grading obligations.

## Performance and current limits

One adapter operation at a time; isolated HDF work remains globally serialized with the 1A worker
limits. Requests are bounded and cancellable; closing exploration aborts its reads, not downloads.
Full original hashes are rechecked. Large originals therefore incur I/O cost, not cube-sized memory.
EMIT import/exploration waits during active recording; an already running bounded worker remains
below-normal priority. Nothing decodes on the telemetry lock, browser polling or simulator toolbar.
The existing scheduler preempts background transfers for live acquisition. Local imports use existing
per-file/per-source operational bounds and physical storage/reservation checks, not collection limits.
Large-real-file throughput and installed Windows/native file picker behavior still need owner evidence.

After a process restart, Library originals and completed durable jobs reopen offline. An interrupted
unapproved local picker review is not silently approved/restarted; existing managed-work diagnostics
account for its staging. Clear/clean it explicitly and reselect originals. NASA job recovery uses the
existing durable intent and range verification. Unverified layouts remain unavailable without touching
originals or mission recording.

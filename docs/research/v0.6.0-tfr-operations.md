# FAA TFR operational interpretation — 2A

This is an advisory MSFS reference, not a real-world briefing or clearance service.
EMIT 1D remains **Pending owner-authorized genuine-original acceptance**; no owner action
is requested for this milestone.

## Implemented workflow

Open the existing map's **Overlays & Legend → TFR Boundaries & Screening**. Refresh the
consented host inventory, inspect a notice, then choose **Retrieve Official Operational
Details**. The host retrieves only that notice's two official XML/AIXM packets, up to
512 KiB each. Reading retained details, paired-device review and mission screening do
not poll FAA. Existing five-minute throttling, consent, unmetered policy, Retry-After,
redirect rejection and the one-writer refresh gate apply. No credentials are required
for these public packets. URLs are generated from a strictly validated retained NOTAM ID;
there is no arbitrary URL fetch or XML external-entity resolution.

Details show original work/issuance identity, per-area limits, UTC windows when supported,
last success/attempt/error, official links and original hashes. XML issuance without a
zone stays original text, not an invented UTC timestamp. The existing saved-mission
screen uses whole-mission time/altitude envelopes, not inferred arrival times at individual points. It accepts an explicitly selected real-world UTC interval; simulator time remains
separate. Saved MSL limits can be compared with supported MSL boundaries. AGL and
standard-pressure limits are displayed without guessing terrain or pressure conversions.

## Source and interpretation contract

The official client at `https://tfr.faa.gov/tfr3/` calls `getTfrList`, `noShapeTfrList`
and the existing `TFR:V_TFR_LOC` WFS. Its `getWebText?notamId=…` notice links point to
`https://tfr.faa.gov/download/detail_<digit>_<number>.xml` and `.aixm50`.
The app generates these exact trusted paths; it does not parse HTML into operational facts.
The WFS DescribeFeatureType has identity/title/modification fields but **no** vertical or
activation attributes. These public graphical/download interfaces are verified observations,
not a documented stable external API or FAA completeness/SLA promise.

Version 1 retains byte-exact originals, SHA-256, retrieval UTC and a fingerprint of the
selected inventory/geometry revision. Interpretation supports XNOTAM 0.1 and the FAA
AIXM 5.0 namespaces. Exact NOTAM, revision/issuance, facility, linked area and supported
numeric limits must agree. An absent work number remains Unknown. AIXM's `year` is **not**
used: all four sampled 2026 notices incorrectly carry `2006` there. One AIXM packet appends
`Z` to issuance where XML omits it; comparing identical calendar components does not
assign a timezone to the XML text.

A single non-recurring XML ScheduleGroup becomes UTC only when its dated components
agree with the exact area's explicit UTC AIXM Timesheet. Recurring/daily, ambiguous,
missing or unsupported schedules stay Unknown. Local display timezone codes never
supply a conversion. ALT, HEI and STD remain MSL, AGL and standard-pressure references;
units and inclusion codes are retained. XML merged WGE/GRC rings join WFS areas only
when normalized original coordinates agree within **1e-8 degree**, the supported packet's
decimal representation bound. This is a join tolerance, not a geographic buffer or a
relaxed projection test. No circles/arcs, holes or segments are guessed from names/order.
Unsupported geometry keeps its operational metadata but cannot supply a boundary join.

The existing schema-5 aviation store's generic atomic snapshot/attempt tables hold
`tfr-detail-<NOTAM>` records. **No migration, new database, source ID, scientific budget,
scientific observation or dependency is introduced.** Original boundary snapshots and
historical scientific evidence are unchanged. API projections omit raw originals and
polygon duplicates. Viewport/screen requests interpret at most 32 distinct notice records;
additional records stay unassessed. This is a request resource bound, not a cache capacity.

## What screening can establish

Each horizontal match has independent time, altitude and provenance findings. A supported
published window can be upcoming, elapsed or currently within its interval; none verifies
that the restriction is uncancelled or legally applicable to this aircraft. An assessed
MSL/time exclusion is labeled **Outside assessed dimensions; lifecycle unverified**.
Uncertain matches remain **Potential intersection**. Missing, changed, failed, older-than-
15-minute or offline evidence cannot reduce a potential warning on current applicability.
No matches or only exclusions still produce **Unable to determine**, because the feed is
not verified complete. Neither a confirmed legal conflict nor an all-clear is fabricated.

Amendment/cancellation events, supported recurring activation expansion, complete feed
coverage and aircraft-specific legal applicability remain **Unknown**. Notice disappearance
is not cancellation. Revision changes invalidate old interpretations. Unsupported lifecycle
packets fail closed and preserve prior evidence marked non-current. No authenticated NOTAM
API access is available/claimed; additional source support needs its own verified contract.

## Evidence and reproducibility

Genuine public requests on 2026-10-24 downloaded notices **6/2070, 6/2069, 6/2014 and
6/9169**, their eight packets, and the three official inventory/geometry originals.
Exact URLs, SHA-256, lengths and UTC retrievals are in
[fixture receipts](../../tests/AeroScience.Tests/TfrOriginals/receipts.json). They are
FAA public reference records, attributed to the FAA; no NASA originals or credentials.
A legacy `/save_pages/…xml` candidate returned 404; the client-linked `/download/…` path
worked. There were no repeated provider retries. Live list counts were 76 notices,
82 geometry features and 15 listed without shapes; this does not prove completeness.

Developer replay, using the actual service/SQLite cache, emits bounded results:

```text
dotnet run --project tests/AeroScience.TestHost -c Release -- --tfr-operations-probe <new-directory>
python scripts/research/verify_tfr_operations.py --originals tests/AeroScience.Tests/TfrOriginals --application <new-directory> --output <new-report.json>
```

The independent second command uses development-only rasterio/PROJ and Shapely. It
checks original hashes, identities, five area/altitude/geometry joins, three explicit
UTC windows and two recurring schedules retained Unknown. All 370 coordinate components
were compared; maximum XML/WFS distance was **6.334818096922164e-9 degree**. The application
uses a disclosed fixed replay clock; it is not presented as a live-current FAA test.
Offline reopening makes zero requests. Unit mutations cover expired-window evaluation,
incompatible companions, canceled/unknown lifecycle packets, redirects, rate limiting,
corruption and malformed XML; these are synthetic/adversarial evidence, not real canceled
NOTAM acceptance. A complete authoritative amendment/cancellation test remains blocked on
an appropriate source. No test creates a flight or changes scientific originals.

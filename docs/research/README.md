# Scientific research and verification records

These records preserve original provider identities, source dates, units, grids, QA,
retrieval/processing context, numeric comparisons and source hashes. Retain them for
reproduction and release verification; age alone is not a reason to delete evidence.

- v0.5.0 [automatic providers](v0.5.0-automatic-provider-acceptance.json),
  [guided ENVI](v0.5.0-guided-envi-acceptance.json) and
  [workspace](v0.5.0-workspace-acceptance.json) are **pending**, not acceptance passes.
- v0.4.2 [automatic providers](v0.4.2-automatic-provider-acceptance.json),
  [guided ENVI](v0.4.2-guided-envi-acceptance.json) and
  [workspace](v0.4.2-workspace-acceptance.json) retain their original source-bound findings
  and limitations. They do not approve changed v0.5.0 code or current installed hardware.
- [Manufacturer/provider investigation](v0.4.0-provider-investigation.json) records
  inspected references. Earlier records in this directory remain technical evidence for
  their named versions, including negative/unavailable cases.

Use the [scientific methods](../v0.4.0-scientific-methods.md),
[verification procedure](../verification.md) and [current development tracker](../roadmap/v0.5.0-development-tracker.md).
Synthetic aircraft positions and test rasters are never proof of real MSFS measurements.
Release verification still requires the current genuine-source evidence and separately
applicable installed Windows/MSFS/device acceptance.

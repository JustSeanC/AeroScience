## Transport findings

| Question | Researched answer / boundary |
|---|---|
| Minimum | API v1: X-Plane 12.1.1; v2: 12.1.4; v3: 12.4.0. Use the common v1 read surface; do not require the newest version. |
| Endpoint | Default `http://localhost:8086/api/v1/...`, WebSocket `ws://localhost:8086/api/v1`. Client design uses explicit loopback addresses only. |
| Version discovery | Read unversioned `/api/capabilities` when present. A legacy 404 permits a bounded v1 probe; a 403 or malformed response is not permission to bypass policy. Prefer advertised v1; unknown-only versions are unavailable until deliberately supported/tested. |
| Port | `--web_server_port=` can change X-Plane's port. Offer one advanced local port setting; no port scans, LAN discovery or simulator configuration writes. |
| Enabled/configuration | Server is built in. “Disable Incoming Traffic” in Network security denies API requests with 403. The article does not establish every installation's factory/security defaults; owner verification is pending. No extra plugin or automatic firewall change is proposed. |
| Discovery | Exact-name filters on `/datarefs`, with bounded pagination and `id,name,value_type`. Empty registry before the first loaded flight is documented. Resolve names again each connection epoch; never persist numeric IDs. IDs are stable across aircraft loads within a simulator session, but availability must still be rechecked. |
| Read/subscription | GET `/datarefs/{id}/value`; `dataref_subscribe_values` / `dataref_unsubscribe_values` over WebSocket. `result` acknowledgements and data updates are separate. |
| Updates | Documented current cadence is approximately 10 Hz. First subscription update supplies all subscribed values; later updates contain changes. Neither atomic sensor sampling, source timestamps nor guaranteed cadence is documented. |
| Types | Scalars/arrays plus base64 `data` values. Preserve numeric ID precision; WebSocket object keys are decimal IDs. `req_id` is a separate unique integer, bounded by 2,147,483,647. |
| Reconnect | Reconnect, negotiate, rediscover, subscribe, await acknowledgement and a complete seed; discard prior-epoch values/late replies. Durable reconnection or frame replay is not promised by the API. |
| Errors | Treat connection refusal/timeout, HTTP 403, 404 missing name/ID, malformed/oversized messages and failed subscription results distinctly. No synthetic fallback. |

These are API facts/design consequences, not installed acceptance. API availability at the chosen endpoint does not by itself establish a running flight or scientific readiness. The server has write-capable interfaces; AeroScience must enforce its own strictly read-only outgoing allowlist.

## Telemetry mapping matrix

**S** = simulator-reported quantity; unit normalization does not turn it into an independent physical measurement. **D** = explicitly derived, not a direct observation. **M** = required core value: if absent/invalid/unconfirmed, emit a status-only Initializing/Unavailable update that clears the old pose; never relax `IsValid`. **O** = optional: null/unavailable with a named reason. **G** = genuine installed validation required; **every row below has G**, including strings, zeros, date boundaries and signs. Native types are from DR; Web API encodes byte data as base64. Existing names/units are from [TelemetryFrame](../../src/AeroScience.Shared/Models.cs), [AtmosphericFrame](../../src/AeroScience.Shared/ResearchModels.cs) and [EnvironmentFrame](../../src/AeroScience.Shared/MissionScienceModels.cs).

## Required snapshot, security and reliability design

The [architecture](../roadmap/v0.8.1-architecture.md#snapshot-and-lifecycle-contract) specifies acknowledgement/epoch handling, bounded complete snapshots, unchanged-value confirmation, clocks, stale clearing and acquisition timing. In particular, a timer must not redate old cached weather and create new observations. Unchanged is not the same as stale; use independently tracked confirmation/read times and source-clock progress, then qualify the proposed refresh budget in the real simulator.

Only the local backend contacts X-Plane. Outgoing HTTP permits GET for the approved discovery/value endpoints; WebSocket permits subscribe/unsubscribe only. Deny redirects, proxies, non-loopback hosts, URI credentials and arbitrary URLs; no POST/PATCH/command/flight/write messages. Keep AeroScience LAN pairing/CSRF and scientific network consent independent. Neither local TCP success nor a synthetic fixture is proof of genuine hardware or flight identity.

## Alternatives and decision

| Option | Assessment |
|---|---|
| Bundled Web API | Preferred: documented discovery and typed read subscriptions cover core candidates with no extra plugin. Use built-in .NET facilities; actual timing/validity still untested. |
| UDP Data Output | Official manual supports user-selected network output/ports. Adds output configuration, datagram loss/order and format/field maintenance; no implementation or automatic fallback in v0.8.1. |
| XPLM plugin | Native read access and lifecycle hooks could address a proven gap but require installed plugin/build/distribution/lifecycle work. Not required by documented core mappings; reconsider only on a demonstrated blocker and owner decision. No native panel in scope. |

**Conditional go for P02 protocol/provider development**, not release approval. No documented blocker requires a plugin for the identified core channels. Remaining questions can be isolated and tested rather than solved by a second science engine.

| Question / release risk | Resolution gate |
|---|---|
| Real factory API/network policy, binding and older-v1 response behavior | P02 fixtures; P06 inspect exact Windows installations without changing policy automatically |
| Menus/unloaded flight, pause/replay and clock/reset semantics after an earlier loaded flight | P02 state-machine fixtures; P06 actual lifecycle traces; API-connected alone cannot authorize recording |
| Attitude signs/local reference, low-speed track, aircraft ground/CG reference, third-party string/guidance behavior | P04 normalization/geometry tests; P06 independent cockpit/pose comparisons |
| Full simulated UTC year/date unavailable on baseline; `zulu_date_days` only since 12.4.1 | Keep explicit unknown components; host UTC remains authoritative archive time |
| Unchanged-field confirmation, delivery gaps, non-atomic composites and sustainable cadence | P02 bounded refresh tests; P06 measured timing/30–60 minute resources; fail closed if budget cannot be met |
| Ambient density compatibility, missing environmental equivalences, accelerated time and continuity eligibility | P04 capability/provenance gates; P06 real channels; unsupported features remain clearly unavailable |
| New origin metadata through exports/evidence and older organization servers | P04 minimum persistence; P05 versioned export/receiver tests; never strip identity to gain compatibility |

Owner actions and exact acceptance observations are enumerated in [P06](../roadmap/v0.8.1-implementation-plan.md#p06--real-simulator-validation-and-release-acceptance). P01 has not installed anything, modified a simulator, changed records or validated an X-Plane flight.

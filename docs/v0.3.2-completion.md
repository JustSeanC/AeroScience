## Recording root cause and protection

`DatabaseBytes()` previously used `File.Exists()` followed by `new FileInfo(...).Length` for the primary database and SQLite sidecars. A sidecar can disappear between these operations when SQLite checkpoints/closes its last non-pooled connection. The resulting `FileNotFoundException` traveled through `RequireFlightCapacity()` to the coordinator's interruption handler. The deterministic reproduction matches the reported `missions.db-wal` failure path without claiming corruption or external deletion.

The primary file is now read strictly. Only `FileNotFoundException` for `-wal`/`-shm` is benign. Permission, I/O, quota and database failures still propagate. No fake sidecar is created and no archive is replaced. Scientific storage distinguishes a verified library that has never created a database from a missing previously initialized database. Related optional file/status accounting was reviewed for disappearance races.

Actual append failures and capacity failures both produce an explicit stop diagnostic. Event/finalization writes are best effort if the real database has become inaccessible; committed rows remain intact for normal startup interruption recovery. Science stops even when its final event cannot be saved. Science-processing exceptions cannot unexpectedly take down an otherwise healthy flight recorder.

## Scientific acquisition investigation

The earlier screenshot alone does not establish a broken science engine. Sources preparing, wrong coverage/date/source mode, QA/nodata exclusions, queue delay and unexpected I/O are distinct conditions. Expected unavailable intervals now have explicit reasons; checksum, storage and decoder errors remain errors.

The former shared queue could cause head-of-line blocking across instruments. Each remote instrument now has its own two-item bounded queue/worker, outside the recorder gate. Queue overflow reports Processing delayed and preserves missing intervals. Per-acquisition processing time is measured. A ten-second, four-instrument 1 Hz synthetic-data test checks saved products and uninterrupted telemetry; this is not a real-flight throughput guarantee.

Source-ready envelopes do not prove valid measurement. Thermal QA/saturation masks, Sentinel SCL and hyperspectral bad bands remain enforced. No missing flight-time observation is backfilled. Results refresh automatically without replacing an open detailed viewer.

## Transfer accounting and preflight

The user screenshot did not prove a stranded reservation in that specific flight. Confirmed implementation problems included full-maximum speculative reservations, hidden reserved totals, terminal cached Unavailable states after temporary exhaustion, and a failed-small-reservation path whose cleanup could subtract bytes that had never been reserved.

A lease now reserves the next bounded read before a provider request and moves **actual received body bytes** from reserved to consumed. Disposal releases only its own remaining reservation on every exit. Failed/partial transfers remain charged. Waiting allowance states retry instead of remaining terminal for thirty minutes. Settings changes cancel current work while preserving charged usage; already authorized in-progress reads are still accounted.

Flight retains the **256 MiB per rolling hour** new-install default and existing explicit values (including 800 MiB). Preflight uses a separate **1 GiB per application-session** default volume. Each has an explicit nullable Unlimited option. Unlimited changes only aggregate volume: per-preparation size, 1–2 concurrent jobs, consent, unmetered restrictions, provider pacing, validation and storage limits still apply. Preflight and flight actual transfers are also shown as a combined session total. These counters measure application-consumed payload, not TLS/header/network-adapter overhead. Usage ledgers are application-session state; preferences persist across restarts.

Saving a plan does not begin downloads. Review shows instruments, bounded route/survey regions, retained footprint candidates for the first 128 inspected regions, limits/storage and an honestly unknown size before provider selection. Explicit sessions continue with their own approval even if automatic background retrieval is off. Pause stops new session jobs while an active read can finish. An active mission pauses unfinished speculative preflight; it remains paused until explicitly resumed. Useful promoted current-flight work and verified originals are preserved.

## Provider-native reuse, regions and measurements

Retained source grids can satisfy multiple preparation areas and future missions. Point/area checks use authoritative stored grids without reopening every TIFF merely to test coverage. Original files are still checked and hashes verified before use. Partial sources remain partial; masks and each source's original date/calibration/identity stay separate.

STAC candidates/catalog metadata have short bounded caches. COG blocks are shared only after a fresh stream header confirms the same asset ETag; changed/unversioned assets do not share blocks. Caches are memory bounded; a network-fetched replacement refreshes an expired block rather than retaining a permanently expired entry. Metadata, numeric body bytes, retries, requests and cache reuse are available by provider host; job scope/instrument/elapsed/actual bytes and retained reuse remain available in activity/diagnostics.

Preflight uses bounded 0.04° regions, including route/scan points and polygon edges/intersections. Steady fast observed motion can retain a 0.04° native optical crop; slow/stationary/turning conditions keep smaller work. A scene-edge miss falls back to the requested region. Native optical resolution is preserved. USGS regional exports increase their grid dimensions to preserve the reference geographic sampling density; the service's unspecified native composite resolution/datum remain unspecified. No whole satellite scene is downloaded by default.

[Regional benchmark status](research/v0.3.2-regional-benchmark-status.json) records genuine early v0.3.1 baseline runs. At the tested Sentinel area, 0.02° and 0.04° each transferred **13,988,984 bytes**, with 239,498 vs 927,504 bytes retained. Landsat's 0.02°/0.04° cases also shared much of the native-block transfer cost; 0.06° was not universally valid. These observations support bounded regional testing, not a universal larger-is-better claim. The corrected harness records failures and separate first/repeat/adjacent durations.

[Eleven retained-data trajectory replays](research/v0.3.2-trace-benchmarks.json) cover stationary/slow/moderate/fast flight, turns, route diversion, lawnmower/repeated passes, orbit/racetrack and repeat flight. Both versions produced **521 successful sample acquisitions**, with actual masked/unavailable intervals preserved and zero HTTP requests in this deliberately offline experiment. The illustrative runs took **5.334 s baseline / 4.829 s development**. They are not statistical performance guarantees or an online-transfer benchmark.

## Operator experience and limits

Download Activity has Active/Queued/Completed/Failed filters, instrument/provider/session selection, stages, actual bytes and measured average rate. Unknown total sizes/ETAs stay unknown. Rows retain expansion and selection during updates; normal pages show compact summaries. Pause/resume/cancel semantics are explicit.

Collections group compatible original provider/product/scene/date/calibration/resolution identities; USGS composite regions are labeled as a collection, not one simultaneous observation. Individual regions preserve IDs, dates, validation, selection and actual georeferenced boundaries. Pages render at most twenty regions. Coverage outlines are not guarantees of valid pixels. Originals are not automatically deleted or treated as disposable caches.

The genuine native toolbar retains SDK templates and CommBus. Saved plans are on Mission and queried automatically. Active recordings use immutable snapshots. The map keeps every route/export point, reduces labels based on screen spacing, prioritizes selected/next points, reports true bearing/ground track and offers waypoint controls. Selecting a plan does not command an aircraft/autopilot. Browser fixtures do not verify native dragging/resizing or VR.

New polygon fits intersect actual scan tracks with a validated local ring, refine navigation geodesic intersections and mark connectors separately. Concave multiple intersections are supported. Connectors can leave the boundary; turning radius/terrain/sensor swath are not promised. Limits: one simple ring, at most 1,000 vertices/route points, 100 tracks, local extent within 100 km, no polar/dateline fit. Legacy envelope fitting is explicit and old saved definitions retain their original behavior. Route exports/true headings/aviation units remain.

Mission results expose atmospheric values and each remote instrument's acquisitions, source/flight times, diagnostics, valid positions and footprints. Previous/Next controls reflect actual counts and reset on selection. Large maps load bounded pages and stop offering more at the 60,000-position threshold (the last page can extend it); full stored exports remain accessible. Old products without indexed valid counts show Unknown. No stitched composite, invented continuous coverage or interpolation is introduced.

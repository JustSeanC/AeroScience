## First-time installed-user checklist

Record the exact source commit, setup SHA-256, Windows/MSFS/SDK versions, aircraft, duration and source/date policy. Mark each result passed/failed/untested honestly. Leave the relevant GitHub issue open while required manual checks are untested or failed.

1. **Installation/upgrade/offline archive:** Install the actual v0.3.2 Setup over the previous release. Verify storage locations, 800 MiB custom preferences, Universal/Realistic modes, old plans, existing sources, products, offline history and exports. New installations should retain a 256 MiB/hour flight default and independent preflight policy. Check uninstall/reinstall preservation and toolbar Keep/Remove choices.
2. **Extended recording (#9):** Record for at least the duration of the earlier interruption (the reported history retained about 748 samples), preferably 30–60 minutes. Run scientific preparation, all supported enabled instruments and Storage status/refresh concurrently. Reopen history and verify sample timestamps/counts, gaps and products. There must be no false missing-WAL interruption. Do not delete/alter a real archive or manufacture sidecars as a test. Genuine disk/quota/permission tests need a separate disposable test data location.
3. **Known-good science (#5):** Choose genuine prepared coverage with a clear historical date/quality policy. Check Preparing data → Ready or accurate Outside coverage/No valid pixels/Processing delayed/Error. Confirm actual files/products, units, masks and source dates through View Data/export. Test 1 Hz concurrent instruments; record actual success/missing counts and processing latency. Results must appear automatically without page reload. Provider failure must not stop telemetry or backfill earlier science gaps.
4. **Separate allowances (#1/#12/#13):** Prepare a mission before opening MSFS. Check preflight bytes/reservations against its own allowance; flight usage must remain unchanged. Review combined actual usage. Exercise finite and explicit Unlimited options independently, one/two concurrent jobs, cancel/retry, settings changes and temporarily exhausted volume. Reproduce the approximate 426.3/800 MiB scenario: with no active reservation and remaining volume, stale reserved/exhausted states must recover. Per-download, provider, privacy and storage protections remain active under Unlimited.
5. **Preflight experience (#13):** Save a plan and confirm that saving alone does not download. Select Prepare Scientific Data; review instruments, route/survey/retained candidates, free space, limits and unknown size where appropriate. Cancel leaves sessions/data unchanged. Start, Pause, Resume and Cancel behave as labeled. Repeating coverage should reuse retained originals. Start recording with unfinished preflight: urgent actual-flight work takes priority; speculative preparation stays paused until explicitly resumed.
6. **Motion/reuse/efficiency (#11):** Fly without a plan, then divert from one. Test stationary/slow, moderate, 400–450 kt, turns, lawnmower/repeated passes, orbit/racetrack and a repeat flight. Disabled instruments should not initiate requests. Observe which actual original source/region satisfies each area. Collect before/after bytes, retained bytes, request counts, cache/source reuse, time to readiness, usable/missing intervals and actual geographic coverage. Larger regions must earn their use; report provider boundaries, masks and failed requests rather than hiding them.
7. **Download Activity (#3):** Open it from Planner, Control, Science and Settings. Inspect Active/Queued/Completed/Failed and provider/instrument/session filters. Verify real stage/actual byte/rate updates, unknown totals/ETAs, allowance figures and scoped controls. Expanded entries, filters, scroll and selected views must stay stable on desktop and a physical paired iPad. Confirm normal pages remain compact and responsive.
8. **Collections (#10):** Review a real library containing at least 32 regions. Expand a collection, paginate, compare individual dates/calibration/IDs and view all actual footprints. Coverage polygons must remain separate with gaps visible. Highlight/exclude an individual source without deleting it or affecting completed products. Check large-library performance and native DPI layouts.
9. **Toolbar mission flow (#4):** The genuine SDK-built Community package must populate plans on Mission without visiting Map. Test Unplanned, saved summary, Refresh, paging, View Route and Start Recording. Close/reopen/reconnect the panel. An active mission must retain its own immutable plan snapshot; selecting a plan must not command the aircraft/FMS.
10. **Native moving map (#6):** Use small/medium/large native windows, at least a 22-point survey and a 73-point orbit. Verify aircraft/ground track, selected/next waypoint, true bearing/NM range, label density, pan/follow/zoom/fit, recorded trail, survey boundaries and export geometry. Check real dragging/resizing, glyphs and Quest 3 VR separately; browser fixtures prove none of those native interactions.
11. **Polygon fit (#2):** Draw a rotated irregular/concave polygon, set heading and 0.25 NM spacing, then Fit. Green scientific scan legs should stay inside; dashed transitions may leave it. Inspect multiple concave intersections, edit/regenerate/add/save/reopen/export and unit switches. Try explicit rectangular envelope overscan. Old saved patterns must not change automatically. Aircraft turning feasibility and calibrated sensor coverage are not promised.
12. **Results (#8):** From Mission History select a mission and Scientific Results, then an instrument. Check successful/valid/unavailable counts, flight vs source dates, atmospheric values, map footprints/valid positions, detail views and exports. Previous/More controls must stop at real bounds and reset on selection. Large maps disclose their page/memory bound. Masked gaps must not become continuous imagery.
13. **Offline/recovery:** Restart without MSFS/internet and inspect archives and valid retained sources. Source modes and consent should persist. Exercise a missing external scientific drive in a disposable test configuration: clear errors, no empty replacement archive. Test privacy cancellation and cancellation of data/import/setup dialogs without unintended writes.
14. **Feedback:** Use Collect Feedback or Download Activity → Export Scientific Diagnostics. Review local JSON/ZIP for geographic privacy before sharing. Include exact steps, time, issue number, source commit, build hash and relevant logs/screenshots. No raw scientific files, databases, credentials or private authorization correspondence should be shared by default.

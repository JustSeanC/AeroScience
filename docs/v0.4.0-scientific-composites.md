# v0.4.0 scientific composites and exports

Mission History → Imagery offers two deliberately different products:

- **Mission Sample Composite:** only finite QA-filtered values actually saved in that mission, placed at their native source pixel indices. Unobserved pixels remain NaN nodata. Sparse saved samples do not become a full airborne image.
- **Retained Source Mosaic:** verified historical source numeric values within the requested mission-footprint bounds. These are retained external observations, including pixels not collected by the aircraft workflow.

Views include natural-color RGB (red/green/blue), false color (NIR/red/green), NDVI, surface temperature K/°C, elevation and available actual hyperspectral channels. Source masks, scales/offsets, bad bands, units and original dates remain authoritative. NDVI is not a universal vegetation-health conclusion. RGB is a view of numeric reflectance bands, not a substitute for them.

Compatible retained regional windows can be combined without downloading a full scene. Compatibility requires matching provider, kind, scene, original date, publication, datum, license/citation, band calibration/catalog metadata and integer-aligned native lattices. Unknown manual scene/date records are not automatically combined. Different scenes, times, units and datums require separate outputs. Overlaps select first/last actual acquisition by packet UTC then stable ID, or first/last valid retained region by stable source ID. No averaging or temporal blending is hidden.

Numeric GeoTIFFs retain the exact native grid, EPSG CRS, affine/rotated transform, Float64 values, units and NaN nodata. No scientific resampling or invented resolution is introduced. Original physical sensor resolution can be coarser than its delivered product grid (for example Landsat TIRS). Geographic previews use a bounded nearest-pixel display-only WGS84 warp and labeled stretch/palette; they do not modify the downloadable numeric raster. Date-line-crossing raster previews currently require a smaller region; numeric exports remain available.

Processing is one bounded background worker with a four-item queue, progress and cancellation. Operations support up to 32 compatible retained regions, 20,000 acquisitions and 16 million native cells, written as 512×512 tiles. Mission samples use a capacity-reserved disposable SQLite working index with a 16 MiB page cache and bounded tile reads, not a whole-mission pixel dictionary. Its temporary durability settings do not change persistent archive transactions. Originals are rehashed before retained mosaicking. Source hashes, acquisition hashes, effective profile snapshots, algorithm version and processing-assembly hashes identify results. A verified completion index enables reuse only for a fully completed matching operation. Cancellation can retain individually complete identified tiles; it never claims a complete operation.

Outputs publish through existing staged, hashed atomic library operations and storage reservations. Completed derived products and reproducibility sources are protected research, not automatically disposable caches. Migration/deletion stops analysis first. Scientific deletion includes owned artifacts but preserves original source collections and unrelated/migration/recovery backups. Failed/unindexed work retains ownership/accounting recovery records.

The Research Package ZIP includes full mission JSON, flight/science/events CSV, GPX/KML, summary, independent environment times, notes/markers, actual acquisition products, source references/hashes, effective profiles, coverage GeoJSON/methods and completed numeric rasters/metadata. Its manifest hashes uncompressed members. Source originals remain in the Science Library and are referenced rather than duplicated; keep them for reproduction. Exports do not download or upload data or create post-flight observations. ZIP output streams with bounded memory, including on HTTP servers that forbid synchronous response I/O.

Production has no external Python/GDAL dependency. Developer-only rasterio/GDAL comparisons independently validate genuine data. [Acceptance reports](v0.4.0-completion.md) explicitly distinguish those checks from installed Windows/MSFS tests.

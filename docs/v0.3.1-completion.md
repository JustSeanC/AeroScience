# v0.3.1 implementation and validation report

Target: **Predictive Science & Guided Dataset Import**. This source change does not alter the published v0.3.0 release/tag/installer. Windows/MSFS and uncoached first-time-user acceptance are separate and outstanding until performed on the installed v0.3.1 candidate.

## Predictive algorithm

A background worker observes fresh positions every two seconds. Geographic displacement/ground track wins over heading and optional route intent. After startup/reconnect a second fresh position is required. Paused/stale/duplicate packets, gaps over 15 seconds, aircraft changes and implausible position jumps suspend/reset prediction. Stationary aircraft do not create a fast forward corridor from a misleading speed field.

The default horizon is `clamp(1.75 × measured preparation seconds × external instrument count / concurrency + 30, 90, 600)` seconds, also bounded to 120 km of projected travel. The estimate begins at 45 seconds and uses an exponential moving average of actual preparations (5–300 second estimate). Advanced lookahead supports 0=automatic or up to 900 seconds, retaining the distance and workload bounds.

At the initial 45-second estimate with one instrument/concurrent preparation, the horizon is **108.75 s**: about **2.72 NM at 90 kt**, **12.08 NM at 400 kt**, or **13.59 NM at 450 kt**. With three instruments it is **266.25 s**: **6.66 / 29.58 / 33.28 NM** respectively, subject to footprint/workload limits. Slow/stationary flight shrinks spatial reach; high latency expands time lookahead. These are prediction targets, not guaranteed ready coverage.

The predictor integrates a filtered, bounded observed turn rate rather than extending a momentary tangent indefinitely. Nearby turn uncertainty and the existing attitude/AGL/FOV plane footprint expand the requested cells. A saved route extends lookahead only when a nearby forward segment agrees within 25° and the aircraft is not in a substantial turn. Routes remain optional and subordinate to motion. Repeated survey passes reuse retained sources. No LNAV/autopilot/aircraft whitelist is used.

Each update holds at most 128 distinct 0.02° areas, with bounded footprint checks and geodesic integration. The 64-job queue prioritizes arrival-minus-preparation time; urgent flight jobs bypass distant preflight work and can replace lower-priority unsent jobs. When every worker is occupied, an irrelevant active preflight job can yield at most once per 30 seconds; partial staging remains retained and accounted, and the progressive session may retry it. Normal flight downloads are not repeatedly cancelled for minor heading changes. Jobs are deduplicated. Course changes remove irrelevant unsent work without deleting sources or repeatedly cancelling useful active downloads. Preflight advances windows of up to 24 instrument jobs beyond eight cells; each session bounds geometry checks and 4096 distinct areas instead of requesting a country-sized bbox. Limits and approximate pending workload are disclosed.

Network controls retain separate science consent, background/unmetered choices, per-download caps, 1–2 concurrent jobs, HTTP pacing, bounded retries and Retry-After. Default overall transfer allowance is 256 MiB per rolling application hour; reservations prevent concurrent jobs from claiming the same remaining allowance. Library/mission defaults remain 50/25 GB, with explicit Unlimited and protection settings preserved. Original sources/products/observations are never silently deleted for space.

Readiness in Planner/Control/Science and the shared map distinguishes ready, preparing, queued, partial and unavailable regions. It shows actual source quality/age, activity, transfer limits and conservative ready-ahead time, with an outrun warning. Local source coverage remains distinct from the requested cell. Per-pixel masks still apply. Missing acquisitions retain a reason and gap diagnostic; flight recording/other instruments continue and later data never backfill earlier flight packets.

## Guided imports and scientific source settings

One import session feeds the existing verified source library. Native Windows file/folder pickers choose the source; HTTP callers cannot provide arbitrary filesystem paths. Compatible DEM GeoTIFF, Landsat ST_B10/QA collections, Sentinel B02/B03/B04/B08/SCL collections and ENVI cubes receive generated manifests. Required missing unit/datum/scale/scene information is requested explicitly. Original metadata files, wavelengths, scale/offset, bad-band flags, hashes and external originals are retained. Cancellation/space errors never advertise partial sources. Exact duplicate imports reuse verified files.

The four-step hyperspectral workflow is Choose → Verify → Confirm/Import → Dataset Ready. It supports 16–512 original channels, supported numeric types/endian orders, BSQ/BIL/BIP, WGS84 geographic/UTM and explicitly declared rotations under 90°. It preserves actual channel indices through wavelength-sorted display order and never converts radiance to reflectance or invents calibration/time/coverage. NetCDF/HDF/JP2/MAT, unsupported CRSs and broad conversion remain unsupported. Existing legacy ENVI records keep their previous coordinate convention; only newly guided imports opt into the GDAL-compatible corner/affine convention. Historical products are unchanged.

Hyperspectral is local-only and works without scientific network consent. Dataset Required/Outside Coverage/Invalid are expected actionable conditions; imported availability and actual acquisition conditions are separate. Optional NASA metadata discovery does not start protected downloads or require an account. Missing hyperspectral data do not block automatic instruments.

Native Settings has four readable source sections; browser Settings has eight secondary categories and precise links. Both share persistent per-instrument source modes, catalog/status and active selection. Exclusion retains files. The planner has Aviation/Metric only, with customized scientific display units preserved separately. Category navigation retains unsaved DOM fields and supports Back/Forward/mobile use.

## P0 pattern regression

Verified code defects included validation of dimensions irrelevant to the selected pattern, a new asynchronous preview on every Add, and duplicate input/blur scheduling. The latter could change report/layout while clicking Add after a heading edit, so the button moved during the click. An actual browser survey-fit/heading/Add test reproduced the failure before event deduplication and passed afterwards.

Validation now targets applicable controls and selected units, preserves an outdated valid preview on invalid input, and ignores stale responses. Matching validated previews commit directly; changed inputs require a fresh matching result. The Add guard prevents duplicate IDs/geometry, retains manual waypoints and gives an explicit save-draft confirmation. All eight types have real editor preview/add/save/reopen coverage, plus existing map-center, survey-fit, delayed-response, export and unit round-trip tests. WGS84/GeographicLib geometry and v0.3.0 saved-plan compatibility remain.

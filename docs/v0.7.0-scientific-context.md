# Scientific context, map layers and research interpretation

## Reading your research

Choose an experiment in **My Research**. Its **Research question** explains what you are investigating. Open **Measurement Strategy & Scientific Limits** for variables, collection method, sampling requirements, expected output and evidence limitations. The same explanation follows the versioned card into **Mission Planner**, **Mission Operations**, recorded results and original-evidence inspection. Editing a plan or card does not change a completed flight's frozen requirements.

| Source label | Meaning |
|---|---|
| Simulator-Reported Observation | A value from the supported simulator interface, at the recorded aircraft time/location. Demo and synthetic fixtures remain explicitly identified. |
| Historical Scientific Dataset | External source values at their original observation date. Sampling them during a flight does not acquire a new satellite image. |
| Modeled Scientific Output | A documented calculation from supported inputs, not a measurement from physical hardware. |
| Pilot Observation | A pilot's written description with original time and available recorded position, not a numerical sensor reading or proof of a hypothesis. |
| Unavailable / Unsupported | The required supported source or provenance is unavailable. No missing value is substituted. |

## Understanding a map layer

1. Open a recorded flight in **Science Map**.
2. Choose an instrument and measurement in **Science layers**.
3. Open **About This Layer** for loaded source/quantity details. The same action is in **Overlays & Legend**.
4. Use **Browse recorded science** to inspect an acquisition or reading. **Inspect Original Observation** opens that exact original record in Mission Operations' synchronized timeline.

Accessible tables expose the same original values. Source observation, local import, product processing and flight sampling/receipt dates are separate fields. An absent observation date says **Not supplied by source**; publication/import time is never substituted. Coordinate system, native spacing, datum, missing-value markers, citation, license and limitations come from retained metadata. Coordinate-grid spacing is not sensor accuracy; absent uncertainty is not estimated from the value range.

At most eight loaded source/quantity groups appear together; the paged archive browser can inspect every acquisition. For flights with several cards, **Research objective for layer suitability** selects the frozen requirement to explain. Matching a variable alone does not establish readiness: QA, datum, source age, geographic support, actual samples and evaluator requirements still apply. **External Data Manager**, original source inspection and existing preparation/readiness remain authoritative for availability and consent-controlled preparation.

The basemap supplies geographic context. Flight tracks show aircraft positions. Planning shapes and acquisition footprints describe intended or modeled geometry. Recorded points remain points. Native cells show saved QA-valid sample support; displaying a cell does not prove its entire area was sensed. Source extents do not establish QA-valid pixels. No new sensor swath or area percentage is inferred.

## Three supported examples

- **Vertical Atmospheric Profile:** original simulator air temperature versus recorded feet MSL. Valid samples, consecutive-reading requirements, missing bands and gaps determine collection completeness. Unsampled altitudes and Earth's real atmosphere are not inferred.
- **Terrain & Temperature Survey:** DEM elevation retains its datum; historical Landsat surface temperature retains acquisition date, Kelvin source units and QA. Simulator air temperature is separate. The terrain scanner does not produce actual LiDAR returns. Each selected objective qualifies independently.
- **Experimental Sensor Checkout:** original air-temperature inputs and fictional model-derived response remain separate series. The frozen definition explains response time, gain, offset, input range, sampling and gap resets. A model result does not validate a physical detector.

Comparisons retain epochs, variables, units, datums, source category, configuration and card revision. Differences are explained even when a layer has no valid cells. Existing engines still decide quantitative compatibility and common support; a shared display scale does not establish simultaneity, causation or scientific equivalence.

## Local storage and availability

These displays use existing bounded source/product/card metadata. They do not contact scientific providers, decode full rasters on each refresh, create an archive or authorize uploads. Source inspection still verifies originals and reads only the requested bounded window. Changing the window clears results. Deleted originals cannot be recreated by context helpers; independent recorded samples follow established ownership/deletion rules. Existing unsupported P17/P18 complete-product transport remains unsupported.

## Scientific boundaries

Simulator observations, historical datasets, modeled outputs and pilot documentation have different meanings. Missing metadata stays unavailable. An import date is never an acquisition date. Points remain points; a flight route or modeled footprint cannot establish valid-pixel coverage. Local collection/evaluation, organization receipt and reviewer approval remain distinct.

P17/P18's unsupported complete raster/QA and modeled-response products remain unsupported. Authentic owner-authorized NASA/EMIT originals, installed MSFS/SDK, physical devices and production hosting remain separate acceptance gates. P23 does not change raw storage, deletion, source hashes, scientific tolerances, privacy scopes or evaluator semantics.

Implementation and exact validation results will be recorded here and in the development tracker after verification.

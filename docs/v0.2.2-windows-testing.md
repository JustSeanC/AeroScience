# AeroScience v0.2.2 — Windows build and actual acceptance

This is the maintainer workflow. Testers install `AeroScience-Setup-v0.2.2.exe` and launch from Start. No terminal is required for ordinary operation. This Linux cloud cannot execute MSFS, Windows installer UI or DPAPI; do not reuse v0.2.1 acceptance for the changed EXE.

## Build

Start the **x64 Native Tools Command Prompt for Visual Studio**, then enter `pwsh` to switch to PowerShell while retaining compiler tools. `Set-Location` is a PowerShell command.

```powershell
Set-Location 'C:\Dev\AeroScience-release'
git status --short
git pull --ff-only origin main
git log -1 --oneline
pwsh -NoProfile -ExecutionPolicy RemoteSigned -File .\scripts\release\Build-ReleaseCandidate.ps1 -SdkRoot 'C:\MSFS 2024 SDK' -RuntimeApprovalRecord 'C:\AeroScience-Release-Records\runtime-approval.json' -RuntimeRedistributionConfirmed -InnoCompiler 'C:\Program Files (x86)\Inno Setup 6\ISCC.exe' -OutputDirectory 'C:\AeroScience-Builds\Geographic022-1'
```

Require a clean source checkout, .NET 10.0.402, Node 22+, Python, your actual MSFS SDK, compiler and Inno 6.3+ (6.7.3 supported). Keep the existing private authorization correspondence private; reuse the reviewed runtime attestation only for the exact licensed DLL hash/conditions. The build keeps official SDK ABI/packaging, signed VC++ prerequisite, bundled-asset hashes, runtime checks and release provenance. No self-hosted runner is needed.

Run `C:\AeroScience-Builds\Geographic022-1\installer-candidate\AeroScience-Setup-v0.2.2.exe`. The candidate ZIP is an internal/optional portable payload. Retain this exact installer throughout testing; finalization does not rebuild it.

## Required actual tests

Use disposable copies for deletion/migration/failure testing. Record your actual results; screenshots or long logs are optional, but identify which candidate you tested and any limitation.

1. Upgrade the installed v0.2.1 application. Verify both configured storage paths, mission modes, history, saved plans, presets, science rows, settings and old backups survive. No mission DB schema migration is required by v0.2.2. Test Start/shortcuts, dashboard auto-open, offline history/export, prerequisite loading, clean-user installation, uninstall/reinstall and toolbar Keep/Remove choices.
2. Settings → Maps & Basemaps: verify fresh offline default/no external requests, independently configured public Esri key encrypted in the stable configuration folder, saving/restarting, Streets, satellite and labels at a known location, required attribution/logo and account restrictions. Actual key/imagery acceptance needs your own account; do not share keys in feedback. Disconnect internet, use an invalid key or a restricted test quota, and confirm honest fallback without route loss or recording interruption. Disable online maps and confirm tile activity stops.
3. In Planner, create/edit/save patterns, polygons and manual points across the dateline/high latitude. Change basemaps without losing geometry/view. Export/share preview must show count, distance, airports, patterns and warnings. Test DD/DDM/DMS, ICAO-minute and documented SimBrief-second routes. Published-fix mode requires explicit identifiers. Clipboard must copy the complete preview only after a click. No external plan is submitted.
4. **Import PLN into the real MSFS 2024 EFB**: airport-to-airport, local/no-airport, multiple custom fixes, lawnmower, expanding square, closed orbit/return, negative/positive/unspecified target altitudes, and a long route. Check actual count/order/geographic positions/altitudes. Enter required cruising altitude; missing per-waypoint altitudes must stay unspecified. Document EFB/FMS limits; do not call XML parsing successful simulator import. If an import fails, retain the file and report it before release acceptance.
5. Compare planned GPX/KML/CSV with the original plan, including pattern association, precise coordinates, optional altitudes, survey polygons and XML/CSV special characters. Planned exports have no invented future timestamps. Historical Recorded Flight exports remain distinct; editing a saved plan must not rewrite a recording's immutable snapshot.
6. Install the genuine SDK-built 0.2.2 toolbar via the existing update prompt/progress flow with MSFS closed. Begin with an older toolbar; exercise Remind Later, Settings repair, rollback on disposable failures, and unrelated add-on preservation. After starting MSFS, test native header drag, every edge/corner resize, scroll, minimize/close/pop-out and keyboard focus. No Compact VR mode or turquoise content border should appear.
7. Toolbar → Map: load a saved plan when idle, switch to Mission and start it; verify its science mode, instruments and immutable route are retained. Also record a planned mission from the dashboard. The active mission must use its immutable snapshot. Verify all generated route vertices, numbered waypoints, areas, selected waypoint information, approximate range/bearing, live aircraft/heading and bounded actual track. Test Follow Aircraft, Free Pan, Fit Mission and zoom. Test a 1,000-point route; static geometry should transfer only on revision/reconnect and live packets stay bounded. Switch missions, aircraft, disconnect/reconnect, close/reopen and verify stale position removal. The toolbar stays entirely offline and sends no aircraft-control writes. Native Coherent behavior is not established by browser mocks.
8. Verify shared map layer preferences/colors across Planner, Control, History, Analysis and Science Collection. Mission Control retains View Science and a compact active-route summary/View Mission Map. Check narrow/wide sizes, 125%/150% desktop zoom and physical iPad Safari.
9. Data Management: open a fresh dialog after restart and v0.2.1 upgrade. Each independent section defaults to **Permanently delete without creating a new backup**. Confirm source path, mission/dataset/observation counts, approximate DB size, removes/preserves scope and exact phrase. Wrong phrases, active recording and cancellation leave data unchanged. No-backup must open **no folder picker or Explorer** and the final warning must say deletion may be irreversible. Explicit backup mode must open a clearly labeled recovery destination picker outside both data stores and installation; cancelling it must cancel deletion. Confirm final Yes/No cancellation, verified backup failures, transactional behavior and previously created/migration backups, settings, saved plans (unless opted in), presets and unrelated files retained. Flight and science clearing remain independent.
10. Retest live science, separate science pause/resume, real Mach/atmospheric fields, sampling gaps, recording recovery, offline research exports and dual-storage availability/migration using the existing tests. Measure Quest 3 FPS/frame time/stuttering/CPU/memory with app stopped, app running/panel closed, Mission/Payload open and Map open. Do not infer hardware performance from browser fixtures.

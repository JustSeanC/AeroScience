## Pilot workflow

1. Select your saved mission as usual, then open **Mission Operations** and use **Start mission**. You can also open it during a flight already recording.
2. Use **Activate Card** for the cards you want to monitor. **Focus Card** makes one question prominent without changing any other active card. Conflicting cards explain which one you must deactivate first.
3. Use the existing science-session buttons, **Begin Attempt** / **End Attempt**, optional **Enable Automatic Detection**, or **Record a Pilot Observation**. Recording, science collection and card monitoring remain independent.
4. After **End mission**, Operations opens the recorded flight. Select a point on **Synchronized Evidence Timeline** or use **Accessible Timeline Table → Inspect Original Evidence**. **Event category**, **Research card**, **Science session**, **Timeline instrument** and UTC filters narrow the original records.
5. Select a scientific reading to see its original value, units, quality, provenance and supported location on the same map. Select an attempt to inspect its frozen card, original interval, saved outcome and paged original samples. Use the existing results/replay links for further analysis.

**Load Recorded Flights** and **Older Recorded Flights** page through retained flights. Mission History also links to **Mission Operations**. The compact instrument table keeps current operating/source status and recorded-row counts visible. **Instrument Health & Scientific Source Details** expands the original calibration/quality/provenance cards; the map sits beside research controls on a wide display. The original Mission Control and Instruments & Collection views remain available; the operations view moves their existing control components and map instead of creating competing controllers.

## Shared state and evidence contract

`MissionIntelligence` now includes the existing `ResearchFlightState`. One visible live read feeds session controls, sensor operating/source status, card controls and Operations. The recorder remains at its existing cadence; no extra science evaluation, raster load or organization request occurs on each telemetry update. Failed/stale reads disable controls until fresh synchronization. Commands retain their original expected flight/session/attempt/control revisions and durable request IDs. A late response for another recording flight is ignored.

The timeline is a **version 1 read projection**, not a replacement history. Sources are original mission events, typed collection events, recorded telemetry, original scientific observation rows, pilot markers and research notes. It adds query indexes to the existing mission database without changing schema version 13 or rewriting original rows. The normal ingress-only controller checkpoints are available through exact acquisition references rather than flooding the science-session lane once per sample.

- Default timeline pages contain 50 records, maximum 100. Keyset cursors bind flight, UTC interval, category and exact-identity filters; ties use stable source/primary-key order in either direction. Variable-width JSON UTC fractions normalize to the same seven-digit UTC representation for indexed comparisons without floating-point timestamp rounding.
- Original details are limited to 256 KiB per record. Oversized originals explicitly require existing archive/export tools; they are not silently truncated into verified evidence. List summaries are bounded. Original text is rendered as text, never executable HTML.
- Attempt selection resolves its **original begin/end event IDs**, frozen card/point and saved evaluation reference. Telemetry comes from that exact interval, 50 samples per page. Up to 50 scientific rows from the interval are labeled contextual, not an invented causal card/measurement join.
- Scientific selection resolves the **original observation primary key/content hash**. Where recorded, its exact intent, configuration, input receipt, collection epoch, session and publication hash must agree. A changed/missing publication fails closed. Legacy observations without acquisition references are explicitly limited to the retained original row; no session is invented.
- A chart window contains at most 50 same-dataset, quantity, unit, source, provenance and calibration-definition readings within 15 seconds. Only published-valid finite values are drawn. These are separate points, not interpolated lines. Selecting a point or its table row verifies that exact original. Chart-context rows retain published QA; full acquisition verification applies to the selected reading.
- Nearby aircraft samples (three-second context) and last-controller-state-at-or-before-UTC are labeled **context**, never a nearest-time authoritative join. Card/session/instrument filters include only explicit original identity links.
- Atmospheric/transect readings, scalar survey samples and pilot notes/markers now enter the same timeline by their original IDs. A survey raster/product without a scalar observation ID is explicitly redirected to existing Scientific Results; no nearby scalar is substituted.

Scientific map points indicate recorded observations. Flight paths, planned geometry, derived footprints and original scientific point readings retain separate existing map layers. Invalid/missing values are not drawn as valid science. A bounded postflight track preview does not claim a complete sensor swath. No new area-coverage percentage, modeled measurement, interpolation, external-source download or scientific calculation is introduced.

## Lifecycle, privacy and deletion

Live Operations shows provisional progress. Recorded Operations reads the archived plan/cards, sessions and operating evidence once, then checks a small processing/deletion status every five seconds while visible. Timeline refresh is limited to the current recent/first page; older pages and selected evidence are preserved. Requests are cancelled/invalidated on flight changes and navigation. Original controls/map return to their existing locations when leaving Operations. No hidden map, second scientific archive or duplicate event stream is created.

A deleted scientific original cannot be rebuilt from nearby telemetry. Deletion removes dependent scientific results through the existing contract; timeline selections/charts/map scientific highlights clear when deletion is observed. Separately retained raw flight evidence remains separate. Failed/interrupted attempts and original manual/automatic identities remain inspectable after restart.

Organization cards use the same local operations and frozen issued identity as personal cards. Local recording/evaluation is separate from organizational eligibility, submission and approval. No live organization traffic, position sharing, credential elevation or background submission is added. P17's explicit evidence-selection/approval workflow remains the sharing authority. Existing paired-browser authentication, host authorization and CSRF controls protect the new read endpoints and reused mutations.

## Native toolbar boundary

**Mission / Payload / Map / Research** keep one native application. A compact persistent research summary shows focus and bounded active-card names/count; the Research tab contains the existing card/point/attempt controls. Focus and selected point survive ordinary state refresh/tab navigation. Other active cards remain active. Full original evidence and the timeline stay on the dashboard.

Commands are measured in UTF-8 and limited to 1,024 bytes; research replies remain at most 8,000 UTF-8 bytes. At most three shortened display names are added; they can be omitted if packet space is needed. Original card/claim/point IDs, scientific requirements and numeric values are not shortened. Existing card/map pagination, CommBus, SDK bootstrap/window behavior and telemetry cadence remain. Browser wrappers and actual handler tests do not establish installed SDK/MSFS, touch or Quest acceptance.

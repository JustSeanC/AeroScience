# v0.4.0 archive and processing design

This design precedes changes to persistent formats. v0.3.2 archives and release evidence remain intact.

* Aircraft telemetry retains its 360-byte native definition. Optional ground and environment variables each have an independent one-FLOAT64 SimConnect request, rejection state and receipt timestamp. The existing 40-byte atmosphere and 248-byte guidance definitions stay intact. JSON telemetry receives nullable, additive environment and atmosphere fields. Old samples do not acquire invented values.
* Instrument configurations may contain a versioned effective payload snapshot. Catalog IDs identify a particular reference configuration, including its lens. Generic/custom configurations identify themselves as such. Snapshots carry geometry, capabilities, documentation and limitations; changing the catalog never changes a historical snapshot. Old acquisitions with no snapshot retain their original recorded mount and methodology.
* Provider, collection, retained source, data capability, modeled instrument and geographic acquisition remain different concepts. Capabilities describe actual retained numeric data. A hardware profile never establishes source availability or calibrates an unrelated historical satellite product. Existing raster manifests remain readable; point-cloud support must preserve original point records and reference information, rather than disguising them as DEM rasters.
* Replay reads recorded timestamps and bounded indexed pages. No interpolation creates science observations. Event, aircraft, source and processing times remain independently identifiable.
* Coverage distinguishes route adherence, geometric acquisition footprints and valid scientific support. Duplicate support cannot increase union coverage. Analysis settings, denominator, resolution, projection and error limits travel with results.
* Mission sample composites use only saved acquisitions. Retained source mosaics use explicitly selected verified sources. Incompatible quantities, dates, scenes, units and datums are separated. Outputs retain nodata and source resolution. No analysis triggers gap-filling downloads.
* Derived artifacts live in the existing independently movable Science Library. Publication uses capacity reservations, staging, hashing and atomic catalog publication. Originals are immutable. Additive catalog tables require a verified backup before the first schema extension, following the existing remote-products migration pattern. Stable library/source/dataset IDs and relative paths survive moves.
* Background analysis must remain outside the recorder gate, be bounded and cancellable, and coordinate with existing migration/deletion maintenance. Interrupted outputs are incomplete, never accepted products. Cache identities include algorithm version, input identities and effective settings.

Windows/MSFS acceptance, genuine-source acceptance and automated regression results are separate evidence. Compilation alone does not approve an instrument, provider, installer or release.

## Minimum writer versions

Mission schema 5 upgrades to 6 with the existing verified SQLite backup before the additive receipt-time indexes and version change. The scientific catalog upgrades from 1 to 2 after verified backup and additive artifact/index creation. No historical payload is rewritten. These version markers prevent an older companion from writing archives whose new snapshots/artifact ownership it does not understand. Backups preserve the original database for explicit rollback; an old binary must not be pointed at the upgraded writer database. Initial effective payload settings are recorded atomically with mission creation, while subsequent configuration changes remain timestamped events. Planning AGL, groundspeed, overlap and source references are optional canonical-unit plan fields, separate from MSL targets.

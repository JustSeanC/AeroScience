# v0.2.1 — Mission Planning & Science Experience

Source implementation and cloud verification are complete. **A v0.2.1 Windows installer has not been built or accepted here, and no v0.2.1 binary or release tag has been published.** The source is intended for the existing manual gaming-PC build and public GitHub prerelease process. Previous v0.1.1 user-reported hardware passes do not establish acceptance for these changes.

## 1. Implemented scope

The twelve requested areas are implemented: toolbar version/update UX; shared graphical progress; genuine offline geographic mapping; eight editable patterns; planned/recorded comparison; independent instrument presets; science-only pause/resume; Science navigation/Mission Control access; global science units; native Payload/browser Science redesign; readable typography/charts; and explicit optional-backup data clearing. Existing live SimConnect/Mach/guidance, recording, offline history, dual storage, migration/export and installer architecture are retained.

## 2. Toolbar detection and prompting

`ToolbarVersions` reads actual SDK `manifest.json` versions from the bundled package and selected/discovered Community installation. It reports **Missing, Current, UpdateAvailable, Unknown, Incompatible**. An unknown version is never assumed current; supplemental protocol metadata detects unsupported versions. A newer installed package is not automatically downgraded. Startup offers Install/Update or Remind Me Later for missing/outdated packages; session suppression prevents repeated interruption. Dedicated native **Settings → Toolbar** and browser Settings show installed/bundled versions, status/location and update/repair access.

## 3. Progress and update safety

The first-run wizard, startup prompt and Settings use the same asynchronous `ToolbarProgressForm`. Copy and final verification percentages use actual completed/total files; checking, backup, activation and version confirmation are indeterminate stages. No simulated progress timer is used. Source files must match a genuine full SDK receipt and companion version. Files are copied/hash-checked in staging outside Community; old files are backed up outside Community before activation. Final activated files are rehashed and their manifest version re-read before success. Fault injection verifies copy interruption and post-activation corruption retain/restore the prior package. Process/file leases prevent concurrent updates/removal; MSFS must be closed. Diagnostic logs live under the stable configuration `logs` directory. A process killed during staging may leave diagnostic staging outside Community; it does not erase the original package.

## 5. Offline map behavior

The map includes actual land/country boundaries/coastlines, country/city/airport reference labels and offline name/ICAO/IATA/coordinate search. Airports are not exhaustive and geography is intentionally coarse. No default external request, credential, account or subscription is needed. Optional OpenStreetMap detail sends the visible region/IP to that provider only after explicit disclosure/consent; attribution and normal browser caching apply, with no bulk download/prefetch/offline tile-cache feature. Pan/wheel/pinch/fit, aircraft/waypoint centering, draggable numbered waypoints and graphical polygon drawing/edit/delete are available. Unset coordinates differ from valid 0,0. Existing geometry and resolvable departure take precedence over live aircraft/regional fallback. Dateline coordinates remain WGS84; Mercator display is limited to ±85.0511° and is not a navigation chart.

## 6. Patterns and geometry checks

Lawnmower, creeping line, expanding square, racetrack, orbit/circle, box, radial spokes and straight transect use GeographicLib WGS84 direct/inverse geodesics. Parameters include geographic center, heading, length/width/spacing/radius, legs/orbits, direction, altitude and notes. Curves use 5-degree samples; reported route distance is the generated waypoint-path length. Preview is asynchronous; insertion uses its own completed result to avoid races with pending previews. Points remain editable/reorderable, carry pattern IDs and support regeneration/removal/geometry undo. Generation never writes simulator/autopilot state. Tests cover all eight deterministic patterns, actual lengths/spacing, dateline/high-latitude positions, orbit radii/direction/closure, validation and saved/manual edits. Local pattern extents are bounded to 500 km and total editable points to 1,000; create separate patterns for larger routes. No travel-time claim is made without a speed assumption.

## 7. Planned versus recorded analysis

Comparisons use the immutable recording plan, stored full telemetry and persistent tolerance/gap settings. Distances use WGS84 geodesics. Waypoints require observed points **in route order** within tolerance; closest proximity is separately reported and does not establish intention. Telemetry gaps and non-increasing timestamps are excluded from connected distance/traversal. Aggregate mean/maximum deviation uses every valid recorded position. Segment completion requires ordered endpoint visits at different times, intermediate observed points within tolerance and no telemetry gaps; it does not infer intention. Route deviation uses a local projected fraction evaluated on each geodesic segment; it is approximate for long/polar segments. Altitude error is compared against the reached waypoint's actual target. Survey path traversal integrates connected track in approximately 250 m subsegments; it is not instrument-area coverage. No arbitrary coverage percentage, pilot score or causal scientific interpretation is generated. Methods/limits, bounded deviation observations, raw overlays/exports and comparison JSON are exposed; complete original telemetry remains available.

## 8. Reusable presets

Presets have independent names, descriptions and supported instrument/interval configurations, with create/save-current/apply/edit/rename/duplicate/delete and recommended configurations. Science applies to current/spontaneous missions; Planner applies without changing route/aircraft/objective. Recorded actual configurations and plan snapshots remain independent after preset edits/deletion. Unknown future instrument IDs remain in stored presets and produce a warning/explicit partial-apply choice; unsupported instruments are never enabled. Individual advanced channel settings are not implemented for the current fixed instrument definitions. Presets survive archive clears unless future explicit preset management requests otherwise.

## 9. Science pause/resume

Shared coordinator commands and native CommBus controls pause scientific saving without ending or pausing flight telemetry. Current configuration and dataset identities are retained. Duplicate/simultaneous commands are idempotent. Host-UTC pause/resume/stop events and reconstructed pause intervals/durations appear in review and JSON; interrupted open intervals remain explicitly incomplete when the end is unknown. Resume resets cadence anchors so deliberate pause slots do not inflate unexpected missing intervals/average interval diagnostics. Source disconnect, simulator pause, unavailable readings, disabled instruments and intentional user pause remain distinct. Restarted/interrupted missions never silently resume.

## 10. Science units

Persistent preferences support C/F/K; inHg, hPa/mbar and kPa; kt/m/s/km/h; degrees true; kg/m³/slug/ft³; ft/m science altitude; and NM/km/mi distance. Aviation/Scientific presets and category overrides are graphical. Canonical SDK readings/source units remain unchanged in storage and default full exports; explicit chart display CSV names its converted units. Dashboard, toolbar readings, history summaries, chart axes/tooltips and analysis use the same conversion definitions. Tests check known numerical conversions, null/invalid handling, round trips and persistent settings. Unit changes do not modify the native ABI or calculate substitute science/Mach values.

## 12. Typography and scientific charts

The complete web UI uses 28–30 px page titles, 18–20 px sections, 15–16 px body/forms/buttons, 13–14 px secondary text and approximately 28–32 px important values. Containers, wrapping, touch targets and dialogs adapt with typography; desktop/narrow/iPad-size and 125%/150% layout-scale checks pass without full-page horizontal overflow. Browser layout tests do not establish Safari/OS zoom behavior on a physical iPad.

Science cards emphasize human names, measured values, selected units/state/interval and distinct acquisition sets versus measurement values (wind has two values per set). Detailed diagnostics collapse. Native Payload uses two flex columns or one narrow column, small On/Off controls, Pause/Resume and SDK-owned window controls; no Compact VR UI or container outline returns. Native bootstrap retains `/JS/dataStorage.js` and CommBus.

Local Chart.js plots provide readable numeric ticks/units/grids, exact UTC/value/altitude/quality tooltips, selected time ranges, expanded view, point toggles, PNG and explicit display-unit CSV. Profiles and time views show observation markers without smoothing or invented line interpolation; temporal gaps remain empty. Display reduction retains bucket extrema; canonical exports remain complete. Expanded views and selection preferences survive normal live refresh behavior.

## 13. Data clearing

The trusted native UI presents explicit **Permanently delete without creating a new backup** and **Create a recovery backup, then delete (recommended)** radio choices. No-backup invokes no folder picker; cancelling a requested backup cancels deletion rather than silently switching to no-backup. Deletion scope/path/counts and recovery destination are distinct. The backup dialog starts in Documents and validates a separate destination outside managed data/application roots. Existing typed phrases, cancel/active-recording guards, verified SQLite backup, maintenance leases, transactional deletion and unrelated-file protection remain. Flight/science clears are independent; plans are opt-in and presets retained. Row deletion can retain SQLite allocation; no automatic VACUUM or retention/deletion policy is introduced.

## 14. Persistence and compatibility

Mission schema **5** adds independent preset and analysis-setting tables. Existing schemas 1–4 receive a verified SQLite backup before upgrade; unknown newer schemas are rejected. Tests preserve exact legacy telemetry payloads, Realistic/Universal modes, Mach-null history, library IDs/references and scientific observations. Unit settings live separately under stable configuration, independent of data-directory migration. No raw telemetry/science rewrite or mandatory cloud service is introduced. Existing dual-storage migrations, unavailable-drive protection, single-instance leases and offline startup remain.

## 19. Known limits and next steps

Coarse world geography/non-exhaustive airport references are not detailed terrain, imagery or certified charts. Mercator has polar limits. Pattern curves are sampled and very large layouts bounded. Route deviation/polygon traversal are documented approximations; waypoint rules are intentionally conservative and cannot infer pilot intent between samples. Scientific area coverage needs a future validated footprint/acquisition model. Historical chart pages/display reductions are bounded; full raw exports are authoritative. Per-channel advanced configuration, calibration, remote sensors, replay execution, pilot scoring and cloud sync remain out of scope. Windows/device acceptance and sustained long-flight performance are the next work before public binary publication.

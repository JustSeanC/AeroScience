# Native toolbar JavaScript compatibility

The web dashboard and the simulator's Coherent UI have different JavaScript capabilities. Modern browser success alone cannot prove native syntax compatibility. Native sources remain maintainable shared JavaScript; the SDK staging pipeline compiles them to **ES2017**, then independently parses the emitted scripts before invoking the official package tool. No compiler or npm dependency is loaded by the installed toolbar.

Build-only tools are pinned by package.json/package-lock.json: Microsoft TypeScript **5.9.3** (Apache-2.0) and Acorn **8.15.0** (MIT). Install the locked build dependencies with the existing repository setup. The maintained Build-Toolbar script requires Node and fails closed on compilation/parsing errors. Source files and imported research definitions are never transpilation inputs from an ordinary pilot; only the repository-controlled copied SDK staging project is accepted.

Order: copy native project and map/geography → apply private profile/source namespace if selected → compile all staged native JS → independent ES2017 parse → genuine SDK compilation → exact SDK output hashes and native-javascript proof → private receipt. The proof covers every delivered JS asset, source and compiled hashes, target, actual compiler and parser versions. Private receipt validation refuses missing proof, additional scripts, changed output or traversal-shaped references. The original source tree cannot be an output target.

The SDK's Include.addScript does not establish a completion-callback contract. Register only when RegisterCommBusListener exists. Track connection through the SDK's connected/disconnected lifecycle callbacks; initialization must not depend on an unproven Node.isConnected implementation in the native host. A partial listener failure is cleaned up before retry; delayed callbacks from disconnected epochs cannot change current status. Loading failure is bounded and actionable. A small ES5 bootstrap reports application initialization failure, including syntax/load failure, without sending commands or claiming a connection. Matching source authorization, native request-size bounds, receipt correlation and the original SimConnect-only request/reply path remain mandatory.

Tests exercise the actual generated output, equivalent null/zero/false behavior, delayed helper availability, registration cleanup, source mismatch, raw-data/session protection and packaging. Public SDK typings and a reported-working simulator example inform this engineering, but only a genuine installed-MSFS retest can establish runtime/native input acceptance. No private candidate, public add-on, image or release is published by these checks.

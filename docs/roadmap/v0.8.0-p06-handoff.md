## Scientific evidence boundary

P06 adds a narrow negotiated format: version-2 documents may include explicitly selected version-1 **supporting metadata/hash references** for the existing modeled-corridor, terrain-elevation-index and historical-LiDAR-index products in eligible issued research contexts. Legacy version-1 serialization and response-codec compatibility remain tested. Unsupported peers prevent approval/delivery; no silent downgrade. Source policies, exact original/tile/manifest hashes, geometry/input/algorithm identities, source-owned deletion and original analysis leases remain required.

These references **do not include** source binaries, DEM/DSM cells, point records, numerical profiles or viewer caches. A received hash does not independently verify an unshared original. Historical source/project/date/CRS/vertical reference/classification declarations and limitations remain explicit; unknown values stay unknown. Historical LiDAR is never represented as aircraft-acquired data. References count zero original observations and grant no original acquisition/grade/card/campaign credit. Complete terrain/raster/model-product scientific approval remains unsupported. Original observations, modeled geometry, actual terrain products and historical points remain distinct throughout pilot/reviewer views.

## Security, live sharing and notifications

Actual supported roles are Administrator, Manager, Reviewer and Pilot; read-only desktop access is a grant, not a new role. Reviewer campaign grants, active membership, origin/identity/expiry, vault protection, scope, rate/quota and revision checks remain on the server. Unauthorized UI controls are not substituted for authorization. Cross-organization isolation and wrong-server/revoked/expired grants retain actual backend tests.

The original optional relay sends current permitted state only after a separate browser grant and explicit per-flight consent. Join/claim/record/science/submit never starts sharing. The UI exposes the actual server/grant/audience and confirmed consent expiry, source freshness, aircraft and source-time duration. Duration is not recording continuity or scientific collection. Position/detail expiration, stopped/revoked consent and restart behavior remain original; no persistent location history, shared track or replay is added. When a server is unreachable, local sending stops and the last shared position expires under the existing 30-second limit.

Discord remains OFF by default. Only the original separately opted-in flight events, independently approved research and accepted exceptions are supported. Recent administrator MFA/recovery confirmation, encrypted credentials, explicit external disclosures, pilot consent, exact destination revision, bounded projections, retries and uncertain-acknowledgment holds remain intact. Tests use a controlled HTTPS receiver; no real Discord delivery or public hosting is performed.

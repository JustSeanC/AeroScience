# P08b — Guided owner checklist window

The earlier installed-release checklist used a native Windows Forms grid. The new `scripts/release/Open-080Checklist.ps1` brings that layout to the private 0.8 validation record without changing the older release tool or rebuilding the tested companion/SDK toolbar. Run it from a separate current tools checkout and pass the **existing tested build's** source SHA and independently retained receipt hash, even when the checklist tool itself has a newer source commit.

The window shows every existing P08b check by a plain-language name, its instructions, a result dropdown and multiline notes. All unrecorded items start **Not Tested**. There is no blanket Passed action and no test ID typing. Passed changes need notes plus explicit personal-testing confirmation. Save writes changed checks only; close/reopen loads the most recent records for that exact source/instance/receipt. Unsaved changes prompt before closing. Native system controls, colors, fonts, keyboard navigation and accessible names are used; installed visual/high-contrast/screen-reader acceptance remains separate.

`checklist_080.py` adapts the existing `private_validation_080.verify` and `observation` functions, not the application or science controllers. Source, runtime, SDK, helper and receipt identities stay in the original version-1 append-only observation events. Existing records and reviewed evidence stay intact. Newer edits are detected by content revision; concurrent guided saves use an OS-released lock. All changed rows are validated before any event write. If a later I/O failure interrupts a save, previous events remain and reopening shows what actually saved.

The helper reads the sealed package and writes only its sibling `Results` directory. It starts no HTTP listener, makes no sharing/upload/download requests, sends no flight/science commands and neither starts nor stops MSFS or the companion. Original package files, receipt, source archives, organization permissions, existing release gates and four candidate-locale human-review status remain unchanged. The existing command-line recorder continues working; the older installer acceptance format is not accepted as a private 0.8 checklist.

For the owner's already-built attempt, the build parameters remain:

```powershell
$app = 'C:\AeroScience-Builds\Validation080-20261115-095408\AeroScience-0.8.0-Validation'
$sourceCommit = '876ecf594956b7a40c7df0d4968dac1ce69ac971'
$receiptHash = '52660521d3a3f04aa62eae266989a6c55467cdeafbec0fd66531fded42bf1447'
pwsh -NoProfile -File .\scripts\release\Open-080Checklist.ps1 `
    -ValidationFolder $app -ExpectedSourceCommit $sourceCommit `
    -ExpectedReceiptSha256 $receiptHash
```

Keep the tools checkout and PowerShell window available while using the form. MSFS and the existing test companion can remain running. Choose a result and write what happened for each check actually tried, confirm personal testing for Passed changes and click **Save my results**. Closing the checklist does not close the game or companion. Untested cases stay Not Tested; saving notes does not approve a release, qualified translation review or P08c.

Focused receipts and exact Windows control-smoke evidence are recorded in `p08b-review/checklist-window.json` at closure. Linux native-form execution is unavailable, so its one Windows control test is explicitly skipped locally and required in focused Windows CI. No browser capture or hidden control smoke is genuine installed MSFS acceptance. Full CI is not repeated for this standalone maintainer UI; the original exact-source milestone Full CI remains unchanged.

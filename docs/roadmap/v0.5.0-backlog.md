## DATA-01 — Scientific Data Library: Browse and Download by Geographic Area

**Owner request, 2026-10-19:** Users should be able to visit the Scientific Data Library, choose a real-world scientific source/product, view locally retained coverage alongside actually discoverable provider coverage, and **manually select geographic downloads** ranging from **one small bounded cell/source window** to several cells, a drawn region, a county/state-sized area or similarly large custom region. **Do not create a special 'Download United States' button.** Large selections are a deliberately queued, bounded workflow, not a single giant HTTP request.

### Current baseline

The v0.4.1 Library's `View Combined Geographic Coverage` shows **already retained** source geographic footprints, not provider availability and not a manual download planner. Existing providers are USGS 3DEP **bare-earth elevation**, Copernicus GLO-30 **surface elevation**, Landsat C2 L2 **thermal land-surface data** (Microsoft Planetary Computer) and Sentinel-2 L2A **multispectral**. Distinguish 3DEP from Landsat; `177 geographic regions` or `2.2 MiB` shown for retained crops is not a full-state or full-country product-size estimate. NASA hyperspectral access differs: catalog discovery alone is not automated authorized retrieval.

### Desired full-page workflow

1. **Library > collection > Browse & Download Data.** Display a sizable map and concise source/product controls, not a giant list of preparation attempts.
2. Distinguish overlays using legend and text: **Already downloaded locally**, **provider catalog coverage**, **selected for download**, **queued/in progress/failed**, **unavailable**, and **not searched**. Provider scene outlines do not guarantee QA-valid pixels; source availability does not imply an aircraft acquired it.
3. Choose **one small existing bounded source/request cell**, multiple cells, drawn box/polygon, current map viewport, or state/regional boundaries when sourced from authoritative geometry. Allow keyboard-accessible selection using numeric bounds/place search; don't force map drawing. A 'cell' is a geographic preparation/download work unit, **not a single native satellite pixel**.
4. Apply provider-appropriate **product, mission-use/measurement type, date range, bands/scene choice, cloud/quality policy and spatial resolution**; use truthful defaults. For Landsat/Sentinel, a state selection must not silently mean *all scenes from all dates*. Show original source dates separately.
5. Preview **exact selected area and expected work scope**: geographic regions/cells, known source scenes, locally reusable pieces, to-fetch pieces, coverage uncertainty, estimated bytes/time/space **only when supported by evidence**, and remaining library/transfer allowances. Display Unknown if unknown and warn/require explicit consent for expensive or large jobs. Allow trimming selection.
6. On explicit confirmation, queue **bounded, chunked, durable, pause/resume/cancel/retry** provider downloads, with stable progress at product/region level and Advanced tile detail. Honor rate limits/Retry-After, provider 429/503, reasonable concurrency and live-flight priority. Handle restart, offline operation, storage exhaustion and user cancellation without losing verified sources. No mandatory remote cloud account.
7. Reuse the **existing scientific acquisition/download service**, privacy/consent, network cost restrictions, bandwidth budgets, staged disk reservations, source hashes, native numeric values, QA/nodata, scientific licensing and source provenance. Do not build a second conflicting data pipeline. Do not silently expand user budgets or delete sources to free space.
8. Store results as validated **reusable Scientific Data Library sources** for later science missions, even without a current mission. Clearly distinguish downloading into Library from exporting a copy of saved originals; don't mislabel downloaded external historical imagery as a new in-flight sensor observation.

### Scope and feasibility

Small single-cell selections should be practical; state-sized or larger requests require source-specific assessment, scene/time selection, subdivision, bandwidth/storage estimation and upper workload caps. If very large requests are impossible under provider/library limits, explain the actual constraints and offer chunks. There is no unconditional 'download all USGS Landsat in one go' promise.

### Acceptance criteria

- Complete end-to-end genuine-source download of one selected cell; validate original georeference, CRS/vertical datum, dates, scale, QA, hash and offline reuse.
- Select multiple cells, custom polygon and a state/large region; review spatial subdivision, true local reuse, transfer/storage budget checks, user confirmation, queue/cancel/restart and honest progress.
- Verify no full-history Landsat/Sentinel download without explicit scene/date scope, no duplicate download of an exact retained source, and correct separation of downloaded source area and mission-sampled area.
- Validate throttling, quota/consent/privacy, metered/offline networks, unavailable coverage, disk failure, concurrent in-flight sampling and nonfabricated estimates.
- Real Windows and provider tests separate from synthetic map/browser fixtures.

**Roadmap relationship:** This DATA-01 proposal augments v0.5.0 without reassigning or replacing the original Advanced Instrument Calibration & Aircraft Operating Constraints milestone.

## DATA-02 — NASA Hyperspectral Download Assistant (v0.5.0 stages 1 and 2)

**Owner-approved scope (2026-10-19):** Build **Stage 1 + Stage 2** during v0.5.0. **Stage 3 (native EMIT NetCDF-4 download/import) is explicitly deferred to v0.6.0 or a later release**, depending on research/validation. Do not silently expand the v0.5.0 scope to include Stage 3. The original v0.5.0 **Advanced Instrument Calibration & Aircraft Operating Constraints** roadmap remains the version's primary focus; this is an additional feature of the map-based Scientific Data Library download experience (DATA-01).

### Existing foundation and scientific limits

- AeroScience already performs genuine **NASA CMR catalog discovery** for EMIT L2A reflectance, AVIRIS-Classic L2 Reflectance, and AVIRIS-NG L2 Reflectance. Catalog discovery does **not** currently initiate protected Earthdata downloads.
- The guided local hyperspectral importer already inspects **compatible ENVI `.hdr` + numeric binary** files, band wavelengths, bad-band flags, original radiometric units, geographic references, source dates/metadata, and imports validated original values to the Library. The existing genuine AVIRIS Cuprite fixture is not proof that every NASA AVIRIS distribution package/version is auto-importable.
- Many NASA assets require user-specific Earthdata authorization. Availability, authentication flows, archive packaging, rights and exact linked scene assets are product-specific. Do not confuse scene catalog metadata with verified accessible numeric source files. No mandatory paid account or AeroScience-hosted credential proxy.

### Stage 1 — Map-based NASA hyperspectral discovery and guided access (v0.5.0 required)

1. Add a **Hyperspectral** mode to Library > **Browse & Download Data**, reusing the geographic selection workflow from DATA-01: bounded box/polygon/cells/state-sized selection with actual NASA scene/flightline footprints, not a uniform nationwide grid promising coverage.
2. Search the official **NASA CMR product/granule catalog** for AVIRIS-Classic, AVIRIS-NG and discoverable EMIT scenes; expose **product, original observation date, footprint, wavelengths/band count when authoritative, reflectance vs radiance, known format, original archive link, size when verifiable, availability and Earthdata authorization requirement**. Show clear unsupported/unknown metadata as such.
3. Permit users to filter by scene/date, mission geometry and compatible source/instrument capabilities; preview actual footprints and retained local coverage distinctly from discovered scenes. Scene metadata does not guarantee that QA-valid pixels exist throughout a footprint.
4. For protected data, provide a **guided NASA Earthdata access flow** via the user's official provider authorization mechanisms and product landing/access links. Clearly explain the steps without asking for a NASA password in the AeroScience UI. If an official, suitable locally authorized desktop workflow cannot be safely automated, provide a functional user-directed download procedure with validated file selection instead of guessing/handling credentials insecurely.
5. Before the user confirms a download, show anticipated file sizes or **Unknown**, required disk/reservation allowance, retention policy, source terms/attribution and relevant format support. Present a warning for large multi-band files and no invented ETA.
6. Require an explicit **user action** before network download; respect privacy consent, offline/metered controls, TLS, fixed trusted endpoints, authentication secrets, storage and transfer budgets and cancellation. Never expose credentials, tokens or signed provider URLs in logs, saved metadata or exports. Do not proxy personal Earthdata tokens through an AeroScience service.
7. Show **Supported now / Download only / Requires conversion or future support** status per NASA product, with explicit EMIT limitations.

**Stage 1 acceptance:** Discover genuine official granules for at least one bounded area (or a well-documented empty-result area), display actual scene footprints with truthful metadata, distinguish prior local downloads, and guide a user to an official protected download method or original NASA product page; verify no credentials leaked and no fabricated scientific coverage.

### Stage 2 — Authorized AVIRIS download → verify → guided ENVI import (v0.5.0 required)

1. Support **AVIRIS-Classic and AVIRIS-NG compatible Level-2 reflectance products** as the first end-to-end targets. Validate the current official original asset formats, granule relationships, file naming, metadata requirements, acquisition dates, licensing, units and any product-specific exceptions. Do not assume every AVIRIS distribution is a valid ENVI input.
2. Implement secure user-authorized acquisition when the actual Earthdata flow permits it, otherwise the best reliable **download handoff** with automatic post-download verification/import guidance. Distinguish clearly between **one-click in-app download successfully implemented** and **guided browser download followed by local import**; do not misreport the latter as fully automatic.
3. Associate actual original **ENVI header + binary and supplementary metadata** correctly, verifying checksums when provided, binary dimensions/endianness, wavelengths, no-data values, band-quality flags, geo/CRS, calibration/scale, units and original scene date. Keep unmodified original file values and identify missing required metadata instead of making it up.
4. Bridge verified supported files directly into AeroScience's existing **GuidedHyperspectralImport** workflow. Preserve compatibility/validation guards, duplicate-reuse and immutable retained originals. Provide meaningful explanations and next steps for unsupported versions, archives, auxiliary files, user permissions or inconsistent metadata.
5. Use **resumable, chunked downloads only when safe and actually supported by the authoritative endpoint**, otherwise provide robust restart/error handling. Show exact downloaded bytes, paused/cancelled states, integrity status, disk availability and import verification as separate stages. Respect existing scientific bandwidth consent and flight-priority scheduling.
6. After import, map the real scene coverage in the Library and show **Available for mission planning** (subject to actual source capabilities and source-quality masks). Offer **Use with a planned mission** only for geographically compatible setups; no false new in-flight observation claim.
7. Keep product/band/date and license/attribution metadata. Treat unavailable assets or protected Earthdata authorization failures as normal recoverable states, not silent fallback to rendered RGB imagery.

**Stage 2 acceptance:** Demonstrate at least one **genuine authorized AVIRIS-Classic and one AVIRIS-NG** end-to-end *download/access and verified import* path, or document a precisely bounded external-access blocker while still completing a usable guided workflow. Validate original spectral values and wavelengths independently, exact-source provenance, geographic footprints, retained source identity, archive reopening, no secret logging, offline reuse and practical Windows workflow. Report partial compliance rather than claiming full automation when NASA authorization or format differences block it.

### Not in v0.5.0: Stage 3

**Native EMIT Level-2 NetCDF-4 data download, direct numeric geolocation/QA/uncertainty decoding, persistent import and associated spectral map visualization are deferred to `v0.6.0+`** as a separate future research/implementation candidate. v0.5.0 may show EMIT granules in Stage 1 discovery and link to their official download pages, but must label them **not directly importable in AeroScience** until a genuine numeric adapter is validated. No lossy RGB conversion masquerading as original spectra.

### General constraints

- Original v0.5.0 calibration/operating-envelope scope remains unchanged.
- DATA-01 manual downloads range from bounded source cells to larger regions; large hyperspectral region selection means **discover/choose a bounded list of existing source scenes**, not inventing contiguous coverage or automatically downloading all research flightlines.
- Implement as integrated Library UX with real provider permissions and durable source identity, not another unrelated modal or second download engine.
- Keep release status **planned** until coding and genuine-data Windows acceptance. Do not open GitHub issues or publish releases without explicit direction.

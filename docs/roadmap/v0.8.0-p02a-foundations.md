# v0.8.0 P02a shared UI foundations

Implemented on **develop/v0.8.0**, starting at P01 commit **6677f8035e813c7bddd1a99546df75218dd6157a**. This is the bounded F01–F05/P02a portion of the [P01 handoff](v0.8.0-p01-handoff.md), with focused F09 checks. The approved Auto theme, guided flow, balanced density and five locale identities are retained. Existing Home/Missions, results, science and native-toolbar feature controllers remain in place.

## What changed

| Foundation | Implementation and behavior |
| --- | --- |
| Theme and tokens | [ui-tokens.css](../../src/AeroScience.Engine/wwwroot/ui-tokens.css) supplies semantic light/dark surfaces, text, accent, danger, warning, focus, typography, spacing and control-size tokens. Existing app/workstation variables point to them. Auto follows system changes; Settings → General offers Auto/Light/Dark. Legacy chrome colors were mapped to these tokens. Scientific scalar ramps, original values and native panel styles are preserved; chart canvases retain a readable dark plotting surface. |
| Browser preference scope | [presentation-settings.js](../../src/AeroScience.Engine/wwwroot/presentation-settings.js) saves only the versioned AeroScience.presentation.v1 browser key. It handles invalid/unavailable storage, system-theme changes and same-origin preference updates. Choices apply to this browser; no host/profile, archive, scientific-access, unit or organization setting is written. Shared companion/native persistence remains P02b. |
| Components | [workstation-ui.js](../../src/AeroScience.Engine/wwwroot/workstation-ui.js) adds status pills, empty/loading states, next actions, labeled fields with associated help/errors, source/evidence badges and notifications. Existing button busy/error handling is reused. [dialog-ui.js](../../src/AeroScience.Engine/wwwroot/dialog-ui.js) uses catalog text while preserving explicit cancel, dirty-edit confirmation and return focus. Two existing collection/comparison containers gained valid ARIA roles; no command logic changed. |
| State projection | [presentation-state.js](../../src/AeroScience.Engine/wwwroot/presentation-state.js) is a pure read-only adapter for authoritative mission-intelligence fields. Recording/science remain independent. Missing, malformed, stale, unbound, pending or storage-fault state cannot authorize actions or imply collection. It is available for P04 consumers; current controller behavior was not replaced. |
| Localization | [English catalog](../../src/AeroScience.Engine/wwwroot/i18n/locales/en-US.json), [manifest](../../src/AeroScience.Engine/wwwroot/i18n/locale-manifest.json) and [message schema](../../src/AeroScience.Engine/wwwroot/i18n/message-schema.json) define 74 messages, context, named parameters, plural rules and versions. Settings lists English, Español, Français, Deutsch and Português (Brasil); the four untranslated locales are explicitly English previews. English is the readable fallback, and the document language reflects actual English rendering. Units, UTC, names, hashes and evidence are not translated. |
| Browser/native contract | [i18n.js](../../src/AeroScience.Engine/wwwroot/i18n.js) changes only explicitly marked presentation nodes. [i18n-format.js](../../src/AeroScience.Engine/wwwroot/i18n-format.js) is DOM/Intl-independent and works as ES2017. [build-locales.mjs](../../scripts/build/build-locales.mjs) validates catalogs and literal source references, checks the committed generated browser bundle, and can emit deterministic browser/classic-native/.NET-consumable artifacts. These native artifacts are not installed or connected to CommBus in P02a. |
| Routing and lifecycle | [navigation-routes.js](../../src/AeroScience.Engine/wwwroot/navigation-routes.js) centralizes page/alias/query/workspace classification. task-workspaces mounts the original nodes once; app.js retains existing disposal/generation guards. Keyboard navigation restores heading focus, supports the drawer and preserves browser Back/Forward. Tests verify one event stream and one recording request after repeated navigation. |

The source checker reports **44 literal message references** and **30 currently unused IDs**, including computed source/evidence badge families and future P04 state consumers. Unused IDs are reported for review, not silently deleted. npm run check:web now verifies the locale bundle before the existing web/native syntax checks. No dependencies were added or updated.

## Route contract

Legacy routes retain their original renderers and query values. New aliases redirect to those complete existing views; their replacement screens are later feature checkpoints.

| Alias | Existing destination |
| --- | --- |
| #missions, #missions/templates | #my-research |
| #missions/plans | #planner |
| #flight | #operations |
| #flight/details, #flight/instruments | #control, #instruments |
| #results/overview | #workspace/analysis |
| #results/explore/map, /compare, /replay | Corresponding #workspace view |
| #results/evidence with an explicit flight/missions ID | #operations?flight=exact-ID; no ID opens history |
| #workspace/timeline?missions=ID | #operations?flight=first-ID, preserving remaining query parameters |
| #settings/support?guide=...&anchor=... | #help with the original query, including guide/anchor |

#results/#history remain the recorded-flight list. Archived operations never become the active-flight view. Research preparation, card/submission/organization continuations, scientific filters, Library source discovery, Downloads plan scope and Settings categories retain their original handlers. Home and Organizations have no dedicated P02a route or empty placeholder. No alias starts recording, science, a download or a submission.

## Targeted validation

The later [full CI run 42857877645](https://github.com/JustSeanC/AeroScience/actions/runs/42857877645) exposed browser failures beyond these historical targeted receipts. See the [P02a CI remediation checkpoint](v0.8.0-p02a-ci-remediation.md) for retained diagnostics, reproducible causes, additive regressions and the corrected implementation. In particular, the original dialog test synchronization did not fix the underlying pending-close guard race.

Validation used Node 24.19.0, locked repository npm dependencies, .NET SDK 10.0.402 and system Chromium on the managed Linux environment. Test data was created only by the existing disposable TestHost. No Full CI, real Windows/MSFS, physical-device, protected NASA original-file or human-language acceptance was run.

The test host was restored with locked dependencies and built serially:

```sh
npm ci --ignore-scripts --cache /workspace/.tools/npm-cache
DOTNET_ROOT=/workspace/.tools/dotnet /workspace/.tools/dotnet/dotnet restore tests/AeroScience.TestHost --locked-mode --packages /workspace/.tools/nuget
DOTNET_ROOT=/workspace/.tools/dotnet DOTNET_CLI_TELEMETRY_OPTOUT=1 /workspace/.tools/dotnet/dotnet build tests/AeroScience.TestHost -c Release --no-restore --nologo --output artifacts/browser-test-host -m:1 -nr:false -v:quiet
npm run check:web
npm run test:presentation
```

The default sandbox denied Node worker/child-process creation (EPERM); the same targeted commands ran successfully through the normal approved execution escalation. Serial MSBuild avoided the environment's initial parallel build failure. Incremental host builds staged changed static assets before affected browser reruns. No assertion or production security requirement was disabled.

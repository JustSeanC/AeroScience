## Compatibility and identity decisions

- New evidence schemas explicitly require `version: 1`. `EvidenceContracts.Read<T>` rejects
  missing/unsupported versions, unknown fields/actions, integer enums, duplicate properties,
  invalid identifiers, unbounded collections, nonfinite values and missing required controls.
  Callers must retain unsupported original records and show an unsupported state, never strip
  fields and reinterpret them as v1 success. The legacy `WireJson.Options` remains unchanged.
- These are standalone companion contracts in P01. They are not attached to an existing live
  API or plan execution path; unimplemented automation must not be accepted then silently
  ignored as if it had run. P02/P05 will connect their persistence/execution explicitly.
- Stable survey-area IDs are carried by `CollectionPlan.SurveyAreas` as ID/index/geometry-hash
  bindings. This implements the architecture's stable-identity requirement without modifying
  the hash-pinned v0.4.2 `SurveyArea` wire shape. Explicit future collection-plan saving creates
  bindings; reading an old plan creates none. Reordering/editing polygons requires explicit
  rebinding and validation against the current plan; names alone cannot identify an area.
  Geometry hashing uses existing WGS84 validation and hashes the ordered coordinate values;
  no new geodesic algorithm or duplicate geometry store is introduced.
- Start expects no open session. Pause/Resume expect a session; End targets an explicit
  expected session or explicit no-session state. Every command carries request ID, mission ID
  and expected controller revision. A stale End for A cannot validate against B. This checks
  request shape/concurrency expectations only, not the lifecycle decision or durable retry
  behavior; the P02/P05 engine must perform receipt lookup before applying a new command.
- Closed session A and new session B have different stable IDs under one mission. Session
  state is distinct from controller BetweenSessions. Flight-wide fired/suppressed occurrence
  IDs and manual/continuity holds survive serialization; boundary/route holds target only
  the open session. Automatic End is only representable at a configured waypoint/gate.
  Neither End Flight nor deferred Finish Science is an alias in the new control enum.
- Full instrument/calibration definitions can accompany effective settings. Unknown information
  does not produce parameters or numeric success. Shape/reference validation does not certify
  the truth of a reference, dimensional applicability or calibration operation: P03/P04 must
  validate those against documented instrument-specific capabilities and actual evidence.
- `Snapshot` returns a detached deep copy; `ContentHash` sorts JSON object keys ordinally and
  preserves array order using the current serializer's numeric representation. It is a v1
  local content identity, not a cross-language JCS signature, calibration certificate or
  tamper-proof archive. P02 must persist snapshots and their identities before effects.
- Obligation IDs and planned-session keys are independent of runtime session IDs. No score
  or metric is calculated here. Default grade responses are NotGraded with no score/letter;
  unknown metrics have null values. Final response validation checks structural evidence
  identity/bounds, not the existence of archived evidence or applicability. P08/P09 must
  establish sufficiency, single-letter uncertainty bounds, frozen obligation aggregation
  and reproducible grading; averaging/selecting session grades remains prohibited.

## Validation and acceptance mapping

All new numeric positions, calibration values, hashes and scoring examples are explicitly
synthetic **contract fixtures**. They are not genuine-source or installed-device acceptance.

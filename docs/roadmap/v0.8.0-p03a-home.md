## Home behavior

[home-state.js](../../src/AeroScience.Engine/wwwroot/home-state.js) is a pure read-only projection using the existing mission presentation helper. [home.js](../../src/AeroScience.Engine/wwwroot/home.js) renders that projection with existing UI helpers and shared tokens; it owns no command handlers or independent recording/science/selection authority.

| Confirmed context, in priority order | Primary action | Existing destination |
| --- | --- | --- |
| Fresh active flight | Open Current Flight | #flight → #operations; actual active identity, independent recording/science and important warnings |
| No active flight; original planner has unsaved edits | Resume mission setup | #planner; same live form, geometry, draft and discard guards |
| No active flight/draft; selected saved plan | Continue mission setup | #operations; original selection, readiness and explicit recording controls |
| Current connected simulator; no selected plan | Explore science missions | #missions → complete existing My Research starters/cards/templates |
| Disconnected, paused or stale simulator input | Connection steps | Existing bundled troubleshooting guide; mission preparation remains discoverable |
| Companion read failed, unsupported, stale, future-dated or mismatched with current flight identity | Connection help | No confirmed recording/science status; read-only Refresh remains available |

Active flight takes priority over a later saved plan and unsaved draft; all three names remain separate. A missing selected plan displays its loading/error state and never becomes an unplanned flight. Home's links do not start recording, collection, preparation/downloads, live sharing or submission. The original controllers still own all command/revision/identity/permission checks and receipts.

Critical recovery warnings precede the primary action in reading/layout order, including at narrow widths. Recording and collection are separate indicators. Collection is qualified by telemetry freshness, pause, mission/session binding and original storage/continuity holds. Retained counts use fresh mission-bound indexed original/derived/product counts, including actual zero; null, mismatched and stale counts remain unavailable. Counts and recording completion do not establish scientific quality, readiness or objective completion. The source explicitly identifies simulated telemetry.

Recent results are bounded reads of completed/interrupted flight records, with exact-ID recorded-review links. Live recordings are excluded. Confirmed empty results, loading, unavailable archive and stale archive checks are distinct; failed reads cannot claim that no saved data exists. Scientific evidence/limitations remain in the original review, including deleted/unavailable science.

## Navigation and lifecycle

- Blank URLs now open the implemented #home. Unknown routes keep the recoverable My Research fallback.
- Main navigation is Home, Missions, Current Flight, Results & History; Organizations appears for actual configured connections. Scientific Library, Settings and Help remain named utilities. No renderer is replaced by a placeholder.
- Missions mounts the original My Research and full planner once, with named secondary entries. Flight tools retain a Flight Planner escape. The Missions mount anchor preserves the previous flight-tools-before-planner document order: original map/search lookups must continue selecting the visible planner, including after navigation.
- #organizations is a presentation alias to #my-research?section=organizations, preserving other parameters and focusing the original organization section. Connect/Create remains discoverable from Home and Missions even with no connections. This alias grants no permission and supplies no fabricated connectOrganization server address.
- Every legacy route and supported query continuation remains owned by its original controller. Recorded-flight IDs, multi-ID workspace queries, researchPlan, card/flight/submissionDraft/connectOrganization/permission, scientific filters and harmless future parameters survive alias translation.
- Home uses the application's single existing SSE for current identity, plus visible-only GET polling of mission intelligence (at most once per two seconds) and recent records (ten seconds). Reads have six-second deadlines. Selection changes, hiding and disposal abort/invalidate old reads; late results cannot update another view. Archive availability expires after twelve seconds without a successful check. Polling preserves focused nodes; Back/Forward and the mobile drawer retain the existing keyboard contract.

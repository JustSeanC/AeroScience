## Storage and evidence identity

Mission schema **14** adds `mission_simulator_origins`: one version-1 origin, original JSON SHA-256 and freeze time per new qualified recording, transactionally created with the flight. The existing verified pre-upgrade SQLite backup, free-space checks, atomic migrations and future-schema refusal remain. Failed upgrades leave old flights readable; an older schema claim cannot hide a retained origin table. Foreign-key cascading follows existing explicit flight deletion. Science storage remains the same shared library/database; there is no separate simulator library or historical rewrite.

`Mission`, `TelemetryFrame`, `AtmosphericFrame`, `ScienceObservation`, `ScienceCollectionSession` and performance evaluator inputs have nullable source metadata, omitted when absent. Existing positional constructor shapes and `TelemetrySource` meanings remain. Generic historical Simulator records have **unknown simulator identity**, even after Settings changes. Legacy source JSON/hashes are neither backfilled nor relabeled.

Frozen identity includes simulator ID, actual reported version/build when supplied, adapter/version, API/mapping revision, adapter connection epoch, available aircraft type/registration, host-receipt basis and limitations. MSFS build is **unknown**, not the SDK version. The MSFS host epoch identifies the AeroScience adapter instance; it is not an attested simulator-session identity. X-Plane simulator year remains **unknown**.

New X-Plane input context retains original numeric dataref values **with native units and actual confirmation times**, normalized frame/observation values, field change/receipt/confirmation times, host UTC and separately reported simulator clock components. Private aircraft file paths are excluded. Pressure Pa → inHg, wind m/s → knots and density kg/m³ → slug/ft³ remain reproducible from the recorded native values. Context is a bounded non-atomic composite, never an atomic simulator snapshot.

## Authoritative recording and collection

The existing `SimulatorAccessPolicy`, `MissionCoordinator`, `TelemetryWorker`, `ResearchOperations`, `ScienceCollectionController` and stores are reused. No second recorder/collector is introduced. Exactly one selected provider and the explicit companion-restart rule remain from P03.

The host independently checks the supported compiled adapter/API/mapping, matching epoch, original numeric values/conversions, required field confirmations, valid aircraft frame, core span ≤500 ms and confirmation freshness ≤2 seconds. These remain conservative engineering hypotheses. Provider `ProductionRecordingReady` / `ScienceIntegrationReady` bits remain transport reports, **not authorization**; neither true nor false substitutes for host qualification. The Engine snapshot/settings readiness is the host's result. A live socket, UI flag or changed frame timestamp cannot renew cached evidence.

Qualified X-Plane recording works through the existing endpoints and policies. Armed and legacy collection starts remain separate. Science Start/Pause/Resume/End and session/revision/request checks retain their original authority. Frozen source must match persisted samples and science sessions. Windows status and the dashboard distinguish eligibility from actual recording/collection; installed simulator acceptance is explicitly pending.

Supported science: aircraft-local ambient **temperature, static pressure, wind speed, true wind direction and density**, only when their own values and timing qualify. Original simulator readings and optional user calibration derivations remain separately labeled. Source-aware instrument specifications/default references use distinct X-Plane identities and official dataref names. Existing selected calibration definitions are not rewritten. Genuine NASA/satellite/DEM/LiDAR source provenance, dates, QA, ownership and deletion remain independent of simulator choice.

Unavailable: aircraft-local humidity, clouds/in-cloud, precipitation, optical visibility, environmental vector axes, detailed autopilot/guidance, unverified ground elevation and any undocumented channel. MSFS environment/guidance enrichment is bypassed for X-Plane. Cloud Structure Survey cannot start cloud science from atmospheric substitutes. X-Plane remote-sensing collection, footprints and survey/experimental cards remain restricted because attitude/AGL ground-intersection qualification is not established. Universal mode cannot override that restriction. Existing external Library and archived Results remain accessible.

Normal, explicitly confirmed rate channels are required for atmospheric evidence and continuous-hold credit. Missing/accelerated rate evidence does not manufacture observations or success. Flight-regime/procedure evaluators and automatic detection honor continuity breaks. Card focus/activation does not complete or acquire evidence; unsupported card attempts/evaluation are refused without changing issued definitions or revisions.

## Continuity and geometry limits

X-Plane telemetry/connection qualification loss, a new epoch, changed aircraft, clock rollback/replay, a changed time-rate regime or a position-discontinuity candidate **interrupts** the flight, closes science as interrupted, retains original rows and appends source-qualified boundary evidence. A pilot must explicitly start a separate recording after qualification. This deliberately conservative P04 behavior does not automatically resume across reconnects or infer a loaded-flight identity.

Simulator pause produces no saved paused sample or scientific exposure. Resume retains an explicit segment break. Track reduction/cursor pages, quantitative windows, geographic automation, terrain profiles and navigation exports respect that break; routes are not stitched through an unqualified interval. Existing geometry mathematics remains unchanged; a source-aware X-Plane footprint is refused. Candidate pitch/bank/AGL conventions are not certified by synthetic mathematical tests. The 1,000 m discontinuity tolerance is an engineering candidate detector, **not** an aircraft speed limit or measured coverage claim.

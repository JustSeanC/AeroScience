# AeroScience v0.8.0 — P01 Handoff to P02 (Foundations)

**Checkpoint date:** November 10, 2026. **Branch:** `develop/v0.8.0`. **Completed in this checkpoint:** approved owner preferences integrated; static route/control inventory and risk-ranked usability audit committed. **Not completed:** runnable UI implementation, native SDK acceptance or all dynamic-controls enumeration.

## Approved baseline (do not reopen without new owner request)

- Dashboard theme: **auto** (follow OS/browser preference), with a visible manual Settings override.
- Guided novice journey by default; experienced controls stay available in-place, not in a separate irreversible mode.
- Balanced visual density: modern and spacious with concise summaries, expert detail easy to reach.
- First-wave locales: **en-US, es-ES, fr-FR, de-DE, pt-BR**; language controls for dashboard, native toolbar, Windows companion and organization portal; source and permission review before release.
- MSFS toolbar readability and existing command integrity take priority over exact dashboard component parity.
- UI/UX changes on 0.8 only while 0.7 testers continue; later 0.7 bug fixes forward ported, never the reverse.

## Proposed screen-level wireframes (concept specification, not rendered UI)

### Home (new contextual root)

```text
[Brand / Home | Missions | Current Flight | Results | Organizations?] [Connection] [Settings]
Home
[Active flight?  CONTINUE CURRENT FLIGHT / connection/blocked next action]
[No active flight? START A SCIENCE FLIGHT / Explore experiments]
[Continue saved draft]   [Recent results]
Suggested experiments: question -> aircraft/source needs -> Fly Now | Customize
Footer utilities: Scientific Library | Help
```

The primary card is contextual: if active, show confirmed recording/collection states and resume link, not competing new-flight CTA. If disconnected, show a clear recoverable state. Pairing is a pre-home blocker with separate UI and never becomes a silent success.

### Missions

```text
Missions / Explore                   [My Plans] [My Templates] [+ Custom Experiment]
[Search by science topic] [Optional filters: difficulty, source requirements]
[Vertical Atmospheric Profile]  What changes as you climb? [Fly Now] [Customize]
[Atmospheric Transect]          How do conditions change across a route? ...
[Terrain & Temperature Survey]  What are the available sources? ...
Selected mission -> short readiness panel -> optional advanced route/instruments
```

Cards must expose only supported source and aircraft choices; defer advanced input form until Customize or actual readiness needs. A single guided flow should allow an unplanned flight, respecting explicit recording and science actions.

### Current Flight — browser

```text
Current Flight                    [Connected]  [Recording / Not Recording]
[Mission name + current research question] [Next relevant action]
[FLIGHT RECORDING state]         [SCIENCE COLLECTION state & saved originals]
[Objective / active cards]        [Live map and track]
[Instruments — concise statuses, critical QA visible]
[Add pilot observation] [Instrument Details] [Flight Details] [Timeline]
```

One next action depends on authoritative mission/collection phase; Card focus and Card activation remain separate. Critical scientific failures are never buried under Instrument Details.

### Results

```text
Results / History [search + filter + sort]   selected recorded flight
[Overview] [Explore] [Evidence]
Overview: actual measurements, source types, dates, quality and meaningful findings
Explore: map, chart, terrain/profile/compare where source-compatible, table equivalent
Evidence: synchronized original observation and attempt IDs, flags, UTC, methods, export
```

Preserve all six legacy science workspace deep links as compatible routes into these three presentation layers, not as deleted pages. No chart interpolation or speculative terrain swaths.

### Scientific Library

```text
Scientific Library [Sources] [Downloads] [Storage]
Sources: search/filter retained datasets, provenance/date, reuse/QA, inspect, manage
Downloads: mission-required preparation, queue state, pause/cancel/errors, source consent
Storage: used/free bytes, file location, actual deletion + preview blockers
```

Do not replace original `/api/science/*` action authority. A single navigation entry does not mean one combined destructive API.

### Organizations

```text
Organizations [My Assignments] [Campaigns] [Live Flights] [Submissions] [Admin?]
Current action: accept/prepare assigned research, see approved results or authorize access
Submission: reviewed recipient + exact evidence + size/retention + explicit final approval
Live Flights: explicit pilot opt-in, temporary read-only sharing, stop sharing
```

Show Organization in main navigation only when a connection or active assignment exists (or user intentionally chooses Join an Organization from Missions/Settings). Test no membership, expired session and read-only role.

### MSFS Toolbar

```text
AEROSCIENCE                      [Connection status] [SCIENCE ACTIVE/INACTIVE]
[Mission | Science | Cards*]      [Map subview link]
Mission / Flight: name, selected plan, recording, one next action, minimal telemetry
Science: collection state, retained originals, next science action, automation, instruments
Cards*: focused question and card actions with clear focus vs activation
[Connection & Build Details] [Advanced diagnostics]
```

Cards tab visible only where capable/relevant. Preserve all existing map follow/fit/zoom/waypoint inspection functions under Map subview, despite reducing top-level tab count. Keep old native panel drag/resize and source package rules. Native strings must not overflow at minimum supported panel size.

## Toolbar authoritative action/state matrix

| Confirmed state | Flight next action | Science next action | UI assertion |
|---|---|---|---|
| No companion reply / mismatch | Launch/reconnect companion, commands disabled | Commands disabled | Build/channel registration is not authoritative connection |
| Connected, no active mission | Start Recording | Not collecting | No claim of sampling |
| Flight recording, no scientific session | View Flight or End Mission | Start Science / Arm if supported | Flight samples separated from science originals |
| Armed/awaiting trigger | Continue Flight | Wait for exact configured gate or eligible manual override | **Not collecting** |
| Collecting | Continue Flight | Pause Science, end session secondary | Status only from fresh controller; saved/rejected separate |
| Paused science | Continue Flight (recording may remain active) | Resume Science | Paused science does not imply recording stopped |
| Between sessions | Continue Flight | Start new session / rearm as supported | Previous session retained, no inference about current observation |
| No supported sensor / invalid QA | Continue Flight if otherwise allowed | Unavailable/fix actual problem | Critical error visible |
| Stale, wrong revision, storage hold | Recovery guidance | Relevant commands disabled | No optimistic confirmed success |
| Completed flight | Review saved Flight | Collection stopped | Archive selected by exact mission ID |
| Research card active | Cards tab | Focus, attempt actions via original commands | Focus/active/attempt are independent |

## Integration and risks

**Priority risks:** replacing DOM nodes loses active listeners; browser and Coherent compatibility differ; locale catalogs and runtime packaging can fail offline; all-language native support may require SDK font fallback; constant reconnection can cause stale status; arrival of 0.7 tester bug fixes may conflict in `app.js`, `workstation.css`, toolbar HTML/JS or mission controls.

**Mitigation:** read-only adapters; compatibility-preserving route layer, no existing controls removed until tested; locale bundle manifest and missing-key CI; focused tests per checkpoint, native test gate; stagger forward-merges from 0.7 only after accepted fix, tracking conflicts and original revision.

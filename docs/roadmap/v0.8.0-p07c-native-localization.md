## Implementation

The existing `PresentationText` adapter embeds all five canonical resources, resolves the selected locale explicitly, verifies source identity/version and falls back per message to English. Its bounded integer plural rules match the classic JavaScript formatter, including French/Brazilian Portuguese zero and million-count categories. It does not change process/thread culture, recorded units, UTC, serialized evidence or source hashes.

Windows controls call this adapter through `WindowsPresentation`. Profile preferences are read before constructing the main window; the existing revisioned store persists choices. The main window updates its action buttons; existing Settings/setup/import controls require reopening, and the save feedback explains that limitation. OS high contrast, DPI scaling, focus and original storage/deletion confirmations remain in place. Typed archive-deletion phrases are immutable parameters, never translated command text. Source/provider IDs, paths, credentials and original diagnostic details remain original values.

The existing toolbar adapter now verifies the companion's catalog hash as well as contract/version/locale. An unavailable or mismatched catalog selects English without rejecting otherwise valid telemetry. Catalog 20 has 6,622 canonical messages; its deterministic native projection retains 363 relevant messages and the same source identity, producing a 175,633-byte classic data script. No remote fetch, module or mandatory `Intl` is introduced. Native static controls, accessible names, operational statuses, science/session controls, instrument labels, card actions and offline-map explanations use the shared catalog. Text bindings update their own text nodes and retain interval drafts and nested controls. Cached card displays include locale identity. Existing bootstrap, panel geometry, map calculations, CommBus sizes, request correlation, mission/session/revision and authorization logic are retained.

An active-flight regression exposed appearance yielding at the original 8,000-byte boundary. The existing read-only, correlated `research-state` poll now carries optional appearance and engine identity when it fits; full replies still yield appearance before scientific detail. A same-engine packet omitting appearance retains the last accepted choice. Explicit mismatches fall back, newer engine identity resets it, and stale/foreign-engine replies cannot select a language. No extra command or side-effect controller was added. Targeted tests verify both the byte boundary and language changes during an armed recording with an unsaved interval draft.

The organization portal has a separate browser preference key, `AeroScience.organization.presentation.v1`. An optional authenticated member preference takes precedence in memory; sign-out clears it. The new self-only `/api/account/presentation` endpoint uses existing cookie/security-stamp validation, origin and CSRF middleware, MFA and compare-and-set revision checks. Its additive migration adds only nullable language and revision columns to the identity table. It neither accepts another user ID nor writes roles, grants, science, telemetry or sharing consent. Anonymous users can select a browser language without an account. Theme remains independent.

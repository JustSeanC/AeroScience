## P05c.1 — Sources and decoder decision

Official geographic discovery uses the USGS [3DEP spatial metadata](https://www.usgs.gov/3d-elevation-program/3dep-spatial-metadata) index, the same project/work-unit fields used by [LidarExplorer](https://www.usgs.gov/tools/lidarexplorer). Each query requests at most five geographic work units; source polygons, quality statements, original acquisition range, publication date and CRS declarations remain original metadata. Work-unit dates are not attached to a differently named EPT project merely because their outlines overlap.

The public [USGS EPT registry](https://registry.opendata.aws/usgs-lidar/) documents the separate public EPT and Requester Pays raw-LAZ collections. Only `usgs-lidar-public.s3-us-west-2.amazonaws.com` is supported. Bounded prefix pages contain at most five project keys; verified EPT metadata filters geographic candidates. An exact project identifier is also supported. Five-result pages and source bounds are not a whole-national inventory or valid-point-density guarantee. Unknown dates, density, vertical reference and units stay unknown. A project name, cache date or flight date cannot supply them. Unsupported/unavailable projects are explicit; no alternate survey is silently selected. No national catalog or whole-cloud download is used for discovery.

Chosen decoder: unmodified LASzip source, published tag **3.5.0**, exact commit **`fa089bd8b2b4ca5631e199d257374c32a125f73f`**, Apache-2.0. The tag contains API 3.5.1 constants; source policy hashes determine identity. The separate AeroScience read-only helper statically links the pinned source. Local Linux build: **683,216 bytes** before final build-identity refinements; this is a measured development build, not a promised cross-platform binary size. The offline build verifies every upstream file and rejects unreviewed extra files. Original copyright/authors/license are retained; the license accompanies published project output. No runtime binary is fetched from PATH or downloaded/installed on a user's computer.

Alternatives evaluated: [PDAL](https://pdal.io/en/latest/download.html) supplies EPT/COPC/CRS readers and documented Windows x64 packages, but a full distribution adds PROJ/GDAL and other native dependencies, plugin/network configuration and substantially more packaging surface. A direct managed LAS parser alone cannot decode real LAZ. Synthetic clouds or raster-to-XYZ conversion do not satisfy this checkpoint. Independent validation uses **laspy 2.6.1 + lazrs 0.7.0**, not a second copy of LASzip.

The helper is an identified local subprocess with argument-list invocation, no shell, no HTTP client/plugins, 256 MiB process/address/heap limits as supported by the OS, one Windows job process, 60 CPU seconds and a 90-second parent deadline. Replies are bounded to 4,096 records, preserve original extra bytes and are validated for protocol/count/length. Linux core dumps/file output are disabled. These are resource boundaries, not a claim of a complete hostile-code filesystem sandbox. .NET verifies the bundled executable's SHA against its compiled identity before every invocation.

Supported decoding: LAS 1.1–1.4, original point formats 0–3 and 6–8, ordinary LAS/LAZ; per-original bound 512 MiB / 20 million points; VLR/EVLR metadata at most 1 MiB. Waveform formats, unsupported CRS/units and corrupt metadata are refused. COPC markers are explicitly detected and refused pending validated spatial-index access; ordinary LAZ is not advertised as COPC. Original XYZ integers, delivered scale/offset, intensity, classification/flags, returns, scan angle, source ID, present GPS bit patterns/RGB/NIR/scanner channel and all delivered extra bytes are retained. Missing optional attributes are null. Original VLRs/extra-dimension descriptors remain inspectable. LAS header file-creation dates are not survey acquisition dates.

Supported horizontal calculations are WGS84 geographic, EPSG:3857 and WGS84 UTM in the verified hemisphere/domain. Original XYZ remains available; only XY is transformed for exact point-in-corridor tests. No NAD83/state-plane/WGS84 substitution, vertical transformation, guessed height unit or simulator MSL equivalence. Conflicting WKT/GeoKeys, unsupported explicit horizontal axis order and incorrectly declared horizontal units are refused. Raw header/global encoding and original GPS bits (also exact hexadecimal for browser inspection) preserve the declared time reference; no UTC time or missing GPS week epoch is invented.

The root contains **34,923 genuine delivered historical records**. Every record's coordinates and present attributes/extra bytes matched the independent Rust LAZ decoder. This single EPT octree level is sparse and is **not** full-density Iowa coverage, raw contractor coordinates before Entwine, or flight-generated points. Its survey date, vertical datum and height unit remain unknown.

The actual-network application acceptance also used `IA_FullState`, through the original Library preview/explicit approval/AutomaticScientificData queue. Actual numeric bytes were **4,640,546**; all discovery/planning/worker diagnostics recorded 39 requests, 1,142,712 metadata bytes and zero retries. Genuine local LAZ import independently scanned **34,923** records and retained **1** in the same kind of verified synthetic archived-flight corridor. The independent oracle is `scripts/validation/verify-lidar-points.py`: **laspy 2.6.1/lazrs 0.7.0**, **pyproj 3.7.2/PROJ 9.5.1**, **Shapely 2.1.2/GEOS 3.13.1**. Maximum XY geographic differences were **7.11×10⁻¹⁵° local** and **2.85×10⁻¹⁴° public**; original numeric values and retained record sets matched exactly. This validates delivered EPSG:3857 coordinates, not an unknown contractor CRS/vertical datum.

Separate real processes reopened the retained originals and processed fresh 1,024-record partitions, with **no network calls**, reproducing the same point sets and independent comparisons. A genuine local source-deletion probe removed all managed originals/point tiles, including a registered recovery copy, while preserving P05a geometry, flight science and explicitly retained test exports. Acceptance folders are isolated synthetic mission stores; no owner archives were used. Genuine original records are real public survey measurements, while the flight/corridor is synthetic. COPC and installed MSFS acceptance are not inferred from these tests.

## P05c.2 — Verified originals and approved retrieval

Local import uses the original Scientific Library copy/hash/reservation, source index, ownership and deduplication machinery. A distinct optional `PointCloud` manifest contract preserves the original LAS/LAZ header and VLRs; null is omitted for all older manifests. Every supported record is decoded in bounded batches before publication, under a ten-minute import deadline and 1 GiB decoded-work bound. Generic affine imports cannot bypass the point verifier. Original XYZ, present fields and opaque extra bytes remain original source evidence, with no new observation, acquisition or science credit. Historical point sources are explicitly excluded from raster sampling and live terrain-source selection.

EPT preparation freezes exact project metadata SHA, intersecting full-density node identities/counts and hierarchy snapshots. At most eight 2 MiB hierarchy pages, 64 nodes, two million candidate points and a ≤0.1° study rectangle are supported per review. Excess candidates fail explicitly rather than silently lowering density. Geographic/Mercator prefilters are bounded spatial queries; UTM uses a conservative domain and can require smaller supported collections. Actual corridor clipping is separate. Compressed byte totals remain unknown; an explicit per-job cap and existing per-download/preflight allowances govern actual bytes.

Each EPT node is an independently retained original, reusable by overlapping later jobs. The existing Library preview/selection hash/expiry, approval, control states, AutomaticScientificData priority queue, consent, background/metered policy, transfer ledger and storage reservations are reused. No extra source concurrency or general job system is introduced. Active flight work retains priority. A stopped transfer does not authorize an automatic restart. A completed staging file needs its original transfer receipt and SHA before reuse; an incomplete or altered file is never accepted. Managed interrupted work stays visible/accounted by the existing write-ahead ledger.

## P05c.3 — Exact historical point products

`LidarPointGeometry` streams the original verified P05a chunks into a disposable bounded SQLite RTREE containing modeled polygons/bindings only. Original point XY is transformed into geographic coordinates and tested against exact polygons with holes, including boundary points. The index never substitutes a route/search bounding box. Selected chunk scope is frozen; original invalid/pause gaps remain absent. Every original file is scanned in bounded record batches once, so repeated passes/chunks add session/configuration/profile associations without duplicating a source record. Identical original files selected under multiple source identities are rejected. Different surveys are separate sources/products.

Version-1 `lidar-point-tile` JSON retains original source/header/VLR lineage, file SHA, original record ordinal, raw XYZ integers and delivered scaled XYZ, optional attributes/extra bytes, geographic clipping location and exact session/configuration/profile/chunk associations. `lidar-point-index` holds metadata-only source summaries and hashed tile references. It does not embed a second copy of point values or opaque original VLRs. Both use algorithm `historical-lidar-corridor-1/native-records-1` and the pinned decoder source identity. JSON is an analysis format, not exact LAS export.

The new domain-specific job/checkpoint tables follow P05b's additive backed-up schema, transaction, control revision and receipt pattern. They contain source IDs/hashes, frozen geometry/options, progress and artifact references, not original point values. Creation and control request IDs are content/revision-bound and idempotent. Tile/count/progress updates commit atomically; progress alone does not invalidate a Pause command. Resume rechecks recipe, geometry, originals, checkpoint bytes/counts and output identities. Verified publish-before-checkpoint outputs can be reused. Same-input processing reuses immutable tiles deterministically. Restart requires explicit resume and never restarts a network download.

Defaults: 2,048 records/tile, one million candidate records, 8,192 tiles, 128 MiB output, 64 MiB geometry scratch, 2 GiB original verification, 200,000 geometry vertices and 8,192 support links/tile. Hard bounds: 4,096 records/tile, 20 million candidates, 20,000 tiles, 512 MiB output/scratch, 8 GiB verification, one million geometry vertices, 512 intersecting chunks/point, 32,768 support links/tile and 16 MiB per output file. Output serialization enforces its reservation while writing, before atomic publication. Counts and partial-completion labels do not claim full-density geographic coverage or new flight observations.

Source-owned numeric tiles and interrupted writes participate in existing selective source deletion, physical metadata-backup cleanup and registered recovery-copy ownership. Deleting one source removes its managed point values and invalidates dependent reads; unrelated originals, airborne observations and modeled P05a geometry survive. Collected-science deletion includes the new job/checkpoint/receipt tables through the existing journal/cascade path. Active analysis leases remain mandatory. Original recording/calibration/collection/grading/organization controllers are unchanged.

Focused P05c.3 verification: **54 tests passed**, including actual corridor holes, pause gaps, repeated passes/multiple sessions, native original record/attribute preservation (also LAS 1.4 formats 6/7/8), deterministic tile reuse, create/control receipts, pause/restart/resume, changed inputs/checkpoints, atomic output limits, selective deletion and original DEM regressions. One new test initially used record-reference equality for a deserialized array; it now compares the complete serialized receipt, preserving the full-content requirement. ## Windows distribution and remaining acceptance

The source-pinned helper uses x64 MSVC with static CRT (`/MT`), a Windows job resource boundary and no system PDAL assumption. The helper/license propagate through normal companion and isolated-validation publish graphs. Linux organization builds explicitly allowlist only pinned native sources/build script and install compiler/Python in the **build stage**; the non-root/chiseled runtime, TLS, permissions and source-archive exclusions remain unchanged. Actual Windows build/decoder execution is established by the focused Windows run above; exact-source Full integration remains mandatory, separately from installed acceptance.

**Release blocker:** the existing release payload verifier intentionally permits one Windows application executable. The new identified `LidarRuntime/AeroScience.LidarReader.exe` therefore needs a reviewed **v0.8-specific payload allowlist, binary/license/signing and installer acceptance** at the release checkpoint. Existing v0.7/Beta 2 release verifiers and installer scripts are not changed or weakened. Apache-2.0 license/source notices are retained, but this is not permission to publish a new native payload. Until that integration and installed testing pass, this is a tested development/experimental runtime, not an installer-ready scientific release.

Installed Windows/MSFS (picker, profile/storage behavior and actual simulator use) remains **Not Tested**. Indexed COPC is **unsupported** pending genuine validated index/range/CRS/resource tests; COPC-marker refusal is tested, ordinary LAZ is not a COPC substitute. Genuine full-provider UTM, unsupported CRS/vertical transformations, waveform formats, complete national discovery and large whole-region processing are not accepted capabilities. No v0.7.1 merge/cherry-pick is performed; the controlled forward-port plan from P05b/P04 remains separate, including provider/retry/counter/map changes `04d24aa`, `ed2f791`, `39222c60`, `6648117` and `37a55add` where applicable.

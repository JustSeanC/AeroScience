## P03 implementation and acceptance

### Preferences and restart boundary

`AppPreferences.Simulator` is an additive, optional version-1 `SimulatorPreferences` section. Legacy/missing sections select `msfs2024`, port 8086, revision 0 without writing a file. Supported IDs are exactly `msfs2024` and `xplane12`; advanced ports are integers 1–65535. Present unsupported versions, IDs, ports, revisions, malformed JSON and extra simulator fields fail closed. They are never repaired by switching simulators. Native startup and the settings view provide backup/correction guidance without replacing the file.

`PreferenceStore.SetSimulator` reuses the original per-profile gate, atomic writer and confinement validation. Revision checks prevent stale updates. It patches only the Simulator section; language/theme, units, storage, network, consent, Community paths and unknown owner sections remain independent. A repeated identical save does not increment the revision. No second settings store, data profile or migration was introduced.

Authenticated GET/POST `/api/settings/simulator` uses existing host, session, same-origin and CSRF protection; writes also require loopback. The view distinguishes saved preferences, effective startup selection, engine instance, restart requirement, connection detail and recording/science availability. Saves acquire the original coordinator maintenance gate, refuse recording/maintenance/import work and retain the active provider. A settings-file error never grants recording or substitutes another source.

Native Settings General contains one keyboard-accessible Simulator selector, Save/Reload, a collapsed advanced port control and saved/effective/restart messages. The browser General panel uses existing field/status/localization helpers, retains dirty drafts and focus during refresh, rejects late reads after saves and keeps paired clients read-only. A source change does not restart the engine or end a flight. `MainForm.ActiveSimulator` is frozen for the companion process; storage/setup/connection-settings engine restarts continue using it. **Close and reopen the companion explicitly to apply the saved choice.**

### Startup and MSFS isolation

`ApplicationProfile.EngineOptions`, `EngineOptions` validation and all desktop launch arguments project the selected source through the existing engine. `EngineApplication` registers exactly one `ITelemetryProvider`: original SimConnect for MSFS, existing P02 X-Plane provider for X-Plane. Standalone engine startup without an explicit source override consumes the same saved preference. There is one telemetry worker and no process detection, first-success selection, synthetic fallback, automatic port scan or hot swap.

In X-Plane mode, the MSFS toolbar worker/CommBus transport is not constructed as a hosted service. Defensive worker and command-authorization checks also reject manually resolved/stale MSFS requests. Native startup, Settings and setup skip Community discovery, toolbar update prompts, installation and SimConnect recovery guidance. Existing toolbar files and packaged MSFS dependencies are retained. The legacy toolbar route remains reachable with an accurate unavailable explanation. MSFS mode retains its original provider, native bridge authorization, setup and mission/science paths.

### Read-only telemetry and authoritative safety

`SimulatorAccessPolicy` is shared by `MissionCoordinator` and `ResearchOperations`. X-Plane remains unconditionally ineligible for production recording and science even if an incoming fixture/provider claims ready flags. Source-mismatched or unqualified P02 packets also fail closed in legacy coordinator construction.

The coordinator's X-Plane path exposes only valid, matching, recent basic telemetry diagnostics. It clears stale/missing/disconnected/foreign positions, including aging without another packet. It does **not** call MSFS environment enrichment, the recorder, science observers, collection ingestion, geographic automation or card acquisition. Atmospheric/environment/guidance science projections remain unavailable. A live-only optional `EngineSnapshot.Simulator` describes availability; it is omitted for the original eligible MSFS shape and is not persisted as historical evidence.

Legacy and new recording calls, science start/arm/resume/control and receipt replay, acquisition publication, card activation/attempt controls and new live-sharing preview/start/send are gated at engine/controller boundaries. They cannot be enabled by a browser button or stale toolbar request. Plans, configuration, Library access, saved tracks, archived science, existing exports and already eligible historical organization submissions/reviews retain their original contracts. No X-Plane mission/sample/dataset is created. Existing historical identities, values, hashes and generic Simulator records are not relabeled.

Scientific preparation still permits explicitly approved offline plan preparation. X-Plane positions do not drive automatic flight preparation or claim source/instrument validation. Survey aircraft-point readiness reports science unavailable in P03. No new download, sharing, organization authorization or external network consent was added.

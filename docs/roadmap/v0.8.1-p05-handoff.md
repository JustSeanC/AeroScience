## Compatibility and original ownership

Mission schema stays **14**. No new scientific schema, historic rewrite, source inference, calculation, simulator mapping, receiver downgrade or data migration is introduced. New fixtures exercise real 7→14 and 13→14 sequences; verified pre-upgrade backups; interruption before origin migration commit; recovery from the original schema-7 backup and from the valid intermediate schema-13 database; concurrent SQLite writer release; origin/hash backup restoration; version-3 JSON/CSV/GPX/KML source disclosure; and flight-owned origin cleanup. P04's insufficient-space, corrupt/future origin and future-schema refusal tests remain required.

An actual prior engine compiled from **`741e4a9de3484d24fb8e5886be8e3762d996ce84`** (schema 13) is executed against disposable schema-14 data. `legacy_runtime_081.py` archives the pinned source, builds it with locked dependencies, requires its explicit future-schema refusal, and checks the complete original database fingerprint and legacy/new identities afterward. It does not switch/modify main or open an installed archive. The Linux local probe passed; Windows installed downgrade remains a P06 observation.

The archive-copy audit found two defects: a temporary backup was registered then renamed/moved, leaving an obsolete ownership target; and `Metadata/ManagedCopies` from the original library was copied into the new one, transferring authority over original backups. `ValidationArchiveCopy` now registers the **final** mission/science database paths and excludes the original library's external-copy authority. `DataBackup.Create` retains its normal behavior unless an explicitly supplied final registration path is used by that existing copy workflow. Source database payloads/fingerprints and original files stay unchanged; existing explicit ownership bookkeeping is retained rather than bypassed.

Copying is an explicit existing UI operation, never startup adoption. It records administrative ownership ledgers in the source profile, as the original copy contract requires; this is distinct from changing original observations. P06 defaults to fresh data. Copying an accepted archive needs a separately approved copy plan, original applications closed, enough space and a fresh confined destination. Copied source jobs do not grant new network authorization. See the [P06 procedure](v0.8.1-p06-candidate-checklist.md).

Flight origins belong to flight records: approved flight clearing cascades them in the selected database; science-only deletion retains the separately owned recording/origin. Existing scientific deletion continues purging owned backups/caches and refusing unresolved external copies. Explicit independently retained backups keep their existing ownership/restore semantics. No hidden automatic archive is added.

## Evidence, organizations and live monitoring

Existing version-1/version-2 immutable evidence and legacy mission JSON format 2 retain their original meaning. New mission JSON/submission version 3 retains frozen origin JSON/hash, native units/values, actual receipt/confirmation times and separate simulator clock components. Navigation CSV/GPX/KML preserve source/basis and explicitly are not full scientific evidence. There is no new raw mission-archive importer: verified database copying and the existing versioned receiver are the supported round-trip paths; route import does not manufacture research evidence.

P04 receiver negotiation remains authoritative: `simulatorOriginsVersion: 1`, exact server/pilot/Submit Evidence scope, original payload/manifest hashes, explicit approval/delivery, idempotent receipt and independent review. Unsupported receivers hold/refuse version 3; no stripping, downgrade or new cloud endpoint. NASA/satellite/DEM/historical LiDAR sources keep their own original provenance, dates, units, ownership and deletion rules.

**P05 decision: X-Plane live sharing stays disabled.** Live protocol 1 lacks frozen simulator/epoch information. A safe extension still needs a version-2 payload, explicit receiver capability negotiation, source/epoch verification, source-aware bounded display and permission/revocation/TTL tests on both sides. Existing MSFS live sharing, ephemeral positions, stale expiry, consent and organization visibility remain unchanged. A label alone is not sufficient. No new telemetry stream, history archive, Discord pipeline or automatic consent is added.

Orderly X-Plane shutdown now sends unsubscribe and the WebSocket protocol close, and allows the existing sole receive loop to observe peer closure within the original cleanup budget before abort fallback. Previously, abort immediately after `SendAsync` could discard queued unsubscribe bytes. This changes transport cleanup only: application messages remain restricted to subscribe/unsubscribe, HTTP remains GET-only, and cancellation or a peer that never closes still has bounded teardown. No additional simulator command or write operation is introduced.

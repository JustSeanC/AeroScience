## Approved product direction

Introduce read-only X-Plane 12 telemetry into the existing Windows x64 companion/dashboard and shared mission/science engine. Prefer Laminar's bundled REST/WebSocket API, with no additional plugin for core telemetry. The documented API floor is X-Plane **12.1.1**; support for particular builds remains subject to discovery, mapping checks and genuine acceptance. Do not promise every later build or every third-party aircraft from a documentation review.

The pilot selects **MSFS 2024** or **X-Plane 12** in Settings, launches that simulator and uses the existing dashboard. Existing preferences without a simulator choice continue to select MSFS. Begin with a clearly disclosed companion restart to apply a choice; refuse a change while recording or maintenance is active. No automatic source selection or fallback to synthetic telemetry.

Retain MSFS 2024 SimConnect, native toolbar, SDK bootstrap, CommBus limits/identity checks, aircraft/mission/revision checks and explicit toolbar installation. X-Plane mode must not initialize CommBus or require SimConnect to load. Offline plans, Library and archived Results remain usable with either simulator disconnected.

## Included implementation goals, after P01

- One small `AeroScience.XPlane` adapter using .NET HTTP/WebSocket/JSON facilities and the existing `ITelemetryProvider` stream.
- Explicit persisted simulator preference, local endpoint/optional advanced port, readable connection diagnostics and safe recovery.
- Complete valid core aircraft frames; individually optional atmosphere/guidance/environment channels with honest unavailable/stale states.
- Frozen simulator/adapter/mapping identity for new records, backward-readable legacy records and source-aware science provenance/exports.
- Reuse original mission plans, cards, recording, independently authorized science sessions, geometry, calibrated instruments, genuine-source Library/Results and organization services.
- Focused protocol, lifecycle, security, scientific validity and MSFS regression tests, followed by genuine Windows/X-Plane/MSFS acceptance.

## Exclusions

No X-Plane native panel, plugin, flight-control interface, dataref writes, command activation, flight initialization, simulator settings changes, firewall/network changes, internet-exposed connector, UDP fallback implementation, X-Plane 11 or pre-12.1.1 support. No macOS/Linux product support, simultaneous simulator recording, speculative providers or duplicate mission/science engine.

No new dropsondes, radar, storm/ocean/environmental mission suites or airborne image-capture implementation. Those remain separate [v0.9.0 proposals](v0.9.0-scope.md). No new automatic downloads, uploads, live-sharing/submission grants, account requirements, cloud services or original-source substitutions.

P01 creates plans and audits only: no adapter project/stub, runtime/model changes, migrations, packaging builds, installers, release publication or deployments. P02 does not start automatically.

## Scientific and privacy requirements

1. Preserve strict `TelemetryFrame.IsValid`; missing required numbers never become zero, NaN, carried-forward stale poses, MSL-as-AGL or synthetic movement. A real zero remains valid when actually reported.
2. Optional source absence is nullable/unavailable, not a fabricated reading. Discovery/connection success does not establish instrument readiness or valid science.
3. Normalize units with recorded mappings. Preserve simulator-reported versus derived/modeled versus historical external data, original units/hashes/UTC, calibration, datum limitations and source dates.
4. Keep host receipt UTC distinct from simulator time and historical acquisition time. Do not infer a simulated UTC year from the PC clock.
5. Preserve explicit recording versus Start/Arm/Pause/Resume/End Science, card focus/activation/evaluation, readiness, command receipts and permission checks. No X-Plane command can change the simulated aircraft.
6. Never stitch a route/corridor or graded hold through a connection gap, reload, teleport or unqualified clock/aircraft transition. Predicted geometry is not measured coverage; historical LiDAR is not newly emitted laser data.
7. Organization membership, evidence delivery/review and ephemeral live sharing retain their original independent authorizations. Source choice grants none of them.
8. Maintain local storage ownership, protected paths, migration/backup boundaries and permanent-deletion semantics. Scientific source access remains explicitly bounded and independent of simulator networking.

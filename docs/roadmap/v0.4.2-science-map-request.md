# AeroScience v0.4.2 — Science Map Addendum

**Repository:** https://github.com/JustSeanC/AeroScience

**Authoritative addendum:** `docs/roadmap/v0.4.2-science-map-addendum.md`

This is an additional requirement for the v0.4.2 UI/UX excellence implementation already underway. Preserve existing work and integrate this into the current Science Map redesign.

## 1. Fix "All Instruments"

The v0.4.1 Science Map offers an **All instruments** selection, but the frontend defaults to terrain elevation as its measurement even when multiple instrument types are selected.

As a result, thermal, multispectral and other available products may not be visualized because they do not support the elevation measurement.

Correct this inconsistency.

When **All instruments** is selected, users should see a genuine overview of all saved scientific instrument categories, including geographic footprints or valid mapped measurements where supported.

Provide clear independent layer controls for terrain, thermal, multispectral, hyperspectral and atmospheric data.

Do not combine incompatible scientific units into a misleading shared color scale.

Users must be able to select an instrument and its compatible scientific measurement for detailed inspection.

Automatically include available atmospheric geographic observations in the appropriate overview instead of requiring a separate obscure loading action.

Maintain source dates, quality, original values and provenance.

## 2. Remove Artificial Scientific Map Viewing Limits

The current frontend uses:

- 500 atmospheric observations per manual loading action.
- 12 geographic acquisition records per retrieval batch.
- An explicit 120-acquisition viewing ceiling.

These are pagination/display constraints, not underlying scientific recording limits.

The v0.4.2 user experience should allow users to explore **all saved scientific observations within their selected mission, sensor and geographic scope**.

Do not simply increase the maximum API response size or render thousands of individual markers simultaneously.

Implement scalable visualization using appropriate techniques, such as:

- Automatic bounded pagination.
- Viewport-based scientific retrieval.
- Scientific raster visualization.
- Zoom-dependent detail.
- Spatial clustering or density visualization.
- Incremental rendering.
- Background cancellation and caching.

The experience must remain responsive with thousands or more scientific observations.

If the map displays an aggregated representation, clearly communicate that it is an overview. Users must be able to zoom in or inspect the actual stored scientific values.

Do not silently omit saved data.

## 3. Improve Map Status and Counts

Display accurate distinctions between:

- Total available observations.
- Measurements currently loaded.
- Features displayed at the current zoom or geographic extent.
- Scientific acquisition records.
- Valid geographic cells.
- Missing or invalid data.

Ensure counts remain consistent as additional pages load.

Avoid presenting the last batch's valid-cell count as the overall total.

## 4. Preserve Scientific Accuracy

Maintain the distinction between:

- Simulator atmospheric observations.
- Valid sampled historical scientific pixels.
- Retained external source imagery.
- Modeled sensor geometry.
- Derived geographic composites.

Do not interpolate missing scientific observations, invent pixels or treat provider catalog coverage as aircraft-acquired data.

Exploring saved data must not initiate new external downloads without explicit user approval.

## 5. Required Tests

Create fixtures containing more than 500 atmospheric observations and more than 120 geographic acquisitions across several instruments and missions.

Verify that users can view the entire available geographic scope without repeated manual loading, while maintaining bounded memory and responsive rendering.

Test **All instruments** with terrain, thermal, multispectral and atmospheric data simultaneously.

Verify that each category is represented correctly, with valid measurement options and independent legends.

Test mission switching, instrument switching, pagination, zoom, viewport changes, offline operation and cancellation of stale requests.

Test desktop and tablet layouts.

Preserve original source values, quality masks, mission records, exports and scientific provenance.

## 6. Completion Evidence

Include this addendum in the v0.4.2 completion report.

Provide before/after screenshots and automated test results demonstrating:

1. All instruments genuinely appearing in the scientific overview.
2. A mission with more than 500 atmospheric observations being explored without manual 500-at-a-time clicks.
3. Geographic acquisitions beyond the former 120-item limit being accessible and visualized.
4. Large datasets remaining responsive.
5. Correct and understandable scientific legends, counts and source distinctions.

Do not claim the entire dataset is displayed if only a silently truncated subset is rendered.

**The objective is straightforward: users should be able to explore all the scientific data they've collected without wrestling with internal retrieval limitations.**

Continue the original v0.4.2 UI/UX implementation with these requirements included. Do not create GitHub issues or publish a release automatically.

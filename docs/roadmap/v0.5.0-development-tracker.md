## P03 implementation and next resume point

P03 extends the existing catalog/profile/configuration system (Shared DTOs, pure Missions
validation/arithmetic, existing Engine authorization and instrument editor). Optional fields
omit nulls, preserving old serialized shapes/hashes. Reference accuracy is Unknown or
Unavailable; metadata is never a certificate. Custom definitions have immutable revisions,
author/date/basis/units, canonical hashes and bounded atomic configuration storage. Corrupt
or unsupported settings are preserved and cannot be silently overwritten.

Opt-in `user-affine-1` supports only simulator temperature, pressure, wind-speed and density
scalar channels. Raw values remain bit-equivalent; derived rows have a distinct measurement
ID, Derived provenance, original-value/time linkage, full definition and hash. Wrong units,
unsupported methods/channels, nonfinite values, invalid applicability and physically invalid
results cannot become valid derivations. Missing derived output never discards valid raw
acquisition. External raster/spectral values, QA and camera geometry are untouched. Storage
estimates account for added rows/metadata. Derived rows must not count as independent
observations or extra Good Data credit in P08/P09.

API additions: authenticated calibration catalog GET and loopback/CSRF-protected revision
POST. Existing instrument/plan/preset APIs gain optional complete calibration settings.
Saving a revision does not apply it. Paired clients may select definitions but cannot create
them. Mission start/configuration snapshots, science JSON/CSV and replay retain original
revisions offline; the P02 `Effective` snapshot adapter is ready for P05 session integration.
Legacy history remains uncalibrated/unsegmented/ungraded. No migration, new source provider,
release, installer or change to main is part of P03.

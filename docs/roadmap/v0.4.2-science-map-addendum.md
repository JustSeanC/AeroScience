# AeroScience v0.4.2 — Science Map Addendum: All Instruments & All Saved Observations

**Status:** Owner-requested addendum to the **existing v0.4.2 UI/UX implementation**, 2026-10-19. Not a release/completion claim. Focus is using and accurately displaying **already recorded scientific mission data**, NOT new offline library downloads (the latter is scoped to `docs/roadmap/v0.5.0-backlog.md`). Do not automatically create issues or publish a release.

## UX-AD01 — 'All instruments' must actually work, with honest visualization

**Observed by user:** Selecting **All instruments** in Science Map does not appear to show all scientific results.

**Confirmed cause to investigate in current v0.4.1 source:** `science-workspace.js` sets an empty instrument filter for All, but defaults **Map measurement = elevation** unless a *single* thermal/multispectral instrument is selected. It then calls `/api/science/products/{id}/map-layer?measurement=elevation` for **every** returned acquisition, including thermal/multispectral products for which elevation is incompatible. Those failures are appended as text under Sources/Metadata while valid results from other instrument types may be absent from the map. Atmospheric observations are fetched only by an additional **Load Atmospheric Positions** action rather than included in a truthful combined All-instruments view. Thus the backend may select all, but the visualization only renders a compatible subset; this is an inconsistent **UI promise**, not evidence that other source data are missing.

**Required behavior:**
- Define clearly distinct modes:
  1. **All instruments overview:** A geographical overview with one independently legible overlay/status per instrument (terrain, thermal, multispectral, hyperspectral, atmosphere, etc. where saved data exist), with filters, visibility, legends, counts and an explicit instrument-level list. Draw spatial footprints, geolocated values, or appropriately styled previews; do **not** merge incompatible values or wavelengths into one color scale.
  2. **Selected instrument + measurement:** Dedicated real scientific map/raster for one scientifically meaningful quantity (e.g. terrain elevation, thermal K/°C, NDVI, hyperspectral band, wind speed). Choosing instrument updates to a supported default measurement and available measurement options.
- Opening All instruments should include recorded atmospheric points/paths where present and visually distinguish scientific category. If no saved atmospheric data exist, show the empty category accurately.
- All instruments must not quietly render only elevation while claiming to aggregate all instruments. If technically only one scientific raster layer can be displayed at a time, clearly label the selected active measurement while still showing *all* enabled instrument footprints/layer controls and summaries.
- Show compatible source values, QA masks, source date, units and no-data states. Provider catalog or retained library coverage must not be shown as fully flown mission-acquired valid science.
- User-selected mission scope, dates, instrument toggles, and map state remain consistent across filtering/navigation. Correctly report excluded/incompatible visual layers explicitly in the visible summary, not just deep metadata.
- Add functional regression fixtures with **one mission and three distinct instrument sources** (elevation, thermal, multispectral) plus atmospheric observations, and a second mission. Verify All reports all four (with appropriate distinct rendering) and each single-instrument mode only compatible values.

## UX-AD02 — View all available mission science without the 500-point / 120-acquisition interactive ceiling

**Observed by user:** The Science Map apparently shows only 500 data points at a time and requires repeated clicks to load more. Users should be able to view **all of their saved science**, subject to practical rendering performance, without a silent partial visualization.

**Confirmed current frontend limitations:**
- Atmospheric Map requests `limit:500` per click of **Load Atmospheric Positions** (`science-workspace.js`, `atmosphereAfter`); the server supports bounded paging with a max 1,000 rows per request (`ScientificAtmosphereMap.cs`). This **does not mean only 500 observations are stored**.
- Geographic Map requests `limit:12` indexed acquisitions per batch; `Load More Acquired Science` stops at **120 acquired items per view** (`count>=120`), despite the server exposing paginated records in `ScientificWorkspace.cs`. This is a **frontend display ceiling**, not a mission retention/recording ceiling.
- Currently count of `valid native cells added` is per latest page while the acquisition count accumulates; this creates a misleading status after more results load.

**Required user experience:**
- **Automatically load and visualize the full selected dataset scope** (mission, date, instrument, valid quality) through bounded background pagination and/or a spatially indexed/viewport-based representation. Do not require repeatedly pressing Load More simply to see all normal sized saved results.
- Keep server pages bounded, rendering incremental and cancellation robust. For large datasets use viewport/zoom aggregation, native-raster tiles, clustering, density maps, progressive/virtualized point display, or other defensible LOD techniques. Avoid putting a million Leaflet individual circle markers or polygons on screen; preserve full-resolution inspectability when the user zooms/requests detail.
- Provide visible **Total available / Loaded / Displayed at current zoom or viewport** counts, per instrument and measurement when useful. Clearly distinguish number of measurement values, timestamps, acquisition records, valid native cells, unique positions and scene/pixel coverage; do not equate them.
- Support **All Missions** with larger saved archives, not just the newest 100 in a mission dropdown. Keep index queries bounded/paginated, selection explicit and efficient.
- Remove the arbitrary **120-item user-visible hard stop** by adding true scaling/aggregation mechanisms rather than recklessly increasing response limits. Always show an honest `More data outside current view / zoom in / filter` explanation when drawing fewer features than exist. Do not claim the map shows all original individual points when it's showing a downsampled summary.
- For atmosphere, fetch more than one 500-row page *automatically or on demand from viewport* and provide suitable clustering/aggregation with an accessible searchable observation table. Preserve original UTC, quality, units and geographic positions. Never interpolate through missing telemetry or atmospheric observations.
- For remote sensing, reuse existing true numeric raster/native-grid and spatial indexes rather than fetching thousands of fully expanded polygons into browser memory. Ensure on-map sampled valid cells versus source-only coverage remain distinguishable.
- Do not silently download new external datasets when exploring archived results. Library manual download is a separate v0.5.0 feature.
- Make asynchronous work cancellable and resilient to user switching sensor/mission/date or page; avoid stale overlay/results and unbounded memory growth. Preserve offline behavior.
- Ensure combined data can be **fitted to extent**, independently inspected, legend-readable and, where appropriate, exported with complete underlying observations even if the visible map uses aggregation.

**Acceptance:**
1. Fixture contains **more than 500** geolocated atmospheric observations (including multiple categories) and >120 geographical acquisition records. Open Science Map, select scope, observe meaningful full-extent aggregated view without 500-at-a-time manual clicks or 120-plot hard ceiling; counts are honest.
2. Include stress tests (several thousand+ observation values across missions); confirm bounded memory/render time and no catastrophic freeze. The test may use representative synthetic volume, labeled as fixture data.
3. Confirm all supported instrument types appear under All instruments, each with correct independent measurement/legend or footprint, and switching to a single sensor shows compatible values and no silent loss.
4. Validate consistent cumulative count across pages; no double-count from duplicate source support or repeated records; missing data remains missing.
5. Offline archived review, source provenance, data quality, source dates, complete exports, data unchanged; desktop and physical tablet acceptance pending separately.

**UX framing:** This is a v0.4.2 science-review usability/completeness repair, not an extension of instrument calibration or v0.5.0 geographical source download scope. Preserve 9/10 aspirational UX target, with real acceptance evidence rather than self-assigned scores.

Run focused tests while developing each stage. Run Full CI on the completed integrated runtime before P06's exact candidate; retain diagnosed failures and justify any corrective rerun. - **Goal:** establish a bounded, source-backed implementation design without runtime changes.
- **Tasks/components:** five v0.8.1 documents, documentation index, current-main/release audit, Issue #14 history/update, official API/catalog and existing recorder/science/settings/evidence audit.
- **Dependencies:** accepted v0.8.0 runtime and current `main`; no installed X-Plane required for a research-only result.
- **Checks:** validate local links/paths/fences, exact dataref spelling/native units/introduction versions against the official catalog, cross-document decisions and final docs-only diff. No installer or unrelated full-suite execution.
- **Acceptance / Definition of Done:** all requested audit questions addressed, mappings and unknowns explicit, P02 ready for fixture-first implementation, reviewable PR targeting `main`, #14 retained as the umbrella rather than closed as shipped support.
- **Risks:** evolving API/catalog and lack of actual simulator proof; report these limitations.
- **Owner action:** review the proposed architecture/PR. No simulator setting, installation or scientific file needs changing for P01.

## P02 — X-Plane telemetry provider

- **Goal:** implement the dependency-light read-only adapter and bounded protocol/state handling.
- **Specific tasks:** add `AeroScience.XPlane`, options/client/dataref catalog/snapshot assembler/provider; retain `ITelemetryProvider.ReadAsync`; add optional origin/sample context contracts; discovery by stable name, exact numeric types/units and base64 strings; acknowledgements/full seed/delta cache; confirmation/freshness windows, cancellation/backoff, reload/epoch transitions and explicit capability gaps. Do not expose X-Plane science through production registration yet.
- **Expected files:** proposed `src/AeroScience.XPlane/*.cs`/project, solution/test project references, optional additions to `src/AeroScience.Shared/Models.cs`, `tests/AeroScience.Tests/XPlane*Tests.cs` and clearly labeled synthetic protocol fixtures. No duplicate recorder/science/organization code.
- **Dependencies:** P01 mapping and lifecycle decisions; recheck official API and current branch before editing. No API write interface or plugin dependency.
- **Tests:** v1 discovery and legacy capabilities-404; newer capabilities advertising v1; unsupported versions/403/refusal; ID precision, pagination/type/byte/array bounds; ack-before/after-seed and error results; changed versus unchanged fields; missing core versus optional channels; constant stationary/atmospheric values; delayed reads, stale/old-epoch replies, shutdown/reconnect, clock reset/replay/aircraft transition; exact unit conversions and candidate attitude signs; strict no POST/PATCH/set/command traffic; non-loopback/redirect/proxy refusal; bounded queues/resources with slow consumers.
- **Acceptance / Definition of Done:** provider emits only qualified valid frames or honest status/optional-quality updates, preserves original shared checks, and all focused tests pass with reproducible fixture receipts. No invented real API or performance acceptance. A live-clock/confirmation policy that cannot be justified must remain a blocker to scientific eligibility, not be papered over with cached timestamps.
- **Risks:** minimum-build differences, loading/clock semantics, incomplete/changed-value composites, native angle reference and third-party values.
- **Owner action:** none required for automated implementation. An optional later controlled read-only API capture must be explicitly identified as genuine, source/build-bound and privately reviewed; P02 fixture success does not require or imply that capture.

- **Owner action:** later Windows preference/startup/connection UX observation on a separate development candidate; no accepted beta profile adoption.

## P04 — Mission and scientific integration

- **Goal:** feed existing research with scientifically qualified, correctly attributed simulator data.
- **Specific tasks:** minimum versioned origin persistence before new X-Plane recording; source-aware new dataset definitions/source labels/timestamp basis; propagate environment/guidance origin through enrichment; capability-based readiness and explicit unsupported channels; verify source/epoch/aircraft changes, geometry signs/AGL/true heading/track, gaps/teleports/paused/replay/accelerated-time evidence. Preserve legacy versus explicit armed science policies and independent card actions. Reuse current collection/session/research/analysis/Library/organization controllers and original calibration, grants, receipts and revisions.
- **Expected files:** `MissionCoordinator.cs`, `MissionStore.cs` plus a small origin persistence partial, `ResearchOperations.cs`, `ScienceStore.cs`, `ScienceCatalog.cs`, `EnvironmentTelemetryCache.cs`, shared metadata and original source/readiness projections, relevant export/evidence contracts and server verification where required. The recording/collection/geometry algorithms are not replaced.
- **Dependencies:** P02/P03; confirm the next schema/version before implementing (current mission schema 13). Additive migration tested first on disposable copies. Source-specific scientific labels must be fixed before enabling collection; updating UI names alone is insufficient.
- **Tests:** original `MissionTests`, `MissionScienceTests`, `ResearchTests`, atmospheric/collection/geometry/sensor/terrain suites plus X-Plane cases; missing AGL and environment, stale/mixed-age snapshots, disconnected/paused/replay states; no new acquisition from re-timestamped cache or imagined movement; no corridor/hold across transition; raw recording versus science-paused state; multi-session/card identities and recorded attempt evidence; new versus legacy origin and unchanged old hashes; explicit organization submission/live-sharing consent and independent review.
- **Acceptance / Definition of Done:** every newly persisted flight/dataset/observation accurately identifies simulator/channel/time basis; unknown channels stay unavailable; no altered original evidence or numerical source dataset; focused scientific/security regression passes. Any unsupported cloud/guidance channel is disclosed and cannot earn fabricated card credit.
- **Risks:** hardcoded MSFS defaults, ambiguous historical source records, temporal grading/corridor continuity and strict server evidence versions.
- **Owner action:** prepare a small later genuine comparison flight and retained source examples; actual channel/geometry correctness is still a P06 gate.

## P06 — Real simulator validation and release acceptance

- **Goal:** establish real Windows x64 compatibility for named X-Plane builds and preserve MSFS acceptance.
- **Tasks/components:** owner-friendly graphical acceptance guide, exact-source/candidate receipts, genuine input comparisons, long-flight/resource measurements, security/consent and MSFS toolbar regression; honest supported/unsupported matrix, known issues and release readiness. Reuse original acceptance discipline; synthetic captures are explicitly labeled.
- **Dependencies:** P05 green integrated runtime; separately authorized candidate build/profile and runtime redistribution/signing gates. CI is necessary but cannot pass installed simulator rows.
- **Tests/observations:** follow the matrix below; failed/blocked/not-tested rows remain such with meaningful notes and actual source/build/installer hashes. Retain diagnostics and fix confirmed failures without weakening requirements.
- **Acceptance / Definition of Done:** owner-observed exact candidate passes agreed core Windows/X-Plane and MSFS scenarios; unresolved scientific capabilities are restricted/disclosed; performance is measured with method/hardware/duration, not guessed; release decision is reviewable and explicitly approved separately. Do not publish/merge automatically.
- **Risks:** installed security defaults, supported version/aircraft combinations, native prerequisites, optical/terrain reference semantics and timing under low FPS/acceleration.
- **Owner actions:** use a separate candidate/test account or approved disposable data copies; report exact Windows/X-Plane build and installation channel, selected default/third-party aircraft, port/security state and retained source identities. Never upload unreviewed location traces, credentials or original scientific files publicly.

### Genuine acceptance matrix and owner preparation

| Session | What the owner actually needs to observe / retain |
|---|---|
| Identity and connection | Exact candidate source/EXE hash, configured simulator, X-Plane build/API version, default/custom port; no extra plugin installed for core telemetry. Record current Network security before any deliberate user change. |
| Offline/disabled/loading | Neither simulator open, API refused/403, initial menu and return to menu after a flight; offline plans/Library/Results work, no synthetic/live pose appears. |
| Aircraft readings | Fixed-wing, helicopter where available and one chosen third-party aircraft; independent readout comparisons for lat/lon, MSL/AGL, IAS/TAS/GS/Mach/VS, true heading/track, nose-up/down and left/right bank. Include crosswind/low-speed and a second altitude/location. |
| Atmosphere | Genuine local API readings of ambient temperature, pressure, effective wind and density where present; compare source values/conversions and actual UTC/position association. Record missing channels honestly. Weather presets/ATIS are not numeric ground truth. |
| Time and transitions | Pause/resume, replay, menu/load, same-aircraft reload, aircraft change, reconnect and process restart, teleport, requested/actual and distance acceleration; no old-field blending, backfill, joined corridor or false hold credit. |
| Research operations | Start recording independently from approved science controls; armed/waiting/collecting/paused/resumed/ended, multiple sessions/cards/attempts; pause science while recording continues. |
| Genuine retained science | Reopen a known genuine terrain and historical LiDAR/source-backed result using existing approved files. Confirm source dates/datum/hash and original-versus-derived distinctions; no new download authorization implied. |
| Source identity/recovery | Save/reopen/export, restart interruption and origin metadata; legacy records retain original bytes/unknown identity. Test migrations/deletion only on authorized disposable copies. |
| Security/organizations | No dataref/command writes, remote endpoint exposure or automatic settings changes; sharing/submission/download choices remain independent; received/reviewed states and revoked/expired membership remain authoritative. |
| MSFS regression | Select MSFS after ending the flight/restarting companion; exact existing provider/native toolbar connect/reopen/resize/commands/map/cards, original recording/science/source identity checks and offline behavior. Both sims running must not change the selected source. |
| Endurance/resources | 30–60 minutes with recorded hardware/build, received/committed/missing counts, cadence/window age, reconnection, CPU/memory/queue trend and limits. No unsupported overhead/FPS claims. |
| UX/accessibility | Persistent choice and independent language/theme/units, clear status beyond color, keyboard/focus/narrow display, optional advanced port, recovery instructions; no X-Plane panel or required developer tools for normal pilots. |

The owner need not perform these sessions during P01. P06 must supply the simple graphical checklist/tools; this research document does not ask the owner to manually poll datarefs or edit simulator files now.

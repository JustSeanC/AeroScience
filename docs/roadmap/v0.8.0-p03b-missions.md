## Delivered workflow

- **Explore** is now the complete #missions entry. Six supported starter families use plain-language titles, their actual typed questions, task difficulty guidance, objectives, aircraft/input requirements, original catalog instrument names and source requirements. Exact quantitative criteria and scientific interpretation limits remain one disclosure away. Difficulty describes the task; it is not aircraft certification, a readiness finding or a scientific grade.
- **Fly Now** calls the existing durable starter preparation and selection pipeline, then opens **Prepare**. It starts no recording, science, transfer, sharing or submission. **Customize** still opens an independent editable copy in the original full planner, with its existing dirty-draft/geometry confirmation and retry identity.
- **Prepare** reads the exact saved plan and all selected card IDs/revisions. It shows original objective, geometry, enabled instruments, simulator/selection status, existing data-preparation/consent tools and the existing readiness assessment. Missing, stale, unsupported or mismatched information remains unconfirmed; no fallback unplanned flight or synthetic readiness/result is supplied.
- **Review recording controls** opens the original Current Flight controls. For a fresh matching selection without an active flight, the guided action sets only the original conservative **Arm science without starting collection** form option. It does not save the plan, call an arm endpoint or record. The original **Start Recording** controller still checks selected identity, frozen revision, readiness, maintenance and permissions. Collection waits for the separate original **Start Science Collection** action. Existing advanced plan/automation policies and legacy startup behavior are retained.
- Selected plans and a bounded preview of saved experiments link to exact saved work. **My experiments & templates**, **Saved mission plans**, **Full mission planner**, **Sensors & calibration** and **Organizations** remain named escapes to complete original controllers. The original paged inventory, custom experiments, compound/procedure cards, imports, cloning, versions and reviews remain available.

The application's single SSE supplies current identity to Prepare. View-owned bounded GETs have six-second deadlines, plan refresh is five seconds, stale receipt state expires after six seconds, and the existing readiness context check remains ten seconds. Disposal/hiding invalidates reads and assessments. Polls preserve focused controls; guided page transitions start at the top rather than retaining a card's old scroll position.

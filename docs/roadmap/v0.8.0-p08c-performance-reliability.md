The Linux worker has a two-CPU cgroup quota and 8 GiB memory limit (three visible logical CPUs). Before running, the resource harness declares a 300-second operation budget, 512 MiB **sampled process-tree** RSS budget, 256 MiB output-growth budget and 256 MiB free-space floor. These are conservative local engineering budgets for these small/medium operations. They are not source accuracy, universal dataset-size, native frame-rate or aircraft-speed guarantees.

[`p08c_resources.py`](../../scripts/validation/p08c_resources.py) samples only its owned subprocess tree using already installed psutil. It records elapsed time, sampled RSS/CPU/disk counters, actual final output growth, sampled temporary growth, tool/OS identity and sampling limitations. A budget stop kills only those owned child processes, retains diagnostics and fails. The existing source/processing bounds remain authoritative; sampling cannot enforce instantaneous kernel limits. GNU time high-water data is recorded only if that tool already exists; it was unavailable here and was not installed. Unknown disk counters remain null, never zero. Network zero denotes the existing offline probe contract, not a packet-capture claim.

The first medium run took **17.345 s**, sampled **84,504,576 bytes** peak tree RSS and produced **5,254,698 bytes** output growth. The repeat took **18.838 s**, sampled **84,013,056 bytes** and reproduced the same 109 original records with maximum independent XY difference `2.842170943040401e-14°`. Both reference stages and resource artifacts are retained separately. Reference-tool time is not reported as application processing time. [Machine-readable resource receipt](p08c-review/resources.json).

Original seed files are never handed to the mutating retained-job probe: the harness verifies metadata/hashes, checks its size budget and creates a fresh disposable copy. Repeated processing changes only that copy. The original retained source hashes are rechecked afterward. No source permission, retained original, acquisition count or organization credit is changed by benchmarking.

## Results and exports

The original `SurveyViewProbe`, `capture-survey-view.mjs` and `verify-survey-views.py` exercised genuine historical points and a genuine USGS raster with synthetic archived flight geometry. All 12 light/dark, 1440/390 px captures passed. The browser loaded 12,084 actual points / 16,776,250 encoded numerical bytes; heap after GC was 56,054,732 bytes. Initial Explore took 1.545 s; recorded orbit interaction was 62–75 ms on headless software WebGL. These are browser observations, not native GPU frame rates.

Independent GDAL verified 576 API cells, 143 valid profile values / 114 gaps and all 513 CSV samples. The point oracle verified all 12,084 loaded records and CSV values against the 38,260-record original, with exact raw attributes and a maximum geographic difference `2.842170943040401e-14°`; profile ground-distance error was `1.5443646361745778e-9 m`. Decimation does not change original counts. Unknown datum/Z units remain unknown. Deleting **only the disposable fixture's** managed original through the existing preview/execute controllers cleared numerical displays and blocked later artifact access.

The additional 20 targeted browser checks passed, including WebGL refusal/2D/table fallback, cancellation/stale response handling, scientific values/exports, narrow light/dark/200% text profiles and source download/hold/status semantics. No assertion was weakened. Captures are labeled genuine historical data / synthetic flight / Chromium / not installed MSFS.

## Confirmed tool failure and correction

Two small LAZ measurement attempts stopped because `/proc/<child>/io` denied a disk-counter read. The preserved traceback identifies `psutil.AccessDenied`, not an application decoding failure. Disk counters are informational and separate from memory/time/output bounds. The sampler now explicitly marks unavailable counters unknown; a focused regression verifies that they cannot become zero-byte claims. RSS/CPU availability remains required for the benchmark. The corrected genuine run passed. Failed attempt receipts/logs remain retained and are hashed in the resource summary.

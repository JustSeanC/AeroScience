## Connection protocol and security

Default endpoint: explicit `127.0.0.1:8086`; canonical `::1` is also supported by options. There is no DNS, port scan, URL setting, LAN connection, listener or configuration write. Port must be 1–65535. An internal ephemeral-loopback test server is test infrastructure only.

1. GET `/api/capabilities`. Prefer advertised `v1`; accept advertised `v2` for its common read contract when v1 is absent. A legacy capabilities 404 permits v1 discovery; a 403, redirect, malformed contract or unknown-only API version does not permit fallback. The documented target floor is X-Plane 12.1.1/API v1, **not an installed compatibility certification**.
2. Discover each exact fixed name with GET `/api/vN/datarefs?filter[name]=...&start=...&limit=...`. Validate ID, exact name and native type. IDs remain Int64, including values above 2^53, and are discarded on every new epoch. Default page size is 64, at most four pages per name; arrays/objects have separate bounds.
3. Open `ws://<explicit-loopback>:<port>/api/vN`. Send only `dataref_subscribe_values` and `dataref_unsubscribe_values`, with unique positive request IDs no greater than 2,147,483,647 and discovered IDs only. Require the matching successful result and complete required seed, in either arrival order.
4. Receive every changed-value delta into a fixed-ID cache. Independently confirm current values with GET `/api/vN/datarefs/{id}/value`; do not reinterpret a WebSocket heartbeat as a new measurement.

HTTP has no POST/PATCH/PUT/DELETE path. No dataref writes, simulator commands, aircraft manipulation, plugin installation, firewall changes or unrelated AeroScience network operations are available. Both HTTP and WebSocket handshakes use handlers with redirects, proxies and cookies disabled. Canonical-address validation rejects hostnames, URLs, credentials, remote addresses, abbreviated IPv4 and mapped IPv6. HTTP or handshake 403 remains `Unavailable/ApiAccessDenied`; queued confirmations cancel after a denied/broken contract. Nothing bypasses X-Plane's security setting.

Default response/message bound is 65,536 bytes, checked while streaming and across WebSocket fragments. JSON depth is 12, arrays/objects at most 128 entries; malformed numeric IDs, duplicate names/IDs/properties, binary WebSocket messages and malformed UTF-8/base64 identities fail closed. Scalar mappings do not take an element from a received array.

## Telemetry and units

Core position/attitude fields: latitude, longitude, MSL altitude, IAS, TAS, groundspeed, true heading, true ground track, pitch, bank and vertical speed. Pause, replay, running/flight clocks and a valid aircraft description are required for candidate qualification. Optional AGL, Mach, registration, ICAO type, build, clock components and rate context remain nullable/unavailable.

P02 deliberately requires the valid `acf_descrip` identity rather than the P01 table's possible unknown-display-label fallback. This conservative restriction avoids filling a required `TelemetryFrame.Aircraft` with a substitute identity. Missing/invalid identity produces status-only output; accepting an explicit unknown identity is deferred to a source-aware integration decision. No alternate dataref was introduced.

| Input | Normalized output |
|---|---|
| MSL / optional AGL metres | Feet: divide by 0.3048; never substitute MSL for missing AGL |
| TAS / groundspeed / wind m/s | Knots: multiply by 3600/1852 |
| IAS kias | Already knots; no second conversion |
| Vertical speed m/s | ft/min: multiply by 60/0.3048 |
| True heading / track degrees | Normalize modulo 360; do not use magnetic/local heading |
| Pitch / bank degrees | Candidate direct signs; no copied SimConnect inversion; genuine attitude/geometry qualification pending |
| Temperature °C | Preserve reported value |
| Static pressure Pa | inHg: divide by 3386.389 |
| Density kg/m³ | slug/ft³: multiply by 0.028316846592/14.5939029372064 |

Five optional atmospheric scalars are implemented from the documented aircraft-local temperature, static pressure, effective wind speed/direction and legacy `sim/weather/rho` density mappings. They are explicitly **simulator-reported**, not independently verified atmospheric measurements. Missing or invalid scalar values remain null; all missing gives `ObservationQuality.Unavailable`. Paused output is explicitly paused.

No humidity, cloud density, in-cloud state, precipitation category, wind-vector conversion, ambient visibility equivalence, detailed guidance, inferred ground elevation or replacement weather model is populated. No scientific instrument calculation changed. Atmospheric-family compatibility, vertical-speed lag/sign, density, calm-wind meaning and aircraft-specific reference frames still require real X-Plane comparison.

## Snapshot qualification and time

Defaults are engineering hypotheses from the P01 design, not measured simulator guarantees:

- Explicit confirmation group every 1 second, concurrency at most four (configurable 1–8).
- Required read group spans at most 500 ms; every required confirmation is at most 2 seconds old. The context records both full and core spans; no atomic-snapshot claim.
- Optional reads share the 500 ms deadline. Slow/unavailable optional channels cannot indefinitely hold core position. An optional value outside the core association window is unavailable. Atmospheric/position receipt separation therefore stays within the existing 3-second association ceiling.
- `LastChangedUtc`, `LastReceivedUtc` and `LastConfirmedUtc` are separate. Unchanged values, including zero groundspeed, are valid when actually confirmed with qualified simulator-clock progress.
- Every emitted frame corresponds to a new confirmed group. A timer, cached delta, repeated consumer call or heartbeat cannot duplicate a group or mint a 1 Hz flight sample. A 100 ms status-only watchdog clears stale eligibility while a longer request is pending.
- A late-assembled GET cannot move a newer WebSocket receipt/change time backward. A known newer pause delta blocks an older unpaused group until confirmation catches up. Live clock rollback/replay/rate transitions invalidate the epoch before further output.
- Frame timestamps are **actual last-required-field host receipt UTC**, offset zero. Optional completion cannot redate position. Monotonic time measures freshness/deadlines; simulator running time, flight time, reported Zulu/day and requested/actual/distance rates remain separate context.

The simulator UTC year remains null. Local day plus Zulu seconds are not turned into an invented UTC date. No host-year substitution, accelerated-time sample multiplication or backfill occurs. An unpaused clock must have real recent running/flight progression; a freshly confirmed paused state may remain Connected/paused but cannot supply live science. API connectivity alone does not prove a loaded/live aircraft; status text and capabilities retain that unverified limitation.

Missing, invalid, expired or mixed-age required fields yield status-only `Initializing`, which clears the existing coordinator pose rather than preserving it under `Connected + null`. `TelemetryFrame.IsValid` and its existing required-field/UTC rules are unchanged.

## Epochs, recovery and bounded resources

Initializing precedes negotiation. Valid qualified composites report candidate Connected; transport loss/timeouts report Disconnected; denied/unsupported/malformed contracts report Unavailable. Empty initial registries and incomplete/stale frames remain Initializing, with explicit reason codes.

Every reconnect gets a new GUID epoch, renegotiates, rediscovers names/IDs, resubscribes and requires a new seed/ack/read group. Required-ID 404 loss forces rediscovery. Old-epoch assembler calls and unrelated acknowledgements cannot qualify a new session.

Aircraft description/path-token changes, clock rollback, replay and requested/distance-rate changes invalidate continuity. A speed/elapsed-time comparison plus a configurable 1,000 m diagnostic tolerance identifies large position-jump candidates; this is not a safe-speed limit or proof that every teleport is detected. Actual-rate variation is retained as context rather than assumed to be exact 1x. No new epoch is declared continuous with the preceding flight.

Retries use cancellable **1/2/5/10/30 second** backoff, capped at 30 seconds. The cache holds only the 34 fixed possible channels. All deltas are applied before wakeups are coalesced into a single slot; slow consumers inspect current qualification rather than a replayed frame backlog. No archive or unbounded message queue exists.

Cancellation interrupts discovery, reads, socket waits and backoff. Orderly disposal attempts bounded unsubscribe, then cancels/aborts background work. Default request deadline is 3 seconds and independent shutdown budget 1 second; an already-aborted socket cannot promise an unsubscribe receipt. No shutdown waits indefinitely for the simulator.

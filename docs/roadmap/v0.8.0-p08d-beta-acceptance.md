# v0.8.0 Beta 1 — Owner build and basic acceptance

These are owner/builder instructions. Testers receive one installer and the short [tester guide](../beta/v0.8.0-beta.1/START-HERE.html); they do not run Git, Python or SDK tools. Exact accepted source and Full CI run are listed in [the handoff](v0.8.0-p08d-handoff.md).

## 1. Build a fresh candidate

Use **Visual Studio x64 Developer PowerShell**, with MSFS closed. The build PC needs the genuine MSFS 2024 SDK, .NET SDK from `global.json`, Node 22+, Python 3, Git, Inno Setup 6.3+, an existing hash-bound runtime approval record, at least the preflight's free disk space and the actual signed Microsoft VC v14 x64 installer. The script downloads no SDK/runtime/compiler/prerequisite. Normal locked NuGet/npm build restores still require their configured package services.

Create a separate source worktree so your current source and installed validation remain intact. Replace the two values below with the **accepted runtime source and Full CI run in the handoff**. Keep the real local VC prerequisite path; do not create a placeholder.

```powershell
$ErrorActionPreference = 'Stop'
$PSNativeCommandUseErrorActionPreference = $true
$betaSource = '<accepted 40-character runtime SHA from the handoff>'
$fullCiRun = <accepted Full CI run number from the handoff>
$existingSource = 'C:\Dev\AeroScience-080-Fixed-20261115-095408'
$betaCheckout = Join-Path 'C:\Dev' ('AeroScience-080-Beta1-' + (Get-Date -Format 'yyyyMMdd-HHmmss'))
git -C $existingSource fetch origin develop/v0.8.0
git -C $existingSource worktree add --detach $betaCheckout $betaSource
Set-Location $betaCheckout
$betaOutput = Join-Path 'C:\AeroScience-Builds' ('Beta080-' + (Get-Date -Format 'yyyyMMdd-HHmmss'))
$vcPrerequisite = 'C:\AeroScience-Release-Records\VC_redist.x64.exe'
pwsh -NoProfile -File .\scripts\release\Build-080BetaCandidate.ps1 `
  -ExpectedSourceCommit $betaSource -FullCiRunId $fullCiRun `
  -OutputDirectory $betaOutput -SdkRoot 'C:\MSFS 2024 SDK' `
  -RuntimeApprovalRecord 'C:\AeroScience-Release-Records\runtime-approval.json' `
  -RuntimeRedistributionConfirmed -VcRuntimePath $vcPrerequisite `
  -AllowUnsignedBeta
```

The shown flag is an **explicit unsigned-beta build choice**: it records honest `NotSigned` status for locally built beta binaries and permits Windows reputation warnings. Omit it to enforce valid signatures; this source-build pathway does not obtain a certificate or sign binaries for you. A fully signed path needs signing integrated before helper hashes/embedded identity/payload sealing and separately verified. Do not disable Windows security or describe an unsigned installer as signed.

If preflight names a blocker, follow that message. Keep the failed output/logs and choose a new `Beta080-*` attempt for a rebuild. Never reuse a partial receipt or erase previous validation. Do not rerun full CI merely to retry a local SDK build against unchanged source. Leave MSFS closed until packaging finishes.

## 2. Test these exact installer bytes

After a successful build, keep the entire build folder privately. `$betaOutput\installer-candidate` contains the installer, checksum, sealed payload, `BETA080-INSTALLER.json` and untested acceptance template. The parent holds logs, preflight and exact Full CI proof. Preserve and independently copy the **installer receipt SHA-256**, which is separate from the EXE checksum:

```powershell
$candidate = Join-Path $betaOutput 'installer-candidate'
$receiptHash = (Get-FileHash (Join-Path $candidate 'BETA080-INSTALLER.json') -Algorithm SHA256).Hash.ToLowerInvariant()
Write-Host "Keep this installer receipt hash: $receiptHash"
pwsh -NoProfile -File .\scripts\release\Open-080BetaAcceptance.ps1 `
  -CandidateFolder $candidate -ExpectedSourceCommit $betaSource `
  -ExpectedReceiptSha256 $receiptHash
```

Use an isolated Windows test account/VM/PC with MSFS for the native checks; do not replace your active tester installation. Install the exact EXE yourself. In the checklist choose **Verify installed files** and select the installed Beta 1 folder (the folder containing `application`). This reads actual installed bytes and runs the decoder; it does not start the companion or simulator. Keep this proof before uninstalling.

Go down the eight named rows. Record what you actually saw, choose Passed/Failed/Blocked/Not Tested, tick personal observation and **Save my results**. No test-ID typing is needed. A note such as “yes” cannot establish a pass. In particular:

1. Verify Beta 1 name/version/source, separate folder/port and matching toolbar identity.
2. Check setup, normal prerequisite prompt, installed files and the short guide.
3. Check existing companion, research, settings and Community package are unchanged.
4. Install only the beta toolbar through beta Settings with MSFS closed; then open/reopen/resize/connect in real MSFS.
5. Record a short flight; separately arm/start/pause/resume/end science. Confirm pausing science leaves recording active and saved results reopen.
6. Open genuine retained terrain and historical LiDAR; verify original-versus-derived/source information and missing-data honesty. P08c numerical checks are retained separately.
7. Check explicit source/network permissions and deletion/sharing/submission consent using disposable copies where deletion is exercised. Do not delete your only originals.
8. With MSFS closed remove only the beta toolbar using beta Settings, close beta and uninstall the beta app. Confirm beta research/settings and other installations remain. Reopen your existing companion explicitly.

Long flights, broad source combinations, large datasets and fluent translation review are optional beta cards, not extra basic checklist hurdles. Any observed critical corruption/privacy/security/install problem blocks distribution regardless of other results.

## 3. Export readiness, then seek distribution approval

Choose **Export observed acceptance** after saving. Use its exact displayed filename:

```powershell
$observations = '<full OBSERVED-ACCEPTANCE filename shown by the checklist>'
$readiness = Join-Path $betaOutput ('readiness-observed-' + (Get-Date -Format 'yyyyMMdd-HHmmss') + '.json')
python .\scripts\release\beta_release_080.py readiness `
  --folder $candidate --source $betaSource --acceptance $observations `
  --ci (Join-Path $betaOutput 'full-ci.json') --report $readiness
```

Review `distribution_ready`, every required check, critical defects and deferred cards. It must identify the exact EXE and source. `publication_approved` remains false: send the owner the checksum, readiness report and observations for explicit approval. Do not upload private build folders, SDK/runtime approvals, scientific originals or diagnostic records to Releases.

Only after that approval, distribute the exact `AeroScience-Setup-v0.8.0-beta.1.exe` plus its `.sha256`, the tester guide, known issues/cards and beta notes. Use a clearly marked GitHub **prerelease** if the owner chooses GitHub; use the matching accepted source for the tag. Publication/tagging is a separate action and is not performed by these scripts. Do not distribute the earlier private-validation ZIP as this beta.

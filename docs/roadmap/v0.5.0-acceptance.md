# v0.5.0 feature acceptance and evidence plan

**Planned criteria; no v0.5.0 feature is accepted by this document.** Scope is in
[requirements](v0.5.0-scope.md), execution order in [the PR plan](v0.5.0-implementation-plan.md).
All entries start **Pending**. A future result must name the source commit, test/data
inputs, observed outcome and applicable platform, not just a test count.

## Evidence classes and baseline protection

- **UNIT:** deterministic rule/model/geometry tests with explicitly labeled fixtures.
- **INTEGRATION:** actual local services/stores/worker/browser/protocol processes, including
  crash recovery and persisted data; mocked NASA/STAC is still a test fixture.
- **GENUINE:** actual provider/granule/file/authorized workflow and independently checked
  numeric metadata/values. Synthetic aircraft input stays labeled separately from source data.
- **LIVE:** exact installed Windows candidate with MSFS/real aircraft, physical iPad Safari
  or Quest 3 as specified; actual telemetry versus synthetic host is identified.

This documentation PR performs documentation and branch-isolation checks only. Existing
v0.4.2 counts/reports are historical baselines, not new executions or v0.5.0 acceptance.
Keep baseline tests/fixtures unchanged here. Future feature PRs extend the suite and retain
its behavior, rather than skipping failures or rewriting expected raw scientific values.

## INST-01 and INST-02

- **INST01-META:** reference/custom calibration parameters have units, version/hash,
  provenance/status/applicability; unknown/reference-only/user-asserted are distinguishable.
  Reject invalid units, nonfinite parameters, forged reference content and incompatible channels.
- **INST01-VALUES:** identity/default processing is numerically unchanged. Optional supported
  calibration returns a separately traceable derived channel; raw simulator values, satellite
  bands, QA, source dates and native resolution are bit/hash-preserved. No certificate/accuracy,
  fictional drift/failure or newly invented spectral response appears.
- **INST01-HISTORY:** start/configuration-change snapshots reopen/export/replay offline with
  original calibration/reference versions even after user definitions/catalogs change.
- **INST02-RULES:** exercise documented versus conditional/unknown AGL/range, groundspeed,
  pitch/bank/mount, sampling interval/overlap, capability/source and environmental limits,
  including asynchronous/missing temperature. Each outcome names its actual evidence and rule.
- **INST02-HYBRID:** out-of-envelope caution does not suppress valid raw acquisition; invalid
  ground intersection/unsupported derivation is not displayed as valid. Actual source QA stays
  separate. Any unknown/default/payware/freeware/fixed-wing/rotary-wing aircraft remains eligible.

Use UNIT rule/geometry fixtures, INTEGRATION actual archive/configuration changes, GENUINE
numeric-source comparisons, and LIVE below/within/above supported limits with actual aircraft.
Do not induce a fake instrument fault to demonstrate the warnings.

## SCI-03 — Collection lifecycle and triggers

| ID | Required scenario/result |
|---|---|
| SCI03-CONTROL | Depart Armed with no session/acquisition; Start opens session A; Pause/Resume retain A; End closes only A. Start opens B under the same continuous flight ID/telemetry timeline; Resume cannot reopen A and Start cannot split an already open session |
| SCI03-SESSIONS | Each session has a stable distinct ID, sequence, start/end/evidence times, origin/end reason, effective instrument/configuration timeline and provenance. Session-specific events, source/product references and instrument metrics survive close, restart, offline review/export and independent storage moves; no phantom session on rearm or End without an open session |
| SCI03-AUTO-END | Automatic End is optional and requires a configured route point/gate. Last waypoint, route completion and polygon exit alone do not end collection; boundary exit only pauses when enabled. Explicit automatic End A followed by a later configured Start opens B, with later correctly ordered crossings in the same packet also handled |
| SCI03-MANUAL | Manual Pause overrides automatic Start/Resume. Manual End A suspends automatic starts until explicit rearm; intervening automatic Starts are visibly explained/audited as suppressed, never deferred. Manual Start may open B without rearming and does not silently authorize planned automatic actions against B; explicit rearm permits only fresh future occurrences. Boundary/route/safety holds cannot clear each other |
| SCI03-GEO | Ordered route points, directional gates, entry/exit, initially-inside policies, tangent/grazing edges, hysteresis, dateline cases and unsupported geometry produce documented evidence-backed outcomes; two repeated passes at identical coordinates are distinct occurrences |
| SCI03-ORDER | Flight-wide occurrence keys survive session changes. Duplicate/out-of-order/same-time packets and repeated crossings cannot refire or create duplicate sessions; actual ordered crossings differ from ambiguous/coincident End/Start conflicts. A retried End for A cannot close B or reapply a manual hold after rearm; stale session/revision conflicts are explicit. Map polling never advances triggers |
| SCI03-GAPS | Stale/missing positions, paused simulator, slew/jump, aircraft swap and reconnect reset continuity; no skipped-region trigger cascade or fabricated crossing. Geographic hold/rearm is clear and does not silently end flight |
| SCI03-AUDIT | Every actual/suppressed/conflicting transition identifies mission, affected/expected session or explicit no-session state, origin, command/occurrence, previous/new phase, authority, settings/rules and exact stored evidence, including bracketing positions absent from reduced flight samples |
| SCI03-RECOVERY | Kill at session-create/close/event/checkpoint/outbox/product/ack commits: no duplicate open session, unaudited collection or eligible work in paused/armed/between-session windows. Late work from A never becomes B's observation. Restart interrupts the flight/current session and preserves closed sessions; reconnect preserves current session/fired/manual state |
| SCI03-ACTIONS | End Current Science Session, Start New Science Session and End Flight are distinct accessible actions across clients. End Flight closes the open session with FlightEnded reason and ends recording. No Finish Science for This Flight command/latch is introduced by this plan; End Data cannot behave as that optional future action |

UNIT tests use deterministic time/geometry/property sequences. INTEGRATION tests run the
real backend with every browser/toolbar/map closed, vary recording interval versus incoming
position cadence, race manual/automatic commands, and inspect both stores after kill points.
Verify generation cancellation and durable session correlation cannot credit late work to
a newer session; any permitted recovered result retains its originating session and explicit
postflight label. LIVE acceptance flies departure → Start A → pause/resume → automatic End A
→ configured Start B → manual End B → suppressed automatic Start → manual Start C or explicit
rearm and future Start C → End Flight. Include survey exit/re-entry, a last waypoint with no
End action, telemetry interruption and reopened displays. Capture session/event/packet IDs,
continuous flight telemetry and independently reportable metrics for each session.

## SCI-02 — Preflight readiness

- **SCI02-CHECKS:** objective/template/route/area/instrument/calibration/AGL/MSL/speed/cadence/
  overlap/source/storage/trigger/grading inputs each yield a reasoned Ready/Caution/Unavailable/
  Not Yet Assessed. Test unknown/contradictory targets, broken references/order, unrealistic
  cadence, missing Library/provider and insufficient grading obligations. Validate multi-session
  sequences, optional explicit End points/gates, no inferred last-waypoint End, and manual-rearm
  requirements without blocking incomplete drafts.
- **SCI02-DRAFT:** save/reopen incomplete drafts; noncritical advisories do not block recording
  or fabricate Ready. Assessing/selecting/saving never starts science or a download.
- **SCI02-STALE:** edits, catalog/date/settings revisions, changed storage and expired search
  results invalidate the displayed assessment; offline retained sources remain usable with
  truthful coverage/QA limits. Ready never promises future source support or measurement accuracy.

UNIT/integration/browser evidence must include stale asynchronous replies and paired-client
sync. LIVE: an ordinary pilot prepares/saves/flies a valid plan and an incomplete/manual plan.

## SCI-01 — Grade, fairness and scientific yield

- **SCI01-GRADE:** exact requested category weights and versioned A/B/C/D/F boundaries,
  template-specific applicability and boundary/rounding tests. A vertical profile must not
  fail an unrelated polygon overlap criterion. Universal and legacy flights are not forced
  into Realistic grading. Required evidence missing yields explicit insufficiency, not an A.
- **SCI01-DENOM:** verify every displayed numerator/denominator and method: valid acquired
  support, assessable opportunities, expected work, measurement versus acquisition counts,
  operating compliance and native valid-area union. Duplicated/overlapping samples cannot
  inflate area; no survey polygon means no survey percentage. Display-thinned points cannot
  change any final metric. Session metrics retain their own scope; flight coverage unions
  overlapping session support rather than summing areas, and obligation evidence is not counted twice.
- **SCI01-FAIR:** provider outage/cloud/nodata/unsupported evidence are distinguished from
  observed pilot noncompliance. Planned transit and justified pauses are treated fairly.
  Selective collection, disabling instruments, ending/restarting sessions, adding easy sessions
  or deleting difficult planned sessions/segments cannot improve the grade by shrinking or
  diluting frozen obligations. Splitting identical eligible evidence into more sessions leaves
  the overall grade unchanged; missing never-started session obligations remain visible at mission
  level. Test predeclared repeat/retry attribution, not automatic best-session selection.
  Completely paused/empty missions cannot obtain a perfect grade. Unknown weight is not
  silently discarded; test score-range and evidence-sufficiency policies at their thresholds.
- **SCI01-REPRO:** identical archived evidence plus frozen definitions yields identical metric/
  grade results after restart, settings changes, Library move and offline export/reload;
  provisional-to-final differences are explainable from new evidence. Missing sources/old
  unsupported grading versions return limitations, not the current rubric applied retroactively.
  Reproduce one overall mission grade and all session-level performance/configuration/provenance
  breakdowns. Session End finalizes that session's evidence scope, not the overall flight grade;
  aggregation uses frozen criterion obligations, never averages of session letters or best sessions.
- **SCI01-REVIEW:** recommendations cite actual violated/unknown rules and corrective actions.
  Postflight reconstructed products change separately labeled yield revisions, not historical
  live collection credit or original pilot evidence. Reports retain prior grades/input hashes.

Use hand-calculated small UNIT missions, complete-store INTEGRATION replay and GENUINE
native-value/coverage comparisons. LIVE runs include a deliberate high/low compliance pair,
legitimate pauses/provider unavailability and a 30–60 minute representative mission. These
demonstrate pilot grading behavior, never sensor accuracy or certified scientific quality.

## DATA-01 — Geographic Library

- **DATA01-CATALOG:** actual provider coverage versus retained local coverage, paged exact
  scenes/dates/QA/bands/resolution, no-match and not-searched areas; no false valid-pixel
  guarantee, no whole-history selection by default and no silent scene substitution.
- **DATA01-UX:** one small cell, multiple cells, viewport/rectangle, polygon and authoritative
  regional boundary selection; equivalent keyboard/numeric alternative. Review exact bounded
  work/local reuse/unknowns before approval; oversized state selection offers explicit chunks.
- **DATA01-JOBS:** approved durable intent; independent/global pause/resume/retry/cancel,
  app restart, changed ETag/asset, missing drives, disk/permission/network failure, 429/503,
  allowance exhaustion and concurrent in-flight work. Partial staging never appears Ready;
  unsupported range resume restarts safely. Exact duplicate retained sources are reused.
- **DATA01-SAFETY:** caps, free-space reserve, protected originals, separate science/map
  consent, unmetered-only policy, background setting and live-flight priority remain enforced;
  preview changes require new approval. No current mission is required, and no source-only
  download manufactures a mission observation. Interrupted retries cannot evade budgets.
- **DATA01-INTEGRITY:** real discovery → chosen scene/bands → bounded transfer → original
  numeric preparation/manifest → verified source import → offline reuse for each automatic
  workflow: 3DEP, Landsat, Sentinel-2 and Copernicus fallback. Check georeference/CRS/datum,
  dates, scale/offset, QA/nodata, native grids, units, license, checksums and measured bytes
  against an independent reader. Retain provenance and distinguish DEM from DSM/LiDAR.

Mock HTTP tests cover errors/order; they are not GENUINE acceptance. GENUINE tests include
at least one selected cell per workflow, measured overlap/reuse without duplicate transfers
and honest missing coverage. LIVE tests cover Windows job controls/restart/external storage
and concurrent MSFS recording; region-scale work never requires downloading an entire state.

## DATA-02 — NASA stages 1 and 2

- **DATA02-DISCOVERY:** real official AVIRIS-Classic/NG/EMIT collection/granule identities,
  footprints, original times, authoritative known versus unknown metadata, paged links,
  empty area, source-local distinction and supported-action labels. EMIT says discovery/
  official-link only, not directly importable.
- **DATA02-ACCESS:** explicit user consent; official user authorization or functional official
  browser handoff; expire/revoke/cancel/denied-access behavior; validated original links;
  private credentials and provider terms. Demonstrate the actual path and label guided
  handoff separately from automated in-app retrieval. No AeroScience download server.
- **DATA02-CLASSIC / DATA02-NG:** independently demonstrate genuine supported distributions
  from both AVIRIS families through authorized access/download, actual-file verification,
  existing ENVI import, geographic Library display, archived source metadata and offline
  numeric sample/reopen/export. Validate original spectral values/wavelengths/bad bands,
  radiometric units/scaling, grid/georeference, source date or explicit Unknown and file
  companions/checksums independently. A Cuprite fixture alone cannot approve every format.
- **DATA02-LIMITS:** incompatible/changed archives, missing wavelength/radiometry/georeference,
  bad companions, insufficient space and absent auth produce truthful actionable states;
  no inferred scientific metadata, NetCDF-to-RGB substitute or unvalidated EMIT decoding.

If an external access/format blocker prevents a family demonstration, retain its pending
criterion and concrete blocker/usable guided alternative. The original backlog permits
honest partial compliance reporting; it does not turn blocked automation into a full pass.
Record which formats/collection revisions actually work. Physical Windows authorization/
handoff/import flow remains LIVE acceptance separate from scripted metadata calls.

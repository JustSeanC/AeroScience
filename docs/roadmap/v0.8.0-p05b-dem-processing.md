## Architecture and original contracts

`TerrainElevations`, `TerrainElevationSources`, `TerrainNativeGeometry`, the versioned models and additive `ScienceStore` job tables implement a separate derived analysis operation. They reuse:

- P05a `ContinuousTerrainSurveys.RequireCurrent`, its archive fingerprint and streamed regional chunk records; the original artifact is never rewritten.
- The existing `ScientificRaster` numeric decoder, native grid, nodata/finite-value checks and verified retained originals. `ReadNativeCell` returns decoded and scale/offset values directly by original row/column. The legacy point sampler retains its original projection, rounding and numeric calculation; the new value result is a struct to avoid adding per-sample heap allocations.
- `ScientificSourceSelection` policies and the spatially indexed, paged Library catalog.
- The existing four-place bounded `ScientificAnalysisJobs` queue and single worker; no second collection controller or additional source-transfer concurrency.
- `PublishArtifact`, Library reservations/accounting, write-ahead ledgers, atomic publication, registered recovery-copy ownership and the existing permanent-deletion journal.
- The existing Results route, UI helpers/tokens and Library Download & Import component. English catalog version **7** adds the workflow labels; the four non-English locale identities remain preview resources with English fallback, not complete translations.

There are no new observations, `RemoteProduct` acquisitions, intent acknowledgements, yield inputs, grades, card completions or organization submissions. Recording, collection/calibration, original acquisition footprints and archived evidence remain separate. Existing navigation, native CommBus/identity contracts and organization authorization are unchanged.

## Source compatibility and provenance

Processing requires an exact retained source ID, manifest/file fingerprint, verified original-file SHA-256 values, matching ownership metadata and matching inspected grid. Selected originals are checked during review and rechecked before every resumed/retried operation. No substitute source is selected on failure.

| Source | P05b handling |
|---|---|
| USGS 3DEP numeric composite export | Separate `composite-dem` result. Delivered cell values/grid are preserved. Survey date, native per-pixel resolution and vertical reference remain unknown unless actual retained metadata establishes them. The current composite does not. Explicit unverified-reference acknowledgement is required. |
| Copernicus retained DEM product | Recognized provider adapter supplies DSM classification; vegetation/buildings are not relabeled bare-earth terrain. Source vertical declaration and dates are retained. Genuine Copernicus numerical acceptance remains Not Tested here. |
| Other local numeric elevation | Explicit DEM/DSM definition acknowledgement, supported affine GeoTIFF/ENVI band and original unit/reference required. A name resembling “elevation,” provider-name text or a guessed datum is insufficient authorization. Local declarations are labeled as user reviewed, not accuracy certification. |
| Missing/uncertain vertical reference | Blocked unless explicitly acknowledged; output remains isolated and unverified. No vertical or unit transformation, MSL comparison, averaging or common comparable surface is invented. |
| Nodata/nonfinite samples | Explicit missing cells with no exported elevation value. |
| Declared separate QA band | Requires the identical native grid, unscaled unit-1 band and explicit accepted original values. Excluded samples have no exported elevation value. The original terrain importer still permits one elevation band; its contract was not broadened. The QA adapter edge case is tested with a clearly synthetic retained catalog, not claimed as multiband provider/import acceptance. |
| TIFF extra samples, sub-IFDs or additional directories | Refused for P05b pending a mask-aware adapter, including conservative refusal of ambiguous overview layouts. Potential masks are not silently ignored. Originals remain available to their existing readers. |
| Unsupported CRS, swath, definition, grid or policy | Unavailable/requires review; no estimated transformation or automatic replacement. |

Each output retains the complete selected original metadata, IDs/hashes/files, band scale/offset/nodata, native affine grid, CRS, units, vertical declaration, historical date or explicit null, import time, licensing/citation and limitations. A source declaration is not a new scientific certification. Different sources, resolutions, DEM/DSM classes and references are always separate products. Aggregate counts are source-lattice cell counts, not unique geographic coverage across different grids.

## Exact clipping and regional scope

Algorithm: **`terrain-native-cells-1/pixel-clip-1`**; JSON product schema **1**.

The geometry artifact ID, SHA-256 and P05a input fingerprint are frozen. Current archive/session/configuration evidence is required at review, processing/resume and final publication. Downloads of derived outputs also check current geometry and retained source identities. Changed/deleted inputs invalidate the result; rebuilding is explicit.

Source-search rectangles only prefilter the Library index and prepare discovery. Numeric processing transforms the actual corridor MultiPolygons, including holes, turns, antimeridian splits and session/configuration boundaries, into the original pixel coordinate lattice. Geographic grids use the existing canonical affine grid. WGS84 UTM uses GeographicLib, the declared hemisphere and supported latitude/domain bounds; adaptive midpoint/quarter-point chord checks refine to 0.001 native cell with hard recursion/vertex bounds. This numerical tolerance does not certify positional accuracy. Unsupported portions remain unsupported.

A disposable SQLite RTREE indexes projected geometry and distinct `(source, tile row, tile column)` work keys. It contains **no source elevation numbers**. Only integer IDs are sorted before bounded geometry reads. Its rebuildable main file has a page limit and no rollback journal that could duplicate its scratch reservation; durable Library job/checkpoint transactions retain normal journaling.

Each original unit cell is intersected with the true supported geometry. One row/column appears once per source, even across repeated passes or multiple sessions. Per-cell support retains session/configuration/profile/version, geometry chunk references and precise clipped masks. Masks are explicitly **native pixel coordinates, not WGS84 GeoJSON**. The affine grid and CRS supply their geographic interpretation. Original raw decoded and scaled values are retained for valid cells; no interpolation fills holes or missing values.

Jobs freeze an explicit first/last geometry-chunk range. The UI defaults to the currently reviewed chunk; expert bounds can select a range. Other chunks are **not evaluated**, rather than mislabeled missing-source observations. Source-grid/QA gaps within the selected scope remain gaps. `PartiallyComplete` deliberately makes no mission-wide complete-coverage claim. The original geometry plus supported cell masks/quality labels define the evaluated support and its missing portions; there is no new continuous surface reconstruction or 3D viewer.

## Durable job and artifact contracts

| Record | Contents |
|---|---|
| `terrain_elevation_jobs` | Library/mission identity, immutable geometry/source recipe, selected chunk range, resource bounds, state/control revision, progress, result reference and timestamps. Additive tables/index are created with the existing verified metadata backup procedure. |
| `terrain_elevation_receipts` | Identified request, expected revision, input hash and accepted result. Identical retries return the original receipt; stale revisions or reused IDs with changed contents fail. |
| `terrain_elevation_tiles` | Per-source native tile checkpoint and artifact SHA/size/counts. Tile insertion and progress counters commit in one transaction. Progress alone does not invalidate the operator's control revision. |
| `terrain-elevation-tile` | Verified separate JSON artifact with original source/grid/band lineage, native cell values and quality/support masks. Metadata binds source ownership for deletion. No science credit. |
| `terrain-elevation-index` | Geometry SHA/fingerprint, algorithm, recipe, options/chunk scope, separate sources, tile references/checksums, per-source counts and scientific limitations. It embeds metadata, not a second copy of numeric tiles. |

Start, pause, cancel, resume and retry use durable state and receipt/revision checks through the original analysis queue. Startup converts queued/running/pausing work to `Interrupted`; nothing automatically downloads or restarts. Resume validates the frozen recipe, current archived geometry, original source bytes, checkpoint identities/counts and tile hashes. A verified visible tile published before a checkpoint commit can be reused. Existing source transfer approvals are neither created nor resumed by a terrain job.

Completed tiles remain explicitly visible after pause/cancel/failure. Disposable geometry scratch and `.partial` output are cleaned on ordinary cancellation/failure. Process-killed work remains visible/accounted by its ledger, never accepted as a completed tile. Library loss or deliberate queued-job deletion cannot recreate deleted work or stop independent recording through a terrain error handler.

Default bounds: 16×16 native-cell tiles; 2,000,000 candidate cells; 8,192 tiles; 128 MiB total output; 256 MiB scratch; 4 GiB original verification. Hard limits: tile edge 32; 20,000,000 candidates; 20,000 tiles; 1 GiB output/scratch each; 20 GiB original verification; 16 selected sources; bounded source metadata/files and geometry overlaps/vertices; 16 MiB per numeric tile. Review reports candidate-tile/cell upper bounds and reservations, not a fabricated transfer ETA or universal performance guarantee. Smaller regional jobs are the escape for large flights or tight budgets.

## Review, source preparation and permissions

The existing `#workspace/results?missions=<id>` route adds a small terrain section:

1. Choose/build a verified modeled corridor; review one regional page and indexed retained sources.
2. Inspect potential native grid masks, metadata/limitations and unavailable/policy-excluded sources. Pixel QA and hash verification are still required; candidate outlines are not valid-data coverage.
3. Optionally open **Prepare Missing Sources** for one explicitly selected bounded search rectangle. It reuses the existing Library discovery, source reuse, consent, preview, transfer allowance, metered-network, storage and Download & Import approval controllers. No search/download is triggered merely by opening this component. Unsupported geographic preparation bounds fail before any catalog call; no unrelated default area is substituted.
4. Select exact retained originals/definition/QA acknowledgements and **Verify sources and review processing**. Review the frozen sources, chunk range and processing bounds; **Process retained terrain** is separate and explicit.
5. Pause/cancel or explicitly resume/retry. Open the derived index or first 100 completed tiles; paged API access exposes remaining tiles. A terrain-store failure does not remove the original Results/export controls.

The existing pairing, same-origin/CSRF and no-store protections apply to all APIs. Creating or controlling persistent terrain work additionally requires trusted loopback access; paired read access does not grant new filesystem/download authority. No new source upload, sharing, telemetry transfer or organization evidence delivery is introduced.

Endpoints: artifact `elevation-review`; mission `terrain-elevation/jobs`; `/api/terrain-elevation/jobs/{id}`, `/tiles` and `/control`. Original artifact download verifies geometry/source dependencies. Original science, preparation, recording and native toolbar command APIs are reused without semantic changes. Browser polling preserves job disclosure state and keyboard focus and prevents concurrent repeated control requests.

## Deletion and storage safeguards

The existing Library reservation/accounting and atomic writer manage numeric artifacts. An explicit source-owner write-ahead ledger also binds unindexed/partial numeric tiles if a process stops between file movement and database commit. Permanent source deletion now includes the new tile kind in current storage, metadata backups and registered recovery products, and includes those owned interrupted writes. A partial cleanup/permission failure remains pending rather than claiming deletion success.

Deleting one source removes its managed P05b values and invalidates dependent job/index reads; other source tiles and original airborne science remain protected. The index cannot become a hidden self-contained numeric copy. Permanent collected-science deletion also purges the new jobs, checkpoints and receipts through existing journal/backup handling. Existing analysis/source-maintenance exclusion remains mandatory.

Independently saved original science products and user originals/explicit exports outside managed storage retain their existing protection/ownership contract. This checkpoint does not silently erase those unrelated originals or user-managed copies.

The initial P05b Full run [43168225022](https://github.com/JustSeanC/AeroScience/actions/runs/43168225022), source `2b830dafe9bc58f2827c21f181222168bfe72669`, passed every new P05b .NET case, Windows (1,559 passed / 10 existing skips) and organization deployment. Browser checks were consequently skipped. The original diagnostic ZIP/TRX/decoded log hashes are retained in [the failure receipt](receipts/v0.8.0-p05b-ci-failures.json).

A real pinned SQLite WAL reader reproduced this path locally: the single checkpoint attempt returned pending even when the reader released shortly afterward. Mission cleanup now retries only that physical checkpoint for up to one second; it still requires successful truncation, `VACUUM` and integrity verification. A persistently held reader still leaves deletion pending, and releasing it permits the same authorized journal to complete. The selected data, authorization, raw-recording preservation and original API assertion are unchanged. Two real-reader regressions cover both outcomes. This is a confirmed local contention/recovery fix, not an environmental assumption or a relaxed deletion gate.

## Profile and API contract

- `AppPreferences.Presentation` is optional. Older settings resolve to **auto / en-US / guided / balanced**, revision zero, without rewriting the file on read. Four non-English identities remain explicitly **English previews**.
- `PreferenceStore.SetPresentation` validates the three themes and five exact locale IDs, compares the expected revision and patches only the presentation section through the existing atomic writer. It preserves unrelated settings, unknown JSON fields, configured archive paths and profile confinement. Store instances for the same normalized path share a lock. Invalid/corrupt/future settings are preserved; future versions cannot be overwritten by this adapter.
- Authenticated `GET /api/settings/presentation` returns version, instance identity, revisioned preferences, effective English locale, catalog version, preview metadata and `canWrite`. It exposes no storage paths or credentials. A paired device can inspect this view.
- `POST /api/settings/presentation` accepts only `expectedRevision`, `theme` and `locale`. Existing Host, same-origin JSON, session and CSRF middleware applies, followed by the physical loopback/local-PC gate. Unknown fields/unsupported values are rejected; stale writes return conflict. No scientific units, recording/science state, access policy, storage/deletion or organization permission setting is accepted.
- Existing browser Theme/Language controls remain explicit local overrides. The separate **Companion defaults** controls save the host/profile choices; browser preferences are never uploaded automatically. **Use companion defaults in this browser** removes only the owned override key. Other browser keys remain intact. Host reads are bounded to one visible-page poll every ten seconds plus focus/reconnect; instance/generation/revision guards reject late reads after a confirmed save.

## Windows and native MSFS

`PresentationText` embeds the canonical English JSON/manifest/schema in Shared. The Windows Settings and Setup pickers use this adapter and the same profile store. Settings saves without restarting recording; Setup retains its existing storage confirmation flow and saves appearance on the UI thread after verified storage setup. Reload handles revision conflicts; a toolbar-install retry does not replay an older appearance revision. Cancel does not save a presentation draft.

Main, Settings and Setup apply Auto/Light/Dark through a small Windows adapter, honor Windows High Contrast and react to system preference changes. Other existing Windows dialogs remain outside this bounded migration. Existing dialog prose is English; the four preview selections do not imply translated Windows dialogs. No cloud login is required.

The MSFS toolbar retains its existing readable dark palette, four tabs, SDK header/bootstrap/drag/resize/scroll ownership and command channels. New classic-script `AeroScience.I18n.js` consumes canonical generated `AeroScience.LocaleData.js` and `AeroScience.LocaleFormat.js`. These two generated files are created **inside the copied SDK stage**, including renamed validation panel directories; source catalogs are not duplicated or rewritten. All scripts pass the existing TypeScript-to-ES2017 compiler and independent Acorn parse.

The adapter initially covers marked navigation labels and language/fallback diagnostics; other existing dynamic native text remains English for later feature migration. Scientific values, units, proper names, UTC, IDs, source and QA text are not traversed as translatable prose. No Intl or modern DOM convenience method is required.

The expanded canonical catalog is **version 2** (contract/schema remain version 1), so a cached P02a catalog is detected as old. State replies may add the optional `presentation-1` capability and a small `presentation` object containing contract/catalog version, locale and preference revision. Protocol 1, all existing operations, 1,024-byte commands and 8,000-byte replies remain unchanged. No locale-setting CommBus command was added. Optional presentation bytes are omitted **before** existing scientific detail reduction when the packet budget is tight. Missing/corrupt profile metadata cannot interrupt telemetry.

Native metadata is used only after existing correlation, source, protocol, engine, serial and mission-intelligence revision checks. Older preference revisions cannot replace a newer accepted language view for the same engine. Older companions, missing assets and unsupported contract/catalog/locale metadata retain deterministic English fallback. A mismatched validation source still disables controls through the original identity checks; localization never authorizes an action.

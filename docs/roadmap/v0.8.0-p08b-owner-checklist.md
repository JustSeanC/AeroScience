Use your Windows gaming PC, PowerShell 7 and the **Visual Studio x64 Native Tools** environment. Keep stable/070/071 Beta 2 applications, validators and original data untouched. The recorded reference paths are defaults to verify, not evidence that Codex inspected them. The scripts below pin packaging-repair source `876ecf594956b7a40c7df0d4968dac1ce69ac971`; see the [handoff](v0.8.0-p08b-handoff.md) for its exact CI and remaining acceptance gates.

## Prepare one new attempt

1. Finish any active flight and close MSFS before SDK packaging. Close a previous `fspackagetool` yourself if it is still waiting. Do not kill an active recording or let a script clean Community.
2. Preserve the existing checkout. Fetch the development branch and create a **new detached worktree at the reported SHA**; do not switch/reset an existing dirty checkout. Keep the worktree available for verification and acceptance recording.
3. Choose a new `C:\AeroScience-Builds\Validation080-<timestamp>` output. Use your actual installed SDK and the existing hash-bound public runtime-approval record. If the SDK/record lives elsewhere, pass those actual paths. Never paste or copy private correspondence into the attempt.
4. Run preflight, then the private builder. Missing tools require your own installation; the scripts do not install tools/licenses. Keep every failed attempt and its logs; use a fresh timestamp for another build.

```powershell
$ErrorActionPreference = 'Stop'
$PSNativeCommandUseErrorActionPreference = $true
$sourceCommit = '876ecf594956b7a40c7df0d4968dac1ce69ac971'
$existingRepo = 'C:\Dev\AeroScience-release'
git -C $existingRepo rev-parse --show-toplevel
if ((git -C $existingRepo rev-parse --is-shallow-repository).Trim() -eq 'true') { git -C $existingRepo fetch --unshallow origin }
git -C $existingRepo fetch origin develop/v0.8.0
$nativeWorktree = Join-Path 'C:\Dev' ('AeroScience-080-Native-' + $sourceCommit.Substring(0,7) + '-' + (Get-Date -Format 'yyyyMMdd-HHmmss'))
if (Test-Path -LiteralPath $nativeWorktree) { throw 'Preserve the existing worktree; choose a fresh worktree path.' }
git -C $existingRepo worktree add --detach $nativeWorktree $sourceCommit
Set-Location -LiteralPath $nativeWorktree
if (-not (Test-Path -LiteralPath 'C:\AeroScience-Builds')) { New-Item 'C:\AeroScience-Builds' -ItemType Directory | Out-Null }
$attempt = Join-Path 'C:\AeroScience-Builds' ('Validation080-' + (Get-Date -Format 'yyyyMMdd-HHmmss'))
pwsh -NoProfile -File .\scripts\build\Test-080NativeEnvironment.ps1 -ExpectedSourceCommit $sourceCommit `
  -OutputDirectory $attempt -SdkRoot 'C:\MSFS 2024 SDK' `
  -RuntimeApprovalRecord 'C:\AeroScience-Release-Records\runtime-approval.json' -RuntimeRedistributionConfirmed
pwsh -NoProfile -File .\scripts\release\Build-080PrivateValidation.ps1 -ExpectedSourceCommit $sourceCommit `
  -OutputDirectory $attempt -SdkRoot 'C:\MSFS 2024 SDK' `
  -RuntimeApprovalRecord 'C:\AeroScience-Release-Records\runtime-approval.json' -RuntimeRedistributionConfirmed
```

If the old checkout/path does not exist, stop and locate the real clone. Do not run Git from the Visual Studio installation directory. If the existing runtime attestation is missing/mismatched, follow `docs/runtime-distribution.md` and retain the old record; no correspondence upload is needed. Preflight success is not simulator acceptance.

## Verify, then explicitly launch

Read `BUILD-COMPLETE.json`, retain its source, attempt, receipt hash and archive checksum separately, and compare after copying the archive. Do not approve an unexplained checksum difference. Do not edit the sealed application files or acceptance template.

```powershell
$app = Join-Path $attempt 'AeroScience-0.8.0-Validation'
$receiptHash = ((Get-Content -LiteralPath (Join-Path $attempt 'receipt.sha256') -Raw).Trim() -split '\s+')[0]
pwsh -NoProfile -File .\scripts\release\Verify-080PrivateValidation.ps1 -ValidationFolder $app `
  -ExpectedSourceCommit $sourceCommit -ExpectedReceiptSha256 $receiptHash
# Explicit owner launch: close the existing AeroScience companion yourself first.
pwsh -NoProfile -File .\scripts\release\Start-080Validation.ps1 -ValidationFolder $app `
  -ExpectedSourceCommit $sourceCommit -ExpectedReceiptSha256 $receiptHash
```

This launches only the private companion. The first launch creates a separate attempt profile on port **5088**. Check its validation title/attempt. In **its Settings**, inspect the actual Community path and matching **AeroScience 0.8.0 Validation** package/source/attempt, then explicitly choose installation while MSFS is closed. Do not remove production/070/071 packages. No successful SDK build proves real native panel behavior; record the following observations.

## Record results, including failures and blocked tests

The recommended option is the [guided checklist window](v0.8.0-p08b-checklist-window.md), available in tools source `aead10258e0a757b563b4d4dc9dfd17b7e61d72b`. It works with your existing verified build; no companion/toolbar rebuild, reinstall or restart is needed. Open it from that separate tools checkout, passing the source/hash of the package being tested:

```powershell
pwsh -NoProfile -File .\scripts\release\Open-080Checklist.ps1 -ValidationFolder $app `
  -ExpectedSourceCommit $sourceCommit -ExpectedReceiptSha256 $receiptHash
```

Go down the list, choose each result, write what happened, tick the personal-testing box for Passed changes and click **Save my results**. No test IDs or capitalization need typing. Leave everything not tried as Not Tested. Close/reopen to resume. Keep the tools checkout/PowerShell window available; MSFS and the test companion may keep running. The full one-time setup command is in the linked guide. The existing command-line option remains available:

```powershell
pwsh -NoProfile -File .\scripts\release\Record-080Acceptance.ps1 -ValidationFolder $app `
  -ExpectedSourceCommit $sourceCommit -ExpectedReceiptSha256 $receiptHash -Interactive
```

Record only what you actually observed on this exact source/attempt. A generated form starts **Not Tested**, never Passed. Missing hardware/source/assistive technology is Blocked or Not Tested, not a pass. Record screenshots or reviewed logs by copying non-secret files under `$attempt\Results`; the noninteractive `-EvidencePath` option binds their hashes. Avoid credentials, tokens, exact private telemetry and correspondence in feedback.

Each result event retains source, build/profile, native runtime/helper and SDK receipt identities, catalog, outcome, UTC, observation and evidence references. Later notes append rather than overwrite previous failures.

## P05d.1: Results and native-cell map

Results adds **Overview / Explore / Evidence** using `view=overview|explore|evidence` on the original `#workspace/results` route. Other query parameters, mission and instrument scope remain intact. The unqualified legacy URL keeps source-preparation panels open. Canonical views put these same controllers in a named disclosure. Original maps, original comparisons, research charts, all instrument analysis, source QA, research-card evidence, downlink and original exports remain reachable through their original routes and controls.

Overview separates original in-flight measurement values / geographic acquisitions, modeled scanner geometry, historical DEM/DSM native cells and historical LiDAR returns. Counts refer to the latest verified product of each kind, rather than summing revisions. Post-flight products never create observations, measured yield, grades or card completion.

The read-only `SurveyResults` adapter reuses `ContinuousTerrainSurveys.RequireCurrent`, `TerrainElevations.RequireCurrent`, `TerrainElevationSources.Bind`, `LidarProcessing.RequireCurrent`, existing verified artifacts, original source hashes/policy and analysis leases. It does not publish products, import sources, queue processing, start downloads or create a database/cache. Numerical responses remain paired-session/CSRF protected. Original mutation and organization authorization are unchanged.

Explore draws exact retained cell support (including holes) transformed from the authoritative native pixel mask for geographic display. Native row/column, decoded/scaled values, source units, grid and original artifact remain available in Evidence. DEM/DSM and separate vertical references require explicit source selection. Valid neighboring cells meet without invented interpolation; nodata remains transparent with optional missing-cell edge annotations. A hollow location overview keeps actual cell locations visible at wide zoom; these symbols do not depict measured area. Modeled corridors and original acquisition footprints are outlines. Archived flight track preserves telemetry barriers and collection-session transitions and is explicitly independent of acquired science.

Display elevation conversions reuse saved science units; stored values remain unchanged. Source datum is never equated with aircraft MSL. Original metadata and unknown source dates/references remain visible.

## Bounds and lifecycle

Each numerical page has at most 1,024 original records, 32 scanned tiles, 64 MiB tile reads, 65,536 geometry vertices and a 4 MiB encoded response ceiling. Products above the bounded index size are refused. Terrain original verification is limited to 2 GiB per request. Geometry and track are separately paged; bounded display scopes are disclosed. A 2D canvas is capped at 2,097,152 pixels and device scale 2. Source/session/view changes abort obsolete reads; generation checks discard late replies. Numerical data lives only in memory and is cleared on disposal or failed revalidation. Only validated presentation flags/opacity are saved as viewer preferences.

The current source-change event and periodic visible-view verification clear stale numerical displays after original-source/dependent-product invalidation. Existing active analysis/storage maintenance leases cover numerical response serialization. Opening Results cannot substitute a missing source or change consent.

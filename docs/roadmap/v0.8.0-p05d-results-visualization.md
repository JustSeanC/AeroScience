## P05d.1: Results and native-cell map

Results adds **Overview / Explore / Evidence** using `view=overview|explore|evidence` on the original `#workspace/results` route. Other query parameters, mission and instrument scope remain intact. The unqualified legacy URL keeps source-preparation panels open. Canonical views put these same controllers in a named disclosure. Original maps, original comparisons, research charts, all instrument analysis, source QA, research-card evidence, downlink and original exports remain reachable through their original routes and controls.

Overview separates original in-flight measurement values / geographic acquisitions, modeled scanner geometry, historical DEM/DSM native cells and historical LiDAR returns. Counts refer to the latest verified product of each kind, rather than summing revisions. Post-flight products never create observations, measured yield, grades or card completion.

The read-only `SurveyResults` adapter reuses `ContinuousTerrainSurveys.RequireCurrent`, `TerrainElevations.RequireCurrent`, `TerrainElevationSources.Bind`, `LidarProcessing.RequireCurrent`, existing verified artifacts, original source hashes/policy and analysis leases. It does not publish products, import sources, queue processing, start downloads or create a database/cache. Numerical responses remain paired-session/CSRF protected. Original mutation and organization authorization are unchanged.

Explore draws exact retained cell support (including holes) transformed from the authoritative native pixel mask for geographic display. Native row/column, decoded/scaled values, source units, grid and original artifact remain available in Evidence. DEM/DSM and separate vertical references require explicit source selection. Valid neighboring cells meet without invented interpolation; nodata remains transparent with optional missing-cell edge annotations. A hollow location overview keeps actual cell locations visible at wide zoom; these symbols do not depict measured area. Modeled corridors and original acquisition footprints are outlines. Archived flight track preserves telemetry barriers and collection-session transitions and is explicitly independent of acquired science.

Display elevation conversions reuse saved science units; stored values remain unchanged. Source datum is never equated with aircraft MSL. Original metadata and unknown source dates/references remain visible.

## Bounds and lifecycle

Each numerical page has at most 1,024 original records, 32 scanned tiles, 64 MiB tile reads, 65,536 geometry vertices and a 4 MiB encoded response ceiling. Products above the bounded index size are refused. Terrain original verification is limited to 2 GiB per request. Geometry and track are separately paged; bounded display scopes are disclosed. A 2D canvas is capped at 2,097,152 pixels and device scale 2. Source/session/view changes abort obsolete reads; generation checks discard late replies. Numerical data lives only in memory and is cleared on disposal or failed revalidation. Only validated presentation flags/opacity are saved as viewer preferences.

The current source-change event and periodic visible-view verification clear stale numerical displays after original-source/dependent-product invalidation. Existing active analysis/storage maintenance leases cover numerical response serialization. Opening Results cannot substitute a missing source or change consent.

## P05d.2: Real historical point views

`survey-points.js` selects actual retained records for 2D/3D view-dependent screen/depth bins. It never averages positions, densifies sparse sources, generates DEM points or claims selected point locations establish complete coverage. Coloring reads original Z, classification, intensity, return number or RGB; missing dimensions are disabled and a programmatic invalid selection returns to original Z. RGB uses an explicitly labeled 16-bit display scale. Original class 2 is the ground filter; it does not synthesize a ground model. Height above ground is disabled because no joint vertical-reference compatibility proof exists.

`survey-cloud.js` uses WebGL 1 point primitives with local double-precision origin subtraction before bounded float buffers. Source XYZ/raw integer XYZ, raw GPS hexadecimal bits, attributes, original SHA/record index, tile and original session/configuration/profile bindings remain available through Evidence and the exact artifact. Geographic XY is explicitly a local tangent display approximation; projected XY retains original projection distortion. Known Z units get a display conversion only. Unknown Z units use a clearly disclosed illustrative vertical aspect, never an implied metric height, MSL comparison or datum conversion. Vertical exaggeration is labeled as display only.

Orbit, Shift-drag pan, zoom, reset, pointer picking, keyboard operation and the paginated evidence table share actual record identity. GPU refusal/context loss leaves 2D and table controls usable. Resize is bounded to 2,097,152 pixels; point buffers are at most 65,536 × 24 bytes (1.5 MiB, with the smaller loaded-record limit applying first). Disposal deletes buffers/programs, releases the context, cancels rendering and clears numerical arrays. No point data is persisted in localStorage, IndexedDB or a new file cache.

The client retains at most 32,768 values and 16 MiB of encoded numerical records, plus separately bounded geometry (8 MiB / 262,144 vertices / 256 records) and four 2,048-pose track pages. These are data/allocation bounds, not a claim that browser heap equals encoded size. A cap is visibly disclosed and users can request a smaller geographic window; omitted display detail never becomes a missing-source count. Source and session changes cancel old pages and prevent late results from replacing current evidence.

The explicit **Load bounded local overview** action reads up to 16 pages progressively, within those same limits. Page/window controls share an in-flight guard, and failed verification clears the numerical view immediately. Disposal removes Results markup as well as arrays/GPU resources. The 3D camera fits a local centered bounding sphere to portrait/landscape viewports without changing the original origin or point coordinates. Classification legends show actual loaded codes with their exact swatches; RGB keeps its original-channel display explanation. Optional terrain relief shades only cells with actual valid loaded native neighbors, using approximate display illumination; it neither fills nodata nor publishes a scientific slope/terrain product.

Targeted receipts: [P05d.1](receipts/v0.8.0-p05d1-targeted.json), [P05d.2](receipts/v0.8.0-p05d2-targeted.json). Genuine large-source measurements and labeled captures are reserved for the integration receipt; small synthetic browser fixtures are not performance acceptance.

## P05d.3: Profiles, exports and Library

`SurveyProfiles` is a read-only adapter over the selected P05b index, original `TerrainNativeGeometry.Project`/native support masks, original session/chunk intervals, archived telemetry and WGS84 `Geodesy`. It does not change legacy `TerrainProfiles` or scientific sampling. A profile chooses one explicit DEM/DSM source and native reference. It returns exact retained row/column, decoded/scaled value, original unit, QA, source manifest SHA, tile ID/SHA and session bindings. Analysis path positions are derived WGS84 positions, not newly recorded flight observations.

The horizontal axis sums geodesic lengths of known contiguous archived legs. Unknown displacement across telemetry/pause gaps is excluded; segment and session boundaries stay disconnected. An explicit two-point analysis transect is labeled as unflown geometry and creates no aircraft altitude series. Profiles refuse more than 1,025 sample points, 4,096 original poses, 128 needed native tiles, 64 MiB tile reads, 65,536 candidate cells or 20,000 interval metadata records. The selected native mask must cover a value; nodata, missing support and excluded sessions remain missing. Connections require the same archived leg/session and native support proving the intervening line is covered. Coarse samples cannot bridge unseen holes. Original stored values/units remain separate from preferred presentation units.

The source profile, map cursor, original cell inspector and evidence table share native cell identity. A separate, collapsed chart retains original aircraft MSL pose ordinals/times/source; no mixed-datum plot or HAG comparison is offered. The original advanced track/plan/transect profiler and all instrument-specific analysis remain reachable. New chart labels use theme tokens; profile charts respond to unit/theme changes and dispose their resources.

Explicit downloads add a bounded loaded-record analysis CSV, exact loaded geometry/point-location GeoJSON, provenance report and source-backed profile CSV. These are **derived viewer subsets**, not complete coverage, exact LAS/LAZ subset files or new original evidence. Raw GPS hexadecimal bits preserve the original 64-bit identity; the unsafe JavaScript integer display is omitted. CSV text is protected against formula prefixes. Original acquisition exports and the original Research Package are preserved. The package already includes exact P05a/P05b/P05c artifacts in `analysis/`, metadata, source manifest/hash references and original/derived limitations; **original source files are referenced, not duplicated**. A transient profile remains an explicit CSV sidecar rather than a hidden saved product/cache.

The shared Library navigation now reads **Sources / Downloads / Storage** on the same original routes/controllers. LiDAR source regions explicitly describe delivered LAS/LAZ/EPT identities, original attributes, historical dates/reference unknowns and post-flight-only eligibility. Point originals are not offered through a raster inspector. Source bounds are explicitly search bounds, not valid pixels/point density. Downloads retain the original queue/consent/bytes/speed/unknown-size/pause/retry/cancel controllers. Storage reuses the existing verified local folder opener/accounting and permanent-deletion previews/dependencies. No second downloader, point-data cache, backup or ownership rule is introduced.

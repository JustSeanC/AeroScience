# v0.6.0 implementation sequence

Every phase uses `develop/v0.6.0`, small tested commits and normal pushes. No per-feature branches,
PRs, main/develop-v0.5 changes, history rewrite or public publication. The tracker is the resume point.

| Phase | Deliverable / exit gate | Depends on |
|---|---|---|
| P00 | Current-source audit, contracts, genuine FAA samples/CMR evidence, codec/license decision and explicit gaps | Verified baseline |
| P01 | Separate versioned aviation metadata/store/jobs; explicit consent and approvals; bounded trusted transfers, ZIP validation, real accounting/recovery | P00 contracts; no scientific-store migrations |
| P02 | Compatible authorized raster styles; unified one-basemap/independent-overlay chooser, legend/accessibility/offline behavior | P01 read contracts; Esri authorization/style feasibility |
| P03 | Official NASR airports/runways/NAVAIDs/fixes and airspace normalization/indexed bounded reads; two genuine regions/altitude edge cases | P01; accessible versioned official originals |
| P04 | Approved FAA originals download, bounded windowed reprojection/tiles, verified neatlines/control points and chart lifecycle | P01–03; distributable Windows GIS prototype |
| P05 | Host-owned TFR refresh/list/detail; verified polygons/time/altitude screening only when authoritative data exists | P01–03; independently verified geometry if claiming polygon completion |
| P06 | Existing NASA-job extension, EMIT native reader/companion pairing, QA/uncertainty/GLT/spectra/offline originals | P00 decoder gate; existing Earthdata authorization; genuine original access |
| P07 | Full Linux/Windows/browser/recovery/science/native integration and measured performance, tester workbook/readiness | Implemented preceding features; owner hardware acceptance separately |

P01 may be split into contracts/store and durable-transfer integration commits. Do not label the phase
complete while approvals, actual worker integration or recovery remain absent. P02's supported chooser
can progress independently of a blocked chart renderer; unsupported aviation layers must be explicitly
unavailable. P03 metadata research and P06 codec prototypes can progress without protected downloads,
but synthetic fixtures do not satisfy genuine-source gates. Never invent a fallback renderer or source.

Routine validation follows the existing conservative fast selector on the explicit development branch;
unknown/shared dependencies expand tests. Completed milestones request `[full-validation]` or manual
full CI. Full main/release gates are unchanged. Inspect hosted results once; diagnose repeated failures.
Do not rebuild Windows installer infrastructure after every small change. SDK/MSFS/iPad/Quest acceptance
requires actual devices and cannot be inferred from a Windows CI publish.

Next bounded work after the initial source audit: implement and test aviation record validation and
separate persistent metadata snapshots; then wire consent-gated official catalog discovery. Preserve
unimplemented job controls as planned work, not buttons suggesting nonexistent downloads.

# v0.4.2 performance and reliability evidence

## Defined browser load

The [machine-readable Chromium measurement](research/v0.4.2-browser-performance.json)
uses **2,100 synthetic geographic acquisition records and 12,000 environmental values
across three missions**. It deliberately repeats small saved native support to test
archive traversal/representation. It is not a simulation of thousands of distinct,
large satellite scenes and is not real-flight recording or provider acceptance.

The recorded run loaded the complete-scope overview in about **1.4 seconds** and
returned layer-checkbox feedback in **54 ms**. It represented the scope with **39
Leaflet features** and **42 rendered table rows**, rather than drawing all records.
The measured V8 used heap was about **40 MB** at the captured point. This is a point
measurement, not a proof of a leak-free 60-minute session or total browser memory.
Consult the JSON for exact measurements from the final recorded run and environment.

The test checks deep archive page access, stale-request cancellation, unchanged product
metadata, bounded rendered features/rows, seven viewport widths and zoom emulation.
Local timings depend on machine load and cache. The practical 200ms ordinary-interaction
target is an aim; it is not a production latency guarantee for every query.

## Bounds and architecture

- Overview traverses the full selected indexed scope in keyset pages of at most 100
  acquisitions / 500 simulator values. Each instrument/quantity/unit category has at
  most 12×8 location bins; an overview location is not a scientifically measured value.
- Browser caches at most 16 immutable product/measurement responses and eight recent
  viewport overviews. Route disposal cancels requests/timers and destroys map instances.
  Explicit refresh clears scientific view caches and revalidates saved files.
- Native detail loads all small visible selections within a 6,000 estimated-position
  budget, otherwise one saved acquisition per instrument plus complete location
  aggregation. The archive browser can inspect every record. Atmospheric views above
  1,000 values use aggregation; zoom/detail preserves actual values without filling gaps.
- Metadata/value tables page the DOM. Download activity keeps stable keyed rows/controls
  while polling and bounds its diagnostic row window. Scientific jobs continue outside
  display views. No navigation silently starts provider retrieval.
- The server overview scans matching metadata; work is linear in selected record count.
  Cancellation is checked per page/record, with bounded accumulator memory. A much larger
  real archive may need narrower filters; no million-record timing is claimed.

## Genuine scientific workload

Fresh production-harness runs cover four real public-data workflows, genuine guided
224-band ENVI, retained review, regional combination, native-grid composites, previews
and exports. Independent GDAL checks compare 14 rasters, 170 good spectral bands and
quality/nodata/grid support; six research ZIPs have member hashes verified. See the
source-bound reports and completion report. These establish different facts from the
synthetic archive scaling test and must not be described as real MSFS recording.

Actual-process recovery retains saved samples/mode after forced termination and refuses
a duplicate engine. A long real Windows/MSFS flight, OS resource profiling, physical
Safari/Quest 3 and representative-user latency/satisfaction remain pending.

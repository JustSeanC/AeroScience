# Try the simpler research flight

Use a newly supplied **AeroScience 0.7.0 Validation** copy and MSFS 2024 with an aircraft loaded. Keep your existing application and science files. No NASA download or organization account is needed for this check.

## Collect and review science

| Do this | You should see | Result |
|---|---|---|
| 1. Open **My Research**. Under **Vertical Atmospheric Profile**, click **Fly Now**. | The card shows a short question and source label. Flight Operations says the mission is prepared; it is not recording yet. | ☐ Pass ☐ Problem |
| 2. Click **Start Recording**. If a start check appears, read it and continue when ready. | Recording starts. Science shows its own state and the next useful controls. | ☐ Pass ☐ Problem |
| 3. If science is Armed, click **Show Science Controls** → **Start new science session**. If Paused, choose **Resume science collection**. | Science says Collecting. **Retained original scientific observations** increases. | ☐ Pass ☐ Problem |
| 4. Fly a short climb or descent, then click **End mission**. | The flight is saved and **Review Results** appears. | ☐ Pass ☐ Problem |
| 5. Click **Review Results**. Open **Analysis** if you want to inspect the readings. | Your saved flight is selected, with original readings and units. Incomplete research is identified. Open a details arrow for more explanation. | ☐ Pass ☐ Problem |

## Toolbar retest — separate installed-MSFS check

1. Open **AeroScience 0.7.0 Validation** in the MSFS toolbar. There should be no **Compact VR** button. Open **Connection & Build Details**: it should show the new Validation source, not your older copy.
2. Choose a mission with **Fly Now** on the dashboard. The toolbar's mission selection should match. Open **Payload**, then **Mission**: both should respond.
3. Start recording and science on the dashboard. Check that the toolbar shows the same flight/session. If it stays frozen or reports a mismatch, stop and send a screenshot of its title and **Connection & Build Details**. Do not swap files or troubleshoot channels.

## Prepare the new isolated validator — builder prerequisite

This is packaging work for the builder, not another pilot QA task. This pass does **not** replace an installed copy, compile a genuine SDK toolbar on Linux or supply a new Windows package.

1. Use the accepted UX source on Windows x64 with the genuine MSFS 2024 SDK and the existing private runtime authorization. Keep earlier candidates intact.
2. Use the maintained [private builder](../scripts/release/Build-PrivateValidation.ps1), choosing a **new output folder name that does not exist** outside installation and data folders. It generates the matching source-bound Validation application, toolbar, private ZIP and receipt; it never installs or publishes them. The builder refuses an existing output path.
3. Supply that new private ZIP and its checksum as a distinct candidate. Check its source receipt before launch. Keep production/earlier validation data and Community copies untouched. If a toolbar installation is later authorized, use the companion's normal installer with the matching bundled Validation package; do not replace files by hand.

The existing v0.7.0 Validation profile uses port 5086 and a fixed isolated validation data root. A new output directory alone is **not** a second data profile. A strictly side-by-side run must use a separate Windows test account/profile; close the earlier companion first. Do not select production or older validation science as the new build's data location.

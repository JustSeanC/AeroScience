# AeroScience toolbar source — not an installation-ready Community package

This is an SDK project, not a prebuilt add-on. `manifest.json`, `layout.json`, and the compiled panel `.spb` must be generated by the official Windows MSFS 2024 package builder. No placeholder binary or manifest is supplied.

The previous full panel loaded with simulated telemetry, but moving/resizing/scrolling failed on the gaming PC. The latest interaction source and Compact VR header checkbox need a new SDK build and native retest. See the [focused Windows procedure and desktop/VR results](../docs/toolbar-interactions.md). The existing companion engine is reused.

The first gaming-PC proof-of-concept build is user-reported passed, including SDK contract compilation, Microsoft's package validation and the complete script's nine-file structural validation. Its output is on that PC, and subsequent screenshots confirm the diagnostic panel opens in MSFS and receives companion CommBus replies. The user confirms recurring request-ID updates about once per second. Installed-folder confirmation, long-duration/lifecycle transport, mission controls, the full build and device testing remain pending; see the [evidence record](../docs/validation-results.md#first-visible-commbus-reply).

Open `AeroScience.xml` in the SDK Project Editor, or run `scripts/build/Build-Toolbar.ps1` from PowerShell 7 on a configured Windows PC. Start with `-ProofOfConcept`; this builds the same registration and transport with a minimal diagnostic page before the full interface. See [toolbar integration and pending validation](../docs/toolbar.md).

The original project uses SDK SPB and Copy asset groups and the `ingame-ui` panel system. The transport uses named CommBus messages through the MSFS 2024 SU5+ runtime. It does not embed the companion website or connect to localhost sockets. All recording and operating-mode decisions belong to the central Windows engine.
